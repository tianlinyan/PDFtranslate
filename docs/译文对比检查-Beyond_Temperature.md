- 原文：`Beyond_Temperature_Hyper.pdf`（25 页，ICML 2026 双栏论文，612×792pt）
- 译文：`Beyond_Temperature_Hyper_SimplifiedChinese.pdf`（25 页，**原位翻译**产物，无扩页、非双语交错）
- 体检命令（均已运行）：
  - `python check_translation.py "Beyond_Temperature_Hyper.pdf" "Beyond_Temperature_Hyper_SimplifiedChinese.pdf" --lang "Simplified Chinese" --strict` → exit 1
  - `python check_layout.py "Beyond_Temperature_Hyper.pdf" "Beyond_Temperature_Hyper_SimplifiedChinese.pdf"` → exit 1
- 另用 PyMuPDF + `translate_app.pdfio` 内部函数逐块/逐行核对了阅读顺序、对齐标记、字形与坐标。

## 0. 总览

真正致命的问题**不是"翻错了词"，而是"版面被拆散"**：

| 指标 | 数值 |
| --- | --- |
| 提取出的文本块 | 1650 |
| 其中「单行块」 | 1469（**89%**） |
| 被标记为「右对齐」的块 | 182（11%） |
| 双栏页被判成几栏 | **1 栏**（第 1–13、18 页全部塌陷） |
| check_layout 重叠 | 14 处（第 2/3/5/7/8/25 页） |
| check_layout 漏画 | 3 处（第 12、25 页） |
| check_layout 压线 | 3 处（第 19、21 页） |
| check_layout 字号偏小 | 33 段 |
| check_translation 数字告警 | 17 页（其中约六成为误报或空格差异，见 §9） |
| 文本层缺失字形 | 2 个（第 1 页，U+0000） |
| 中文里残留的英文断字连字符 | 61 处 |

一句话结论：**译文内容大体正确，但排版层被破坏得很严重**——段落被切成"每行一块"、大量译文按右对齐绘制、中文溢出到相邻栏造成叠印，图表内的字被重画后互相压字；附录 G 的提示词被半翻译且叠印。此版本不适合直接交付使用。

## 1.【最严重】双栏版面塌陷 → 段落被打散成"每行一块"

**现象**：译文页的段落不像段落，而是一条条按英文源码行断开的短句，且断点与原文行完全一致。

**证据**（`pdfio._order_generic` 的列聚类结果）：

```
p1  lines=67  med=204 span=488 thr=366 full=1  cols=1  groups=43  single-line-groups=39
p2  lines=95  med=227 span=488 thr=366 full=0  cols=1  groups=83  single-line-groups=72
p6  lines=126 med=234 span=489 thr=367 full=0  cols=1  groups=117 single-line-groups=111
p9  lines=144 med=177 span=488 thr=366 full=0  cols=1  groups=133 single-line-groups=123
```

第 2 页本该是 2 栏、约 25 个段落块，实际得到 **83 个块、其中 72 个是单行**。

**成因**：`_order_generic` 先把"整宽元素"抽出来（判据 `max(1.5×中位宽, 0.75×页面文本跨度)`），再做贪心聚类。本文的行"比一栏宽、但够不到 0.75×跨度"，于是**没被抽走**，反而作为第一个 x 序元素并入第一栏，把该栏的右边界撑到页面右缘；此后右栏每一行的 `x0` 都"小于该右边界"，全部落进同一栏 → 只剩 1 栏 → 退化成整页 y 序（左右栏按 y 交错）。

- 第 1 页触发者：作者行 `Meimingwei Li * 1 …`，宽 358.5pt，阈值 366pt（差 8pt 没达标）。
- 第 2 页触发者：页眉 `Beyond Temperature: Hyperfitting…`，宽 279.5pt，阈值 366pt。

**由此产生的可见破坏**：

1. 中文按英文行硬断行，词被拆开（见 §7 的 61 处）；
2. 单行块 `single_line=True` → 不换行；中文比英文长时只能横向溢出到相邻栏 → 叠印（§3）；
3. 同属一段的句子被拆到不同块里分别翻译，前后重复/不连贯（§8）。

**建议**：整宽判据要覆盖"比**任一栏**宽"的行（例如用列宽/中位段落宽而不是页面跨度），或让 `col_max_x1` 不接受"起点在栏内、终点远超栏"的行。

## 2.【严重】两端对齐的正文行被判为「右对齐」

**证据**：`pdfio._block_meta` 对**单行**块的判据是
`page_x1 - maxx <= 2 且 minx - page_x0 > (page_x1-page_x0)/2` → `align="right"`。
LaTeX 正文（两端对齐）的普通行本来就"右边缘贴着页面右边界"，于是被当成右对齐。

全文 **182 个块**（第 1 页 17、第 2 页 19、第 8 页 20、第 10–13 页各 14–16）按右对齐绘制，表现为**左侧参差、右侧齐平**，看起来像每行都被切断。

典型：第 2 页右上 `定位发现，我们表明无需全参数微调。`（本应左对齐）、第 11/12 页参考文献整段右对齐。

## 4.【严重】「翻译图内文字」（image_text）把图表画坏了

源文里烧在位图里的图注被 OCR 出来后**当作正文重画**，但位置/白底/旋转都没有处理：

1. **白底矩形盖住图表内容**：第 1 页图 1 的 `提升`/`抑制` 白框盖住绿色/粉色柱子；第 3 页图 4 图例 `原始Top-1`/`原始Top 2-10`/`原始超越Top-10` 的白框直接切断柱子。
2. **旋转的坐标轴刻度被水平重画并叠印**：第 5 页原本斜排的刻度 `10-19 / 20-49 / 50-99 / 100-199 / ≥200` 变成同一条基线上的 **`10-120-450-100=209`**（完全不可读）。
3. **旋转的 y 轴标签被竖排拆字**：第 1 页 `Probability` → `概` / `率` 两行；第 3 页 `Top-1` → `Top-` / `1`。
4. **同一张图半译半不译**：第 1 页图 1 的 `Original (T=1.0)`、`Low Temp (T=0.3)` 仍是英文，而同图的 `Same Winner`、`Token A`、`Others` 已译成中文。

## 5.【严重】第 25 页 附录 G 的 LLM 提示词被半翻译 + 叠印

附录 G 是应当**逐字保留**的评判提示词（含 JSON schema）。译文把它逐行翻译，结果：

- 中英混排且同一位置叠印：`**Coherence:** Does the continuation naturally follow from the context? Is` 与 `1. 逻辑在主题和风格上是否流畅一致？` 画在一起；
- 结构被拆散：`**Context:**` → `上下文： **{context}**续写`，占位符 {context}/{continuation_a} 被拼到错误的句子里；
- JSON 模板列被打散：`"coherence_score_a": 1到10的整数评分,` / `_b": 1到10的整数评分, score_a": 1到10的整` 交错在一起；
- 检查器给出 99% 与 84% 两条重叠。

**建议**：代码块/等宽体的提示词默认按"保留原文"处理（或至少不逐行重排）。

## 8. 文本层与内容层面的其它问题

**文本层缺字形（第 1 页 2 个）**：`慕尼黑机器学习中␀（MCML）` 的"心"、`第43届国际机器学␀会议论文集` 的"习"在 PDF 文本层是 **U+0000**。画面可能正常，但复制/搜索/文本抽取会得到 NUL（`page.get_text()` 直接带 \x00）。

**标点/空格**（真问题，非误报）：
- p1 `PMLR 306,2026`（原文 `PMLR 306, 2026`，逗号后空格被吞，容易被读成 30 万）；
- p6 `α ∈[0.01,0.5]`（原文 `[0.01, 0.5]`）；
- p8 `(50.1,64.2)`（原文 `(50.1, 64.2)`）；
- p10/p12/p13 参考文献 `…9(1):147–169，1985`、`arXiv:2502.16722，2025` 等。

**误译 / 不一致**（抽样）：
- p12：`Qwen2.5: A party of foundation models` → **`Qwen2.5：基础模型派对`**（party 误译为"派对"，应为"一组/系列基础模型"）；

## 9. check_translation 的误报（改之前先看这一节）

`check_translation.py` 报了 17 页数字不一致，但**大部分不是数值错误**：

1. **"括号 = 负数"启发式误伤**（`_amounts` 的 `paren_neg`）：源文 `0.684 (+71% rela-`、`compared to Full LoRA (0.528)` 里数字紧跟在 `(` 后就被判为负值；译文的括号变成了中文 `（…）` 或换了语序，数字不再是负数 → 报 `原文 -71 缺失 / 译文 71 多出`（p4）、`原文 -0.528 缺失`（p24）。**数值本身完全正确**。
2. **全角逗号被当成数字分隔符**：`_NUM_TOKEN_RE` 把 `，` 算进 `[0-9,.，．]`，于是 `(50.1,64.2)`、`2502.16722，2025`、`147–169，1985`、`0.01,0.5` 被并成**一个** token，报"缺失 + 多出"（p6/p8/p10/p12/p13）。
3. **图内文字重绘**造成的"多出"：p1 `1.0`/`0.3`、p7 `80.8`、p17/19-23 的图注数值——见 §4。
4. **真问题**只剩"逗号后丢空格"（§8）与第 2 页那次重复绘制。

=> 建议：对非会计文档，`paren_neg` 只认全角 `（` 且要求括号内**仅有**数字；token 正则不要把全角 `，` 当内部分隔符（或先按 `，` 切分再分别取 token）。否则学术论文会长期假红。

## 10. 优先级建议

1. **修列聚类**（§1）——一处修复能同时消除第 8、25 页的重叠、第 12 页的"漏画"、以及全篇 89% 的单行块。
2. **修右对齐判据**（§2）——单行块不要仅凭"贴右边界"就判 right。
3. **默认关闭/改造 image_text 对图内旋转文字的处理**（§4）：无法还原旋转就别重画；白底框不得溢出字形带；同图要么全译要么全不译。
4. **附录代码块/提示词默认保留原文**（§5）。
5. **去断字连字符**（§7）与**修 U+0000 字形**（§8）。
6. 复核第 2 页的块序错位（§6）——若源自模型 `[[n]]` 对齐，说明 `_parse_response` 的"条数相等"校验不足以发现错位。
