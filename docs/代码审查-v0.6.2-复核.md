## 1. 两个 P1

### P1-1 `page_scope` 只在 agent 路径生效 —— IR / 确定性路径整篇翻译（默认 `run.bat` 走 IR），日志却谎报「只翻第 N 页」

`translate_app/worker.py:135` 存入 `self._page_scope`：

```python
self._page_scope: list[int] | None = list(page_scope) if page_scope else None
```

全仓只有**一处**消费它——`worker.py:738`，传给 agent 的 `DocumentSession`：

```python
result = agent_mod.DocumentSession(..., scope=self._page_scope)
```

而生产路径由 `worker.py:263` 分发：

```python
if self._ir_mode:                       # run.bat 设了 PDFTRANSLATE_IR_MODE=1，恒真
    result = self._run_ir(doc, engine)  # 不认 page_scope
elif self._agent_mode and vision:
    result = self._run_agent(...)       # 唯一认 scope 的分支（:738）
else:
    ...                                 # 确定性批次，全文翻译
    result = engine.translate_blocks(doc.blocks, ...)
```

`grep -rn "page_scope" translate_app/` 只命中 `:135` 与 `:738`；`_extract_doc` 也不按页过滤。而 `chat_tools.py:551` 刚用模型解析出页范围并**如实打日志**：

```python
log(f"  [编排] AI 理解为只翻第 {pages} 页" + ...)
```

**主审复现**（2 页样本 + 本地 mock，`page_scope=[1]`＝只翻第 2 页）：

```
P1-1 output page headers: ['===== Page 1 =====', '===== Page 2 =====']   # 第 1 页也被翻译
```

**修法**：在 `_run_ir` / 确定性分支按 `page_scope` 过滤块（把 scope 提升为 `run()` 级别的页过滤），或让两个分支也走同一份页过滤。

### P1-2 `in_image` 图内文字被当成歧义 `ocr` 块交给内容策略

真实 `in_image` 块同时带 `ocr=True`（`pdfio.py:2705` 的 `replace(b, in_image=True, ...)` 保留 `ocr`）。而 `policy.py:104-106`：

```python
if role == "figure" and not in_image:   # in_image → 不进 figure 分支
    kind, default_keep = "figure", True
elif bool(getattr(b, "ocr", False)) and not getattr(b, "keep_original", False):
    kind, default_keep = "ocr", False   # ← 模型可 keep → 图内文字静默不译
```

**主审复现**：

```
P1-2 candidates: [(0, 'ocr', False, 'Revenue by year')]
```

`tests/test_policy.py::test_figure_text_on_a_text_layer_page_is_not_ambiguous` 只传 `in_image=True`、**没传 `ocr=True`**，恰好绕过真实双标志块。

**修法**：ocr 分支加 `and not in_image`（设计契约本就要求图内文字必须翻译）。

## 2. 新发现（既有报告未覆盖）

### N1（P2）内容策略的 `keep` 会让「对话/标注的编辑」在导出时被静默丢弃

契约级冲突。`README.md:103` 承诺「对话的修改保存在受保护覆盖层里，导出时优先于整篇翻译结果」；但导出跳过逻辑在 `pdfio.py:6233`：

```python
if getattr(b, "keep_original", False) and getattr(b, "ocr", False):
    continue          # 只要 keep_original，哪怕 trans[j] 是用户新译文也不画
```

写覆盖层的通道完全不动该标记：`chat_tools.py:308` `set_block_text → ctx.set_overlay`；`doc_context.py:154` `set_overlay` 只写 dict；`worker.py:538` `_apply_overlay_text` 只改 `translated`，不碰 `doc.blocks[i].keep_original`。

**导出层复现**（同一 `ocr` 块，`per_page=[["TRANSLATED-SEAL"]]`）：

```
keep_original=True : 输出 'SEAL\n'                     # 译文被丢弃
keep_original=False: 输出 'SEAL\nTRANSLATE-\nD-SEAL\n' # 译文被绘制
```

**可达路径**：内容策略把某扫描块判 `keep`（印章/手迹）→ 用户在侧栏让 AI「把第 2 页印章翻成 Seal」→ `set_block_text` 写 overlay → 「重新导出」（`worker._run_re_export` 复用带 `keep_original` 的 `_last_doc`）→ 导出仍跳过，用户看不到任何变化。

**修法**：把跳过条件收紧为「且译文就是原文」，即 `keep_original and ocr and trans[j] == b.text`（图表兜底分支已有同款 `trans==src` 判据）；或在 `_apply_overlay_text` 里对 overlay 命中项清除 `keep_original`。

### N2（P3）OCR 公式块会进入内容策略候选，挤占每页名额

`policy.py` docstring 声明「Formulas, numbers and table cells are excluded here」，但代码只排除 `_verbatim`（数字/无字母），没排除 `role == "formula"`：

```
'a + b = c'  candidates: [(0, 'ocr')]
'sin(x)'     candidates: [(0, 'ocr')]
```

`role=="formula"` 非 `in_image` 时 `_keeps_source`（`ir.py:463`）仍会保它、优先于 release，所以**不会丢内容**；但候选会占用 `_MAX_PER_PAGE=6` 预算、并向模型展示它不该判断的块（若整页前 6 块恰是 OCR 公式，真正的印章就不会被列出）。**修法**：ocr 分支加 `role != "formula"`。

### N3（P3，推断）`max_tokens=512` 对全篇 120 个候选偏小

`policy.py:189` 硬编码 512。`_MAX_CANDIDATES=120`，另加 `reason` 与 `reasoning_effort` 的思考 token，可能截断 JSON → `parse_policy_json` fail-open 成「无决策」。无「大候选集 + 推理模型」用例覆盖。**未跑真机，属静态推断**；建议按候选数放大或省略 reason。

### N4（P3）文档与行为漂移

- `README.md:101`「模型不可用时退回离线规则解析」——实际只有**完全没有 llm** 时才用 `parse_explicit_scope`；**有 client 但请求失败**时 `make_llm_flow_compiler` 内部吞异常返回 `{}`，`ai_scope` 直接返回 `(None, "")`，离线兜底被丢弃且**无日志**（对应下方 P2-2）。
- `README.md:42`「特殊页协商」已不再是默认（现为逐页自动翻译，仅 `negotiate=True` 才询问）。

### N5（轻微）工作区卫生

`.review_tmp/`（本次审查的复现脚本所在）与 `.pi/` 均未被 `.gitignore` 覆盖；未提交的 `models.json` 把 `qwen3.8-local` endpoint 改成私有 `192.168.0.19:8888`。

## 4. 总体结论

方向正确：内容策略的**失败方向**（fail-open 到确定性默认）、**红线不可达**、**索引白名单**都做对了；但 v0.6.2 的两项 headline 功能各有一个「主路径失效」的洞——**页范围在默认的 IR 路径完全不生效且日志谎报**（P1-1）、**图内文字被反设计地列为可 keep 候选**（P1-2）。此外发现一个既有报告未提的**契约冲突**：内容策略打上 `keep_original` 后，对话/标注的 overlay 编辑会在 PDF 导出时被 `pdfio.py:6233` 静默丢弃，与 README 的「覆盖层优先」承诺相悖（N1，建议优先修，因为它是**用户可见的静默丢失**）。四个问题修法都不大，每个补一条回归即可；测试 856 全绿但 `page_scope` 端到端、`in_image` 双标志、overlay×keep 均无覆盖——这正是漏网所在。
