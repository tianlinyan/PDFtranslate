# 0.3.4-流程设计：把「流程」从提示词/代码阶段机提升为一等数据结构

> 版本：v0.3.4（草案）　　状态：待定稿　　上一篇：`0.3.1-交互式翻译流程设计.md`

本应用是 **AI 为中心** 的：所有决策都由系统/用户提示词驱动，AI 通过调用**确定性工具**完成任务。本文回答一个问题——**如何把「完成一个相对独立的复合功能」的过程——即「流程」——建模成一等公民？**

一句话结论：**流程 = 由若干「步骤」组成的、可独立调用的复合功能；每步要么是一次工具调用（`ToolStep`），要么是一次有界子代理循环（`AgentStep`），要么是询问用户（`UserStep`），要么是循环/条件（`LoopStep`/`IfStep`）。流程的骨架由两类权威来源决定：**

- **标准流程**：来源是**应用配置/注册表**，骨架固定、可复现；
- **用户自定义流程**：来源是**用户的一句话**，AI 现场从工具集**挑选、排序、定参数**编译成一个流程（或参数化一个标准流程），经用户确认后执行，跑熟后可**沉淀**为命名标准流程。

---

## 1. 为什么需要这一步（现状与问题）

现在「流程」不是数据结构，而是散在 **提示词文本 + 代码阶段机** 两处：

| 层 | 现在在哪 | 问题 |
|---|---|---|
| 宏观阶段机 `preprocess→translate_normal→special_pages→review→completed` | `agent/flow.py::DocumentSession.run()` 硬编码 | 结构在代码里，不可配置、不可复用 |
| 每页微观流程（做什么） | `prompts.page_task` / `review_page_task`（提示词文本） | 只存在于自然语言中，不可检查/参数化 |
| 顺序与调法（怎么调工具） | `prompts.agent_workflow` / `agent_tool_policy`（提示词文本） | 同上 |
| 一次「AI 决策+工具调用」循环 | `agent/flow.py::run_page_visual` = `make_llm_decide` + `FlowAgent` | **已经是标准的 `AgentStep`**，但没被命名成步骤 |

把流程提升成数据结构后，才能做到：**可检查、可审计、可参数化、可复用、可被用户自定义流程复用、可在标准/自定义之间互相沉淀**。这是「AI 为中心」从"提示词驱动"走向"提示词 + 可编排结构"的关键一步。

---

## 2. 核心概念：流程 / 步骤 / 工具

三层，逐层组合：

```
工具（原子）    = read_page, translate_block, check_numbers, ...
                 —— 确定性原语，AI 的"手"
步骤（复合成一） = ToolStep | AgentStep | UserStep | LoopStep | IfStep
                 —— 流程的组成块
流程（复合功能） = Flow(name, description, steps, guards, scope)
                 —— 可独立调用的复合功能
```

### 2.1 步骤类型

| 步骤类型 | 谁执行 | 说明 | 现有对应 |
|---|---|---|---|
| `ToolStep(tool, params)` | 确定性执行器（代码直跑） | 一次无 AI 判断的工具调用；**可复现** | `check_*`、`export` |
| `AgentStep(task, tools_subset, image, max_steps)` | 有界子代理循环 | 一次 `run_page_visual`：模型观察→调工具→读结果→递归 | `run_page_visual` |
| `UserStep(question, options)` | 阻塞 await 用户（侧栏） | 需要人类决定的分叉点 | `ask_user` / 特殊页协商 |
| `LoopStep(until, body)` | 执行器 | 重复 `body` 直到 `until`（含预算/次数上限） | `_ai_self_check` 的逐页复核 |
| `IfStep(cond, then, else)` | 执行器 | 条件分叉 | 保留/跳过页的分支 |

### 2.2 守卫 `guards` 与作用域 `scope`

- **`scope`**：流程作用的页范围 / 块索引范围。例如 `self_check_page` 默认 `scope=已翻译页`，跳过用户选择保留/跳过的页。
- **`guards`**：安全铁律，执行流程前/中强制检查。最重要的两条（沿用现有 `agent/flow.py`）：
  1. **先绑定后暴露**：流程用到的每个工具都必须是 `make_source_tools`/`make_page_executors` 真实绑定的 callable，再经 `tool_names=list(all_tools)` 过滤 schema——**绝不给模型暴露"声明了却用不了"的工具**。
  2. **受保护块不改**：`_protected` = 引擎跳过翻译的（`_needs_translation` 为假）∪ 改写门禁（`pdfio._is_numeric_cell`）。审计/修正一律跳过，否则复核循环会被纯数字格卡死。

## 3. 流程执行器

新增一个薄执行器，它遍历 `steps` 并把上下文（`WorkflowState` + `DocContext` + 通道）注入，聚合结果：

```python
@dataclass
class Flow:
    name: str
    description: str                      # 何时用 / 干什么
    steps: list[FlowStep]
    guards: dict = field(default_factory=dict)   # 先绑定后暴露 / 受保护块 / 预算
    scope: dict = field(default_factory=dict)    # pages / blocks / include_kept / auto_fix

def run_flow(flow: Flow, state, *, log=None, progress=None,
             preview_handler=None, answer_handler=None, render_handler=None,
             cancel=None) -> FlowResult:
    # 依次执行 steps；ToolStep 直跑，AgentStep 调 run_page_visual，
    # UserStep 阻塞等 answer_handler，Loop/If 循环分叉。
    # 全程遵守 guards；取消/预算上限即 fail-closed 返回。
    ...
```

`run_flow` 是**唯一**的流程入口；`DocumentSession.run()` 在迁移后期等价于 `run_flow(translate_doc, ...)`。

> 说明：确定性流程（见 §7）可能只有 `ToolStep`，不需要 AI 编排——执行器对这类流程就是"顺序直跑 + 聚合结果"。

## 4. 流程清单（标准 10 + 自定义 1 类）

### 4.1 标准流程总表

| # | 流程 | 干什么 | 步骤骨架 | 提示词封装 |
|---|---|---|---|---|
| **P1** | `preprocess` | 文档分型 | `[ToolStep(get_doc_info), ToolStep(classify_page) × 每页]` | 无独立提示词（工具描述即可） |
| **P2** | `translate_page` | 翻译单页 | `AgentStep(task=page_task, tools=source+content, image=render_page)` | **`page_task`**（已存在）+`agent_tool_policy`+`agent_workflow` |
| **P3** | `translate_doc` | 整篇翻译（编排） | `[P1, LoopStep(每 normal 页→P2), P4, P5, P10]` | 无（`DocumentSession.run()` 即骨架） |
| **P4** | `special_pages` | 特殊页协商 | `LoopStep(每特殊页→[UserStep(show+ask), If(translate→P2)] )` | **`special_page_question`**（已有）+`review_*` |
| **P5** | `ai_self_check` | 整篇自检 | `[UserStep(review_mode), LoopStep(每已译页→P6), UserStep(export)]` | **`review_page_task`** + `review_mode_question` + `review_export_question` |
| **P6** | `self_check_page` | 单页审计+修正（**核心可复用**） | `[ToolStep(audit), If(有问题→AgentStep(修)), LoopStep(复核 until clean)]` | **`review_page_task`（需泛化，见 §5）** |
| **P7** | `manual_review` | 人工复核标注 | `LoopStep(每页→[ToolStep(goto_page), UserStep(标注)] )` | 预览/聊天工具 |
| **P8** | `re_export` | 重新导出 | `[ToolStep(_run_re_export)]` | 无（`worker._run_re_export`）+`chat_tool_hint` 提及 |
| **P9** | `doc_interact` | 文档问答/导航/改写 | `ChatSession` 的模型→工具→模型循环 | **`chat_system_prompt`**+**`chat_tool_hint`**+`CHAT_TOOL_DESCRIPTIONS` |
| **P10** | `export` | 导出成品 | `[ToolStep(pdfio.save_*)]` | 无（`pdfio.save_*`） |

### 4.2 用户自定义流程（1 类）

| # | 流程 | 干什么 |
|---|---|---|
| **U1** | `user_flow` | 用户一句话 → ① 参数化一个标准流程（改 checks 子集/页范围/是否含保留页/只查不改），或 ② AI 从工具集自由编排成新流程。经用户确认后执行，**跑熟可沉淀为命名标准流程**（`save_flow(name)`） |

> **U1 不是独立堆砌，而是复用 P1–P10 的"叶子"工具 + 参数化标准流程的骨架**。参数化是默认稳健路径，自由编排是进阶、需用户确认（见 §8）。

### 4.3 复用关系

```
translate_doc (P3)
 ├─ preprocess (P1)
 ├─ translate_page (P2) × 每 normal 页
 ├─ special_pages (P4) × 每特殊页
 ├─ ai_self_check (P5)
 │    └─ self_check_page (P6) × 每已译页
 └─ export (P10)

user_flow (U1)
 ├─ 参数化：P6 改 checks 子集 / 页范围 / auto_fix；P2 指定某页；P8 重导出
 └─ 自由编排：从 P1-P10 工具集选+排序（经确认）
```

> **核心可复用单元是 P6（单页审计修正）与 P2（单页翻译）**——它们既是标准流程的子步骤，也是用户自定义流程的底料。你举的"AI 自检"正是 **P5 = 对每个已译页跑 P6、跳过用户保留/跳过的页**。

## 5. 试点：P6 单页审计修正（`self_check_page`）

这是整个流程框架的**试验田**，先落地它再铺开。改动集中在两处：**把审计从"提示词让 AI 记得去查"改成"确定性 `ToolStep` 跑，AI 只在有问题时去修"**。

### 5.1 新增确定性工具 `audit_page(page, checks)`

复用现有 `check_residual/check_missing/check_numbers/check_table/check_layout` 的实现（它们已在 `make_page_executors` 里），合并成一个可参数化的审计：

```python
def audit_page(page: int, checks: list[str] | None = None) -> dict:
    """跑指定子集的确定性审计，合并结果。
    checks 默认全五类：["layout","residual","missing","numbers","table"]。
    跳过 protected 块 + 竖排标签 + 保留/跳过页（由调用方 scope 决定）。
    """
    report = {"page": page, "checks_requested": checks or DEFAULT_CHECKS, "issues": [], "clean": True}
    for name in (checks or DEFAULT_CHECKS):
        findings = _RUN_CHECKS[name](page)          # 即现有 check_* 的内部实现
        report["issues"].extend(_to_issue(name, findings))
    report["clean"] = not report["issues"]
    return report
```

返回统一 findings 结构（供注入提示词 + 供机器判断）：

```json
{ "page": 5,
  "checks_requested": ["layout","numbers"],
  "issues": [
    {"check":"layout","kind":"overflow","index":7,"detail":"译文高度 120pt 超过自身框 80pt"},
    {"check":"numbers","index":12,"source":"3.14 亿元","translation":"314 billion yuan","missing":["..."]}
  ],
  "clean": false }
```

### 5.2 泛化 `review_page_task`（提示词封装）

现在 `review_page_task(page_index)` 是一次性文案。泛化为**参数化 + findings 注入**：

```python
def review_page_task(page_index: int, *, findings: dict | None = None,
                     auto_fix: bool = True) -> str:
    """单页审计+修正任务。
    findings：audit_page 的 JSON 结果（作为具体数据注入，模型不再自己重新推导）；
    auto_fix=False 时只审计报告、不要求改写（只读复核）。
    """
```

**关键变化**：把 `audit_page` 返回的具体 findings **作为数据**塞进提示词（如"`audit_page(5)` 报 index 12：源 `3.14 亿元` / 译文 `314 billion yuan`，missing=['4']"），模型只负责**对着问题清单决定怎么改**，而不是自己重新跑检查推导。这比现在可靠——现在 `review_page_task` 让模型"自己记得跑四类检查并找问题"，模型漏跑一类/漏看一块就假绿。

### 5.3 P6 流程定义（目标）

```python
self_check_page = Flow(
    name="self_check_page",
    description="对一页做确定性审计，并把发现的问题交给 AI 就地修正；只复核真正翻译过的页。",
    steps=[
        ToolStep("audit_page", params={"page": page, "checks": checks}),      # 确定性审计
        IfStep(cond="not audit.clean")                                          # 有实质问题才进入 AI 修正
            .then(AgentStep(task=review_page_task(page, findings=audit, auto_fix=auto_fix),
                            tools=fix_tools + render, image=render_page))
        LoopStep(until="audit.clean or attempts>MAX", body=[                   # 每改一处就确定性复核
            ToolStep("audit_page", params={"page": page, "checks": checks}),
            IfStep(cond="not audit.clean and auto_fix")
              .then(AgentStep(task=review_page_task(page, findings=audit, auto_fix=True), ...)),
        ]),
    ],
    guards={"protect": True, "scope": "translated_pages", "budget": max_steps=24},
)
```

`_ai_self_check` 迁移后等价于：`LoopStep(每已译页 → self_check_page(scope=该页))`，并把 `review_mode_question`/`review_export_question` 作为 UserStep 提到 P5 层。

### 5.4 好处

- 审计**可靠**：不依赖模型"记得去查"——`audit_page` 是确定性代码，跑不跑、跑全不全由执行器保证。
- 只把**有问题的页**交给 AI，AI 的上下文预算花在"改"而非"找"上。
- findings 是**结构化数据**，既进提示词、也进 `WorkflowState.ops`（可审计），也供机器判断 `clean` 结束循环。

## 6. 其余标准流程的定义要点

- **P1 `preprocess`**：`[ToolStep(get_doc_info), LoopStep(每页→ToolStep(classify_page))]`。纯确定性+一次观察，无需新提示词。
- **P2 `translate_page`**：已是现有的 `run_page_visual(page_task)`，即 `AgentStep`。**不改结构**，只把它"命名"成流程步骤并可从 P3/U1 复用。
- **P3 `translate_doc`**：`DocumentSession.run()` 的迁移目标。迁移后 `DocumentSession` 变成薄壳，用 `run_flow(translate_doc)`。
- **P4 `special_pages`**：`LoopStep(每特殊页→[UserStep(预览+询问), If(translate→P2), 记录 user_confirmed])`。提示词沿用 `special_page_question`。
- **P7 `manual_review`**：人工在环流程——`LoopStep(每页→[preview+标注])`，尽量交给侧栏/预览工具，代码里只需要 `apply_annotation` 接线。
- **P9 `doc_interact`**：这是 **chat 侧**，本质已经是"模型→工具→模型"循环（`ChatSession.reply` 的 `_MAX_TOOL_ROUNDS`）。它自成流程，**目前无需改为声明式 Flow**（它是常驻对话，不是一次性复合功能）；只需保证 `re_export` 的描述引导正确。

## 7. 确定性流程（P8 / P10）

决策：**并入 Flow 框架，但单列「确定性流程」**——它们是 `ToolStep` 直跑、不经过 AI 编排：

- **P8 `re_export`**：`[ToolStep(_run_re_export)]`。用上次译文 + 当前 `DocContext.overlay` 重新导出。已由 `worker._run_re_export` 实现；聊天侧经 `re_export` 工具触发。
- **P10 `export`**：`[ToolStep(pdfio.save_*)]`。已有。`OUTPUT_TYPES` 分发。

> 归入框架的意义是**概念统一**（所有"可独立调用的复合功能"都叫流程），但执行器对它们走确定性分支，不消耗 AI 上下文、不受模型漂移影响。

## 8. 用户自定义流程（U1）

### 8.1 两条路径

**路径 A —— 参数化标准流程（默认，稳健）**：用户一句话映射到已知旋钮上，复用标准骨架：

```
"自检只查数字和表格，针对第 3~8 页，把保留页也算进去，数字错了自动改"
  → FlowSpec { base: "self_check_page", checks: ["numbers","table"],
               scope: [2..7], include_kept: True, auto_fix: True }
```

映射可由**规则解析器**做（词汇受限、可测试），也可由 **AI 填 slot**（更灵活，经 `ask_user` 确认）。

**路径 B —— 自由编排（进阶，需确认门禁）**：用户的话没有现成骨架，AI 从注册表选 + 排序编译成新 Flow：`build_flow(spec)` → 用户确认 → 执行器运行。

### 8.2 采纳路径 A/B 的门禁

无论哪条，编译出的工具集**必须先与绑定集对齐**（`make_source_tools`+`make_page_executors`），再 `tool_names` 过滤 schema；且流程必须满足 guards（受保护块不改、预算上限、破坏性操作 `ask_user`）。**绝不给模型暴露"声明了却用不了"的工具**（CLAUDE.md 铁律）。

### 8.3 沉淀

跑熟的用户自定义流程可 `save_flow(name)` 存为命名标准流程，之后与内置 P1–P10 平级展示。这也让"应用配置"本身可被用户扩展、可持久化（如 `~/.pdftranslate/flows/`）。

## 9. 安全 / 铁律（沿用并强化）

1. **先绑定后暴露**（§2.2）。
2. **受保护块不改**：`_protected` = `_needs_translation` 为假 ∪ `_is_numeric_cell`。审计/修正一律跳过。
3. **fail-closed**：任何工具抛异常/未知工具 → 返回 `ok=False` 并带 `error`，绝不崩溃；预算/取消即停止。
4. **结果只给一次+按需视觉**：`make_llm_decide` 的 `tool` 消息只报 `ok/error` + 一次结果；带 `image` 的结果注入为新的视觉观察（`_result_for_message` 剥离图片/字节）。
5. **受保护 overlay 在导出期生效**：AI 对话/标注的编辑在导出中一定赢（`worker._apply_overlay`）。
6. **两套请求参数不变**：交互侧=chat（`interaction_temperature`/`interaction_reasoning_effort`）；翻译侧=其余一切（`temperature`/`reasoning_effort`）。流程编排（`make_llm_decide`）属**翻译侧**，用 `model.temperature`，**不用** `interaction_*`。
