## P1-1　扩页搬走的 OCR 散文块不画白底 → 首页残留原文、续页出现译文

**判定：应修（内容重复 + 未译原文共存）。**

`expand_pages` 的 `_flow_skips()` 只排除四类块，**不排除普通 OCR 块**：

```python
# translate_app/pdfio.py:5959
def _flow_skips(block, trans, chart_page) -> bool:
    if block.is_chart or getattr(block, "in_image", False):
        return True
    if getattr(block, "keep_original", False) and block.ocr:
        return True
    if trans and trans == str(block.text) and chart_page and block.ocr:
        return True
    return False
```

因此扫描页（非表格）上的 OCR 散文块一旦装不下，就会被 `_flow_split` 搬去续页：

```python
# translate_app/pdfio.py:6568（绘制循环内，早于 6636 的 OCR 白底覆盖）
if j in flow_ids:
    continue
...
# translate_app/pdfio.py:6636
if b.ocr and (j not in on_photo or getattr(b, "in_image", False)):
    ...  # 画白底盖住扫描字，再画译文
```

被 `continue` 跳过后，**该块的扫描墨迹在首页原样保留**（红action 只处理非 `ocr` 块），
而译文被画到续页 → 首页是未译原文、续页是译文，内容重复。

**复现**（`.review_tmp/repro_expand_ocr.py`）：

```
expand=False -> pages=1, page1 含译文, dark_px=1554
expand=True  -> pages=2, page1 文本仅 'SCAN-ORIGINAL', dark_px=512   # 扫描墨迹未被覆盖
```

修法：`_flow_skips` 增加 `if block.ocr: return True`（扫描像素不可重排，本就不该移动），
或在移动后于首页补画白底。

## P1-2　短 `per_page` + 扩页 → `IndexError`（违反函数自述契约）

**判定：应修（崩溃 + 契约违背；GUI 生产路径当前的列表长度对齐，故触发面较小）。**

`save_translated_pdf` 的既有契约是容忍较短的 `per_page`：

```python
# translate_app/pdfio.py（save_translated_pdf 内）
m = min(len(blocks), len(trans))   # 注释明确：源 PDF 在提取与导出之间被改过，或调用方传了短列表
```

非扩页路径只遍历 `range(m)`、且 `_compute_table_layout` 对 `bi < len(trans)` 有保护，所以安全。
但扩页路径的 `_flow_draw_row` 对**被搬走行**的每个映射单元格直接取 `trans[j]`，没有该保护：

```python
# translate_app/pdfio.py:6116
for j in cell_ids:
    b = layout_blocks[j]
    _draw_translated_block(page, font,
                           replace(b, y0=y, y1=y + height, fit_height=0.0),
                           trans[j])          # <-- j 可能 >= len(trans)
```

**复现**（`.review_tmp/repro_expand_short_perpage.py`，同一份 PDF、同一份短 `per_page`）：

```
expand False OK
expand True  IndexError: list index out of range
```

修法：`_flow_elements` 只把 `bi < m` 的单元格纳入 `row_cells`，或 `_flow_draw_row` 对
`j >= len(trans)` 用 `str(b.text)` 兜底。

## P2-1　扩页使预览「译文」页号错位

**判定：建议修（用户可见，但需先开启扩页）。**

`_last_pdf` 存在时，预览按 `_translation_output_page` 定位输出页，而该函数对
`translated_pdf` 假定「源页 i = 输出页 i」：

```python
# translate_app/main_window.py:906
def _translation_output_page(self, page, kind):
    if kind == "bilingual_pdf":
        return page * 2 + 1
    return page            # translated_pdf 扩页后不再成立
```

只要任意前置页发生过扩页，之后所有源页的「译文」预览都会显示成**少 N 页**的那一页
（前端错位、内容对不上）。worker 目前只在日志里记录「已扩展到后续 M 页」，没有把
「源页 → 输出页」映射回传给 `MainWindow`。

修法：扩页时记录 `page_map`（源页 → 输出首页），预览据此换算；或在不支持时退回
`_render_cached_translation_preview`。

## P3（轻微 / 边界 / 文档）

- **P3-1 校验脚本对扩页产物错页配对。** `check_translation.py:456` 与 `check_layout.py:378`
  在非交错时用 `src[i] ↔ tgt[i]`。扩页产物页数变多但不会被识别为交错，于是第一处扩页之后
  所有页都拿错译文页比对，可能假绿/假红。建议脚本检测「扩页产物」时给出提示或禁止混用。
- **P3-2 表头切分丢行。** `_flow_header_rows` 允许最多 2 行表头，但 `_flow_split` 若恰好切在
  两行表头之间，续页从被搬走的那一行（`r = n_head` 之前的行）开始，`_flow_draw_row` 只重复
  `r >= n_head` 的行 → 续页缺第一行表头（`pdfio.py:6174`）。
- **P3-3 `is_chart` 是死字段。** 全仓库没有任何 `is_chart = True` 赋值，`_flow_skips` 的首个分支
  （以及 `CHANGELOG.md:29` 声称的「把 `is_chart` 排除在移动之外」）实际恒不生效。真正生效的是
  `keep_original` / chart-page 同文判定。此外文本层**竖排标签**（`_is_vertical_label`，
  `pdfio.py:4737`）既非 `ocr` 也非 `is_chart`，会被当作散文搬走，而其高度是按横排测的、
  绘制时却走旋转路径（`pdfio.py:4823`）。
- **P3-4 cropbox/mediabox 帧不一致。** 首页 `limit` 用 `page.cropbox.height`，续页却用
  `mb.height - _MARGIN`（`pdfio.py:6148`，`mb = src_page.mediabox`）；块坐标是 cropbox 相对帧，
  而续页是 mediabox 页。CropBox 原点非 0 或尺寸不同时，续页内容会整体水平/纵向错位。v0.5.39
  的旋转页修正说明这类帧差异真实存在。
- **P3-5 `rowinfo` 无条件构建。** `return_rows=False` 时仍为每行建 dict（`pdfio.py:5606`），
  大表多页时有小的额外开销。建议仅在 `return_rows` 时构建。
- **P3-6 文档口径与实现不符。** `README.md:81` 与 `CHANGELOG.md:29` 称「只对文本层内容生效…
  扫描件与图内文字不可重排」，但普通 OCR 散文块（非表格、非图内）**会**被搬运，正是 P1-1。
  修 P1-1 后此描述才成立。
