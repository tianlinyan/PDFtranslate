# 0.6.6 文档级翻译方案（TranslationPlan）设计

> 目的：把「开工前先对整篇做一次判断」固化成**可校验的数据**，只覆盖确定性工具算不出的那部分决策，
> 并让执行侧真的消费它。**M1 已实现**（`agent/plan.py` + `prompts.document_plan_task`，默认关、
> fail-open）；**M2 也已实现**（按页 `batch`/`agent`，批量页仍过审计门，见 §5.4 / §9）。

## 1. 为什么做 / 不做什么

### 1.1 现状盘点（都是既有事实，不重复造）

| 机制 | 位置 | 粒度 | 是否用模型 |
| --- | --- | --- | --- |
| 文档信息与逐页分型 | `pdfio.get_doc_info` / `classify_page` | 整篇 + 每页 | ❌ 纯确定性 |
| 图表页默认保留 | `DocumentSession._mark_kept_diagrams` | 每页 | ❌ |
| 文档级术语 | `ir.infer_glossary` → `state.user_decisions["terminology"]` | 整篇，一次 | ✅ 一次调用 |
| 内容策略（保留/放行） | `policy.candidates` + `worker._content_policy` | **每页 ≤6 个候选** | ✅ 每页一次 |
| 用户要求 | `state.requirements` → `FlowAgent.observe()` 的 `requirements=` 栏 | 整篇 | ❌（人给的） |
| 阶段顺序 | `translate_doc.scope["phases"]` | 整篇 | ❌ 固定 |
| 页范围 | `worker._page_scope` → 范围外块标 `keep_original` | 整篇 | ❌（人给的） |

### 1.2 真实空隙

1. **页间抖动**：`policy.candidates` 每页最多 6 个候选、模型逐页判断，同一类页可能这页保留、那页翻译。
2. **约定不统一**：文体/称谓/单位与编号风格/罗马化规则今天只写在 `prompts.py` 的通用规则里，
   没有任何"这一篇要怎么做"的落点，模型每页自由发挥。
3. **调用量**：`normal` 页也是逐页 `run_page_visual`（每页多轮模型调用）。若能在开工前把"哪些页需要
   逐页视觉闭环、哪些页一次批量就够"定下来，省下的是整篇的主要成本。

### 1.3 非目标（明确不做，做了就是退化或新的"说了不算"）

- ❌ **不让 AI 产出文档事实**（页数/页型/语言/有没有表格）：`get_doc_info` 已经确定性、可复现、可测；
  交给模型只会引入不确定性与假阳性。plan **以 `get_doc_info` 为输入**，不替换它。
- ❌ **不做自由文本的"翻译方案"**：一段自然语言"指导后续"无法校验、无法执行、无法回归，等于又造一份
  「日志里说的话」（`page_scope` 的教训：日志说只翻第 2 页、IR/回退路径却全篇照翻）。
- ❌ **不做逐页预算/步数规划**：`Budget`/`max_rounds`/`max_steps_per_page` 是执行层的硬上界，不该由模型定。
- ❌ **不绕过复核门**：plan 只能决定"怎么做"，不能决定"不用查"。

## 2. 设计总览

```
提取（worker._extract_doc，已有）
   └─ DocumentSession.run()
        phase = preprocess
          ├─ get_doc_info / triage                （已有，确定性）
          ├─ _mark_kept_diagrams                  （已有）
          ├─ _inject_terminology  ─┐              （已有，一次模型调用）
          └─ _build_plan（新）      ├─ 合并成 TranslationPlan → state.plan
                                    │
        phase = translate_normal / special_pages
          ├─ plan.glossary ──→ user_decisions["terminology"]   （已有通道）
          ├─ plan.style/notes ─→ state.requirements            （已有通道，observe() 已会打印）
          ├─ plan.keep ──────→ Block.keep_original             （已有通道）
          └─ plan.page_strategy ─→ 每页走 batch 还是 agent     （M2 新接线）
                └─ 两条路都必须过 audit_page 复核门
```

**关键点：M1 不新增任何管线接线**——plan 只往三条已经存在、且已经被每一个消费者读取的通道里写东西。
这样"计划是否被执行"不靠新代码保证，而由既有不变量保证。

## 3. 数据结构

```python
@dataclass
class TranslationPlan:
    """One document-level decision set, produced once, validated against the document."""
    glossary: dict[str, str] = field(default_factory=dict)   # 覆盖/补充 infer_glossary 的结果
    style: str = ""            # 文体/称谓/单位与编号风格（自由文本，只注入提示词，不参与判定）
    keep: set[int] = field(default_factory=set)              # 扁平块索引，写 keep_original
    page_strategy: dict[int, str] = field(default_factory=dict)  # M2: batch|agent|negotiate|keep
    notes: str = ""            # 给用户看的一行说明
    dropped: list[str] = field(default_factory=list)          # 校验时丢弃的东西（必须回报）
    source: str = ""           # "llm" | ""（未生成/降级）——日志与测试据此断言
```

字段语义与约束：

| 字段 | 约束 | 违反时 |
| --- | --- | --- |
| `glossary` | key 必须出现在 `ir.infer_terms()` 的候选集里（或用户术语表/release 过的名字） | 丢弃该条 + 记 `dropped` |
| `style` | ≤ 300 字符，纯文本；**只拼进提示词**，不参与任何 if | 超长截断 |
| `keep` | 索引必须 0 ≤ i < len(flat)，且该块必须落在 `policy.candidates()` 能解释的集合内 | 丢弃 + `dropped` |
| `page_strategy` | key 必须是有效页号；value 必须是枚举值 | 丢弃 + `dropped` |
| 全局 | `page_scope` 之外的页/块**一律不得**被 plan 放行（plan 不能扩大范围） | 丢弃 + `dropped` |

## 4. 生成（`_build_plan`）

- **位置**：`DocumentSession._preprocess` 末尾，紧挨 `_inject_terminology`（同一处已经有"文档级、
  一次、fail-closed"的骨架）→ `_build_plan()`。
- **开关（M1）**：只有 `PDFTRANSLATE_PLAN=1`（环境变量 opt-in，与 `PDFTRANSLATE_IR_MODE` /
  `PDFTRANSLATE_STRUCTURE_MODE` 同款）；关掉时**逐字等价**于今天。prefs/界面开关留到 M2。
- **路径边界（M1）**：方案只在 **agent 编排路径**上生效；IR 与确定性回退路径还没有等价的
  消费点，因此开启时 worker 会**明确记一行**「仅 AI 编排（agent）路径支持，本路径已跳过」。
  设计初稿曾要求三条路径一次到位，M1 选择「要么真做到、要么说清楚」，而不是让方案在两条路上
  静默失效——那正是 `page_scope` 的 P1-5 形态。批量路径的等价消费放进 M2。
- **输入（不把全文给模型）**：
  1. `get_doc_info` 的统计与 `kinds`（确定性）；
  2. `infer_terms(doc_ir)` 的候选术语表（确定性、已存在）；
  3. 每页的**结构摘要**：页型 + 前若干块的文本片段（上限如 3 块/页）+ 表格/图区计数；
  4. `state.requirements`（用户要求）与目标语言。
  总预算 ≤ 8000 字符；超出按"页型优先级"截断（`uncertain/scan/chart` 优先于 `normal`）。
- **提示词**：`prompts.document_plan_task(summary, terms, requirements, lang)`，要求回**严格 JSON**
  （只有 §3 的字段，不许自由发挥）；解析沿用 `user_flows._parse_plan_json` 的容错做法。
- **校验**：`validate_plan(raw, *, doc_info, doc, scope, candidates)` —— 纯函数、可单测，返回
  `(plan, dropped)`。逐条按 §3 的表格判；对不上的**丢弃并回报**（照 `Plan.dropped` 的先例）。
- **失败方向**：模型不可用 / 超时 / 解析失败 / 校验后为空 → `plan.source = ""`，日志一行
  「文档级方案：未生成（原因）」，其余行为与今天**完全一致**（fail-open，绝不因为没方案就不翻）。

## 5. 消费（三条既有通道 + M2 的一条新接线）

1. **术语**：`plan.glossary` 合并进 `state.user_decisions["terminology"]`（`apply_terminology` 与
   `_translate` 已经把它当 `extra_glossary` 传给引擎，并计入缓存键）。plan 的术语**覆盖**
   `infer_glossary` 的同名项。
2. **约定**：`plan.style` + `plan.notes` 追加进 `state.requirements`——`FlowAgent.observe()` 已经
   每轮打印 `requirements=`，因此模型立刻能看到，且**不需要改任何提示词管道**。
3. **保留**：`plan.keep` 写 `Block.keep_original = True`（引擎、IR 的 `_keeps_source`、审计的
   `_audit_protected`、导出器四个消费者都读它）。与 `_mark_page_scope` 的优先级：**页范围优先**，
   plan 只能**增加**保留，不能取消范围外的保留。
4. **页策略（M2，已实现）**：`page_strategy[p] == "batch"` 时该页先走一次**确定性批量翻译**
   （`worker._translate_page_batch` → 复用 agent 本来就会调用的 `translate_blocks` 工具，所以译文
   与 agent 自己翻的一致），随即跑 `audit_page`：`clean` → 该页直接 `done`（省掉整页的 decide
   循环）；不干净 / 抛异常 / 一个译文都没产生 → **回退到逐页 agent**。所以批量只会更便宜、
   不会更差，而「每页必须过审计门」这条不变量没有被绕过。
   两条必须记住的约束：① 只对 **normal 页**接受 `batch`（扫描/图表/待确认页需要视觉循环）；
   ② **保留块永不进入批量翻译**——agent 可以在用户要求时覆盖一个 keep，确定性路径没有这个
   判断力，所以 `_translate_page_batch` 显式排除 `keep_original` 的块，并且批量页的「有没有
   译文」判据也用 `include_kept=False`（否则整页保留会被误判成没翻译）。

## 6. 一致性与可复现

- **缓存键**：`glossary` 已进哈希（`_cache_key` 的 glossary 内容哈希），plan 的术语因此**自动**影响
  缓存名；`style` 只影响提示词、不影响译文缓存正确性；`keep`/`page_strategy` 不写入缓存（它们不改
  译文文本，只改选择）。**若 M2 让 batch 与 agent 产出不同译文，需要把 `page_strategy` 纳入
  `_CACHE_VERSION` 的评审范围**。
- **日志口径**：生成成功 → 一行摘要（术语 N 条 / 约定 X / 保留 M 块 / 页策略分布）；未生成 → 一行原因。
  「AI 说的」与「实际做的」必须在同一行日志里对得上（P1-5 的直接教训）。
- **可测**：plan 是纯数据 → 用假 LLM 注入固定 plan，断言三条通道的最终状态。

## 7. 与既有机制的关系（不重复实现）

- `infer_glossary`：保留。plan 在它**之上**做覆盖与扩展，绝不再写一套术语抽取。
- `policy.candidates` / `_content_policy`：M1 不动；M3 再把页级判定合并进 plan（消除抖动），
  在那之前两者可以共存，冲突时以"更保守"为准（保留）。
- `FlowSpec` / `compile_plan`（Path A/B）：那是**执行层编排**，plan 是**内容层决策**。两者不合并成一个
  结构——否则又会回到「一个 JSON 里既有意图又有步骤，最后说不清谁说了算」。
- `page_scope`：plan 必须在它**之下**生效（见 §5.3）。

## 8. 风险

| 风险 | 缓解 |
| --- | --- |
| 模型编造页号/块号/术语 | 校验器按 §3 丢弃并回报；`dropped` 出现在返回值与日志里 |
| 一次调用拖慢小文档 | 页数 < 3 或 `doc_info.block_count` 很小 → 跳过（记一行"文档太小，不生成方案"） |
| 上下文超限 | 输入有硬预算（§4），超限按页型优先级截断 |
| 计划与实际不一致 | plan 只写既有通道；无新执行路径；日志口径逐条对应 |
| 关掉时行为漂移 | 开关默认关 + 「关掉 ⇒ 与今天逐字等价」的回归（对比导出产物字节/文本） |

## 11. 未决问题

1. ~~**M2 的批量产物要不要过复核门？**~~ **已决（M2 实现时定）：要。** 先批量、后过确定性审计门，
   不干净才进 agent。理由：审计是确定性的、不花模型调用，"省下的调用"本来就来自省掉 decide 循环
   而不是省掉检查；不过门等于用"更便宜"换"可能更差"，而本仓库的质量不变量就是每页过门。
   **待真实文档量一次**：批量页占比与实际省下的调用数（现在只有小样本单测，没有真机数据）。
2. **plan 要不要给用户看/改？** 倾向：M1 只记日志；M2 之后在侧栏给一个只读卡片；编辑留到 M3。
3. **`style` 的自由文本会漂移吗？** 它只进提示词、不参与判定，所以漂移的后果是"文风不一致"，
   不是"内容丢失"；接受。若要更稳，可把它约束成几个枚举（如「公文/学术/口语」）+ 备注。
4. **与术语表（`glossary.json`）的优先级**：建议 `用户术语表 > plan.glossary > infer_glossary`，
   实现时在 `translate_blocks` 的合并处一次性定死并写进 CLAUDE.md。
