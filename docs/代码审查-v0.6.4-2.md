## 2. P1 问题

### P1-1　扩页把「不可搬移块」推出页面：原文被擦掉、译文在页外，且无任何日志

**判定：必须修。静默丢内容（v0.6.4 引入）。**

- **位置**：`pdfio.py:5896`（`prose_blocks` 含**所有**非表格单元块，含 `ocr`/`in_image`/`is_chart`）→ `5919`（给它们算 `shifts`）→ `6781`（扩页路径 `page_height=None`，**关掉页底钳制**）vs `6306`（`_flow_skips` 保证这些块**永不进 flow**）。
- **根因**：两条 v0.6.4 改动（关钳制 + 不搬 OCR 块）的交集处没人负责。这些块既**被下推**、又**不能被搬走**，于是直接掉出页面。非扩页路径因为钳制还在，看不到这个症状。
- **复现**：`.review_tmp/mine_shift_probe.py` / `mine_shift_probe2.py`（我在内部量上取证）、`.review_tmp/mine_shift_visual.py`（像素取证）、`.review_tmp/audit_flow/r28_pixel_final2.py`（子代理独立复现）。构造：400×200 页 = 文本层框线表格（3 行，单元格给长译文）+ 表格下方的位图/OCR 块。
  ```
  块6 ocr=True in_table=False  dy=66.2  绘制框 y 238.2..256.2 【整个框在页高 200 之外】
  flow_ids 不含 6（永不搬到续页）；flow 为空 → 不产生续页、不打任何日志
  expand=True : 页数=1、日志=[]；扫描带暗像素 434 → 0（原墨迹被白底擦掉）
                可提取 "Operating" 词数 5 → 4（该块整句译文消失）
  expand=False: 页数=1、日志=「表格译文超出页底，已压缩行高至 12%」；暗像素 447（覆盖在原位）、译文在页内
  ```
  子代理另有 `in_image` 块同现象（`r28` 实测 `shifts[4]=10.0` → 译文 y1=205.4 > 200）。
- **附带（同一根因、扩页之前就存在）**：`cover_rects` 按**未平移**的原始 bbox 度量（`pdfio.py:6869-6881`），而译文画在 `draw_b`（已平移）→ 覆盖矩形与译文错位。扩页下错位可达 66pt（= 原文被擦、译文在页外）；非扩页下也有小错位（本例 `dy=+22`）。
- **建议修法**（择一）：
  1. `_compute_table_layout` 接受「不可搬块索引集合」，把它们从 `prose_blocks` 的推挤链里摘出，并以其最低 `y1` 参与页底钳制（即：不可搬块上方仍可长高，但不能把它们顶出页面）；
  2. 或 `_flow_split` 之后对**未进 flow** 的元素把 `shifts` 钳回页内（`shift = min(shift, limit - b.y1)`）并记一行告警。
  无论哪种，`cover_rects` 都应随最终 `draw_b` 平移。
- **回归测试**：`test_a_block_below_a_grown_table_never_leaves_the_page`（断言 expand=True 时 OCR/in_image 块的白底矩形与原 bbox 相交，且页内所有词 `y1 <= page.rect.height + 0.5`）。

### P1-2　元素高于一页时，扩页比不扩页**丢更多内容**（上一轮复核 P1-1，仍开放）

- **位置**：`pdfio.py:6404-6416`（`_flow_split` 只在**元素之间**切分，元素内部永不拆）+ `6511-6546`（续页首元素无论多高都直接画）。
- **根因**：扩页路径既不缩字也不钳制，而一个元素高于一页时超出部分永久落在纸外；非扩页路径由 `_fit_block` 缩字兜住。
- **复现（我亲测）**：`.review_tmp/mine_oversized.py`（400×200 单页、一个 23pt 高的正文块 + 1824 字符长译文）：
  ```
  expand=False: 1 页，可提取字符 1549/1824 = 85%
  expand=True : 2 页，可提取字符 1064/1824 = 58%，续页 ymax 205.7 > 200，日志只有「已扩展到后续 1 页」
  ```
  子代理独立复现（`.review_tmp/audit_flow/r9_rot_oversize.py`，595×842，译文 3690 字符）：`expand=False 630/630 词` vs `expand=True 481/630 词（−24%）`。
- **建议修法**：续页对 **prose 元素按行切分**（`_wrap` 出行后按剩余高度分段、段末翻页；表格行仍不拆）；或 `h > limit - _MARGIN` 时退回旧路径（缩字 + 钳制）并**记一行告警**。至少不能让「开了扩页」成为负优化。
- **回归测试**：`test_an_oversized_paragraph_continues_onto_the_next_page`（断言可提取字符数 == 译文非空白字符数）+ 全页 `max(word.y1) <= page.rect.height + 0.5`。

### P1-3　旋转页（`/Rotate 90|270`）+ 表格 + 扩页 → 页数爆炸、首页空白、内容重复

- **位置**：`pdfio.py:6740`（`_extract_tables` 返回的是**旋转显示帧**几何）vs 块坐标/拆分上限（**未旋转帧**）→ `6747` `mapping` 残缺 → `6808` `_flow_split` 用错帧判定 → `6519-6531` 续页重复画行。

  ```
  rot=  0: expand=False 1 页(282 字符) / expand=True 2 页
  rot= 90: expand=False 1 页(234 字符) / expand=True 4 页
           各页字符 [0, 135, 46, 135] —— 页0 空、页1 与页3 完全相同（行重复）

  我另用探针确认帧错位本身（`.review_tmp/mine_rot_probe.py`）：同一页 `page.rect=200×400`、`cropbox=400×200`，而 `_extract_tables` 的行顶 60/100/140 与被绘制的**列** x 坐标一致 → 确认几何来自显示帧。

### P1-5　`page_scope`（只翻第 N 页）在 IR / 确定性路径被忽略

- **位置**：存点只有 `worker.py:136`，消费点只有 `:750`（`DocumentSession(scope=…)`，即 agent 路径）；`_run_ir`（`:472-518`，`run.bat` 因 `PDFTRANSLATE_IR_MODE=1` 默认走这条）与确定性回退（`:299 translate_blocks(doc.blocks, …)`）**完全不使用** `self._page_scope`。
- **复现（我亲测，`.review_tmp/repro.py` 在 HEAD 复跑）**：`page_scope=[1]`（只翻第 2 页）+ `ir_mode=True` → 输出仍是 `['===== Page 1 =====', '===== Page 2 =====']` 两页全译。
- **影响**：用户/模型明确表达「只翻第 N 页」并已打印「AI 理解为只翻第 N 页」，实际全篇翻译（时间、费用、缓存全部浪费），这是"日志与行为不一致"的信任问题。
- **建议修法**：在 `_run_ir` / 回退分支按 `page_scope` 过滤要送翻的块（其余块保留原文），或若某路径不支持则在启动时明确提示「当前模式忽略页范围」而不是谎报。
- **回归测试**：三条路径（IR / 回退 / agent）各一例 `page_scope` 端到端断言。**该缺口正是 P1-5 连续两轮漏网的直接原因**。

### P1-6　`_extend_with_body` 把有框线的表标成 `borderless` → 表格线不擦不重画

- **位置**：`pdfio.py:4198`（`_extend_with_body`）→ `4242`（`borderless=True`）；`4292` 对每个 lines 策略表格都调用；`5924-5939`（`borderless` 表直接 `continue`：既不进 `grid`、也不进 `bboxes` 红action）。
- **根因**：`borderless` 的语义是「源本无线 → 不重画网格」，只对 text 策略兜底表成立；现在被用到**lines 策略检出、本身确有框线**的表上。且它对 `find_tables` 已完整解析的表也会触发：900pt 内有另一张同列宽的表，就被当成自己的「无框线表体」吸收。
- **复现（我亲测，`audit_extract/p1_extend_stacked.py`）**：两张上下相邻、各自全框线的 3 行表 → `find_tables` 返回 2 张，但**两张都 `borderless=True` 且都报同样的 6 行、bbox 同为 (60,90,500,246)**。反事实对照（`p3_extend_counterfactual.py`，同一 PDF 同一批长译文）：跨线 **19/102**；把 `_extend_with_body` 换 no-op → **0/102**；`check_layout.py` 对前者报 9 条 `[压线]`。
- **建议修法**：① 把同页其它表的 bbox 传给 `_extend_with_body`/`_body_side`，跨邻表边界即停；② `borderless` 不应等于「完全不重画」——记录来自 `find_tables` 的 `ruled_rows`，只对这批行出 `grid` 线并保留 `bboxes` 红action。
- **回归测试**：两张相邻全框线表 + 长译文 → `check_layout` 退 0。

### P1-7　列宽重排把窄列压成**负宽度** → 反框、逐字换行并越出表右边界

- **位置**：`pdfio.py:5778-5795`（`new_w[c] = budget*demand[c]/flex_demand` 无下限，随后再减 `_TABLE_CELL_PAD`）。
- **根因**：只在 `total_demand > total_cur` 时重排，所有 flex 列按需求比例缩到需求以下；低需求窄列（`(二)`/`行次`）可分到 <4pt，减 pad 后框反号；`_fit_block` 把 `max_width` 钳成 1.0 → 逐字竖排。
- **复现（我亲测，`audit_extract/p18_reflow_collapse.py`）**：
  ```

- **回归测试**：低需求窄列 + 长译文 → 输出无负宽框、无文字越出表右边界。

### P1-8　换源文件后预览「译文」仍渲染上一份文档的导出 PDF

- **位置**：`main_window.py:571`（`set_source_path` 不清 `_last_pdf`/`_last_page_map`/`_last_output_type`/`_last_translated`）→ `:842-845`（预览按 `_last_pdf` 渲染）→ `:924`（`page_map` 越界时静默回退同号页）。

- **回归测试**：换源后 `_render_translation_preview` 必须返回 `None`（或渲染新文档）。

### P1-9　`txt/md` 导出非原子 + 关窗硬退 → 半截文件毁掉上一份产物

## 5. 覆盖缺口（本轮问题的"为什么能活这么久"）

1. **扩页的"装不下"方向几乎没测**：`ExpandPagesTest` 7 例全是"装得下/刚好装下"的理想场景；`test_continuation_page_orders_the_rows_and_stays_on_the_sheet` 的"不出页"断言只作用于装得下的元素 → P1-2、P1-3 绿着过去。
2. **不可搬块与文本层表格**同页的组合零覆盖 → P1-1。
3. **旋转页 / CropBox≠MediaBox + 扩页**零覆盖 → P1-3、P2-7。
4. **扩页产物的校验链路**零覆盖（`test_check_translation`/`test_check_layout` 无 `expand_pages=True` 用例）→ P2-1。
5. **`page_scope` 端到端**（Worker → IR/回退/agent 三分支）零覆盖 → P1-5。
6. **overlay × `keep_original`** 零覆盖（README 有承诺、无回归）→ P1-4。
7. **审计的"假阳性方向"**零覆盖（只测「该报的报了」）→ P2-3。
8. **`_merge_ocr_blocks` 的顺序契约**零覆盖（现有测试只断言数量/集合）→ P2-4。
9. **reflow 列宽下限**零覆盖（只测了 `demand==0`）；**双语产物表格行高**零覆盖 → P1-7、P2-5。
10. **`_validate_plan` 丢弃行为 / `resume` 语义 / `--skip` 非法值 / OCR 缓存与顺序绑定**零覆盖 → P2-8、P2-9、P3-7、P3-10。

## 6. 做得好的地方（本轮实测确认）

- **默认关闭时逐字节等价成立**：无溢出时 `expand=False` 与 `True` 的页面内容流 sha1 **完全相同**（2396 字节），`_flow_grid`「没搬走任何行时与钳制版逐字相同」是真的。
- **翻译协议层防御扎实**：`_parse_response` 仍严格「恰好 k 条非空译文或抛错」，缺号/重复/越界/空串/空白回复全拒；**没有任何路径用原文填补缺口**，失败批既不写缓存也不进成功结果；`load_translation_cache` 还会主动丢弃历史污染的空条目。
- **并发与取消**：结果按完成序回收但输出严格按输入序对齐（含 3 线程共享同一 engine）；`_cache_lock` 快照 + `_persisted_seq` 丢弃过期快照在 40 组随机失败/多批运行中 0 失败；401/403/404 **恰好 1 次请求**即 `TranslationAborted` 且不挂起（0.06s 返回、12 批只发 4 次请求）、cancel 1.5s 内返回并关闭客户端。
- **`run_flow` 的 fail-closed 语义正确**：`ToolStep`/`AgentStep`/`UserStep` 三处都 `except ControlSignal: raise`；未知工具、工具异常、未知占位符、无 `ask` 通道全部落到 `rs.error`；`LoopStep.max_iter`/`max_steps` 有真上界；`_window_messages` 上下文有界。
- **`DocumentSession` 的失败方向不说谎**：页失败 → `needs_user` 且 summary 明说「待处理/保留页 N 页」；「有可译块但零译文」判 `needs_user` 而非 `done`。
- **工具目录与绑定集严格双向对齐**（24 = 24，差集皆空），schema 与实现签名一致，`tier` 标注正确；已删工具（`set_font`/`set_align`/`rewrite_block`/`create_block`/`move_block`/…）在目录与提示词两侧都查不到。
- **api_key 处理**：`${ENV_VAR}` 惰性替换、未解析绝不上网（改 `"not-needed"` + `validate` 告警）、`repr` 无密钥。
- **帧语义单点定义且注释写清了为什么**：`_rot_map_rect` 在「旋转 × 裁剪」8 组合下像素级命中且往返精确；旋转页照片不画白底（0/90/180/270 像素保持原色）。
- **退化输入稳健**：24 种畸形块（NaN/inf、`x0>x1`、零面积、`size` 1e6/NaN/负、未知对齐、5000 字）过 `_fit_block`/`_draw_translated_block` 全无异常。
- **缓存/偏好原子写**：缓存与 OCR 缓存每批/每页落盘 + 临时文件 + `os.replace`；`save_prefs` 原子写并返回失败原因；`prefs_path()` 空白环境变量视为未设置。
- **提示词与工具单一来源**被机械验证 100% 一致；**AI 工具有效性铁律**有守护。
