# 0.3.1 交互式 AI 翻译流程设计（草案 → 方案）

> 本文档把「AI 互动驱动全流程翻译」的草案细化成一份可落地的**详细方案与分阶段计划**。
> 目标：用户点「开始翻译」或输入「开始翻译」后，由 AI 调用工具预处理、逐页翻译、
> 对特殊页与用户协商、完成后自检/人工复核，并通过预览窗口 + 图片标注来回改当前页。
> 本文只做设计（不改代码）；实施按下方「里程碑」逐步推进。

---

## 0. 一句话目标

把现有「agent 视觉闭环逐页翻译」升级为**文档级、会话式、可交互修正**的工作流：
AI 负责看/想/做，用户负责在关键点做决定、在预览里指点（标注）改页。

---

## 1. 与现有架构的关系（复用清单）

现有代码已具备大量地基，方案在其上扩展而非重写：

| 现有模块 | 现状 | 本方案用途 |
|---|---|---|

| `translate_app/chat.py` `ChatSession`/`ChatWorker` | 常驻后台对话（交互模型） | **用户指令入口**：自由文本 / 中文命令 → agent 动作 |

## 2. 总体会话状态机（阶段）

一次交互式翻译是一个**长生命周期会话**，由 `SessionPhase` 驱动。核心状态机：

```
IDLE
  → PREPROCESS       收到「开始翻译」：AI 调工具采集文档信息、逐页分型（普通/特殊）
  → TRANSLATE_NORMAL 先逐页自动翻译全部**正常文本页**（并行/串行均可，进度上报）
  → SPECIAL_PAGES    再集中处理**特殊页**：逐页 AI 询问 + 预览展示 + 按用户意见处理
  → COMPLETED        全文已生成初稿译文（尚未导出即进入复核）
  → REVIEW           询问「AI 自检 or 用户手动检查」→
                        ├─ AI_SELFCHECK   AI 读回译文页、跑自检清单
                        └─ USER_REVIEW    用户看预览、发指令/标注改页
  → MODIFY           根据用户指令/标注，AI 调工具改当前页（改完回到 REVIEW）
  → EXPORT           用户确认或 AI 完成 → 重新导出
  → DONE
```

阶段只前进不后退（REVIEW↔MODIFY 可反复），可取消/中断回到 IDLE。

**关键顺序**：`TRANSLATE_NORMAL` 一定先于 `SPECIAL_PAGES`——先把能自动完成的大量普通页翻译完，再**集中**进入特殊页协商，避免「翻一页问一页」打断批处理；到 `SPECIAL_PAGES` 时各特殊页才逐页与用户确认。

**关键原则**：
- 只有 `out_doc`（译文侧）可改，`src_doc`（原文）只读（沿用现有硬约束）。
- AI 的每个请求/每处修改都写入 `WorkflowState.ops`，可审计可回退。
- 「特殊页 / 关键决策」一律先 `ask_user`（阻塞侧栏出问题按钮），用户答完再继续。
- 用户在 REVIEW 的任何自由文本都作为**指令**喂给 agent 解析成工具调用。

## 3. 各阶段细化

### 3.1 PREPROCESS（预处理，AI 主动）

**触发**：用户点「开始翻译」按钮；或侧栏输入「开始翻译 / 开始 / 打开这个 PDF」等（由 `ChatSession` 收到后转成一次 `START` 会话）。

**动作（AI 调工具）**：
1. `get_doc_info` → 返回原文件信息：`{pages, title, language_guess, text_pages, scan_pages, block_count}`。
   - 来源：`extract_document_text` 已算出的 `pages`/`ocr_count`/`block_pages`；语言由「原文是否含 CJK」等启发式 `detect_language`。
   - 注意：`extract_document_text` 要在预处理阶段跑一次以拿到块与 OCR 页数，随后阶段复用 `DocumentText`。
2. 逐页分类 `classify_page`（可复用 `classify_block` 思路，或先用一个确定性初筛：无文本层→扫描页、图表页→`is_chart`/竖排标签、表格页→`in_table`、其余→正文）。区分：`normal` / `scan` / `chart` / `table` / `uncertain`。
3. `summarize_doc`（可选）→ 简要给用户一句话：`共 N 页，其中 M 页为扫描件需 OCR，K 页为图表/表格特殊页。`

**输出到侧栏**：AI 用一段中文摘要汇报（仅侧栏显示）。

**决策点**：对 `uncertain` 页直接进入特殊页协商（见 3.3），对 `normal` 页走自动翻译。

### 3.2 TRANSLATE_NORMAL（先自动翻译全部正常文本页）

- **先翻译所有 `normal` 页**，此时不打扰用户。逐页调用现有单页视觉闭环 `run_page_visual`（或批量引擎 `translate_blocks`），只处理 `normal` 页。
- 进度上报 `progress(page_done, page_total, "翻译第 x 页")`，主窗显示流程状态。
- `scan` 页在 PREPROCESS 已 OCR 提取；`table`/`chart` 页**此阶段不动**，留到 SPECIAL_PAGES。
- 每页完成记入 `PageState.status = done` + `translated`。

### 3.3 SPECIAL_PAGES（正常页翻译完后，集中处理特殊页）

对 `scan`（扫描/需 OCR，或不清晰）、`chart`（组织架构/竖排标签）、`table`（报表）、`uncertain` 页，**在全部正常页翻完后集中逐页进行**：

1. AI 调 `preview_page(page, what="source")`:预览窗口弹出，**展示该待处理原文页**。
2. AI 调 `ask_user(question, options)`，例如走固定协商模板（不逐词/逐页重复提问，按页类型给一次决策）：
   - 扫描页：「这是扫描件，需 OCR 识别后翻译。是否继续 OCR 并翻译？(继续/跳过)」
   - 图表页：「此页为组织架构图，节点标签是否保留原文？(保留/翻译)」
   - 表格页：「此页为报表，按原地覆盖+绘制处理？(确认/交给 AI 重建)」
   - 不确定页：「请确认这页应如何处理？(作为正文翻译/保留原文/跳过)」
3. 用户在侧栏点选项 / 在**预览窗口里框选**回传区域，`answer_handler` 返回 `{value, ...}`。
4. AI 按 `user_decisions[key]` 执行：走对应工具（`translate_block` / `keep`（不写）/ `set_text` / `rewrite_block` / `delete_block` …）。
5. 该页标记 `needs_user=True` 写入 `Op.user_confirmed`，防重复问。

**集中处理带来的好处**：所有特殊页共享同一套「预览 + 询问」交互上下文，模式一致、界面不来回跳；普通页批处理不受特殊页提问打断。

### 3.4 COMPLETED（初稿完成）

- 全部非特殊页翻译完成；特殊页按用户决定处理完。
- 汇总 `pipeline_summary`：`已处理 N/M 页，K 处按用户意见保留/跳过。`
- 进入 REVIEW 前置询问。

### 3.5 REVIEW（自检 or 人工检查）

**触发**：COMPLETED 后，AI 主动 `ask_user`：
`「全文初稿已生成。交由 AI 自检，还是你手动检查？(AI 自检 / 我手动检查)」`

- **AI_SELFCHECK**：AI 调用自检工具（读回译文页、检查残留中文/越线/字过小/编号，但注意——上一轮已删掉独立质检；此处由 agent 在 `run_page_visual` 视觉闭环内做，或复用 `check_residual`/`check_missing` 工具）。发现问题→`apply_review_fix` 或 `rewrite_block`/`set_font` 就地修；修完重新 REVIEW 询问是否导出。
- **USER_REVIEW**：进入手动检查循环（见 3.6）。

### 3.6 USER_REVIEW / MODIFY（人工检查 + 指令改页）

这是交互最密集的阶段。用户看预览、发中文指令、在预览图上标注，AI 据此改页。

**导航工具**（AI 可见）：`goto_page(page)` / `next_page()` / `previous_page()` / `show_preview(page,what)`。
- 用户说「显示第 3 页」→ agent 调 `show_preview(2)`。
- 用户说「下一页」→ `next_page()`（AI 维护 current_page）。

**改页工具**（AI 可见且已绑定）：`set_text` / `rewrite_block` / `delete_block` / `create_block` / `move_block` / `set_font` / `set_align` / `draw_block` / `cover_region` / `merge_cells` / `set_text`。
> 现状：`make_page_executors` 只绑定了内容/校验子集，`draw/erase/merge` 等虽在注册表却未绑定。本阶段需把它们绑定到 `out_doc` 的可执行实现（见步骤 8）。

**图片标注回传**（核心新能力）：
- `PreviewWindow.SelectionCanvas` 已能框选并 `sendRequested(cropped_png)` 回传**裁剪图**。
- 增强：回传除了 PNG，还带上**标注在原页上的坐标（image 像素 → 页坐标）**，并且：
  a. `PreviewBridge.get_region` 把 `(png, rect_pdf, page)` 返回给 agent；
  b. agent 调 `apply_annotation(page, rect_pdf, instruction)`：把标注区域映射回 `page` 上最靠近的块（复用/重建 `_nearest_review_block` 思路），AI 依据「该区域原文 + instruction」用交互模型翻译/改写，再 `set_text`/`rewrite_block` 到该块；`void`/`delete` 标注→`delete_block`。
- 用户点「发送」后，裁剪图也作为新图像进 `make_llm_decide` 的下一轮（现有 `preview_page` 图像注入逻辑已支持）。
- 每次修改写入 `Op`，可回退/审计。

**自检收尾**：用户说「好了/完成/导出」→ 进入 EXPORT。

### 3.7 EXPORT / DONE

- 用户确认或 AI 收尾 → `export(output_type)` 调 `pdfio.group_by_page` + `save_*`；主窗「完成/打开输出」。
- 记日志（主窗）：流程状态 + AI 工具调用/操作；侧栏：对话/决策。

| 工具 | 分类 | 说明 |

| `export_output` | structure | 按格式导出当前翻译 |

### 4.2 复用/需绑定的工具

### 4.3 通道
- **侧栏**：自由文本 → `userMessage` → 会话控制器（不再是简单的注入 requirements，而是**指令**）。

- **预览**：`PreviewBridge.get_region` 增强为返回 `{png, rect_pdf, page}`；标注回传坐标。
- **进度**：`TranslateWorker.progress` 上报阶段/页数。

## 5. 数据模型扩展（`agent/state.py`）

```python
class DocInfo:  pages:int; title:str; language:str
                text_pages:int; scan_pages:int; chart_pages:int; table_pages:int
class PageTriage: page:int; kind:str        # normal|scan|chart|table|uncertain
                  decided:bool=False; decision:str=""

SessionPhase = "idle|preprocess|translate|completed|review|ai_selfcheck|user_review|modify|export|done"

WorkflowState:
    phase: SessionPhase = "idle"
    doc_info: DocInfo | None = None
    triage: dict[int, PageTriage] = {}
    current_page: int = 0
    annotations: list[Annotation] = []   # {page, rect_pdf, png, instruction}
    pending_annotations: ...
    summary: str = ""                      # pipeline_summary
    review_mode: str = ""                  # "ai"|"user"
```

## 7. 交互协议细节

### 7.1 用户命令 → 工具调用
会话控制器把 `userMessage(text)` 交给一个 `route_command(text)`：
- 若命中预置指令（正则/意图）：`开始翻译`→`begin`；`显示第x页`/`第x页`→`goto_page`；`上一页/下一页`→`next/prev`；`完成/导出`→`finish/export`；`AI自检/我检查`→`review_mode`。
- 否则作为自由要求，喂给 `make_llm_decide` 让它决定调哪个工具（在 REVIEW/MODIFY 阶段，把当前页观察 + 用户文本作为新的 user 消息发下去）。

### 7.2 标注坐标 → 块
`SelectionCanvas` 已给出 display→image 映射；增强为 image→PDF 页坐标（除以页面渲染缩放）。
`apply_annotation` 里用「标注矩形中心落在块 bbox 内（或最近）」恢复块，拿到 `flat index`，再对该块做修改。

## 9. 错误处理 / 取消 / 重入

- **取消**：沿用 `TranslationCancelled`；会话控制器在每阶段/每指令间检查 `cancel`；预览/问题阻塞可被打断。
- **引擎失败**：某页/块失败保留原文（fail-closed），记入 `result.errors`/`Op`，AI 征询是否重试或跳过。
- **重入**：`begin()` 重置状态；`WorkflowState` 每次会话新建；`out_doc` 逐块 overlay，导出时分页。
- **审计**：`WorkflowState.ops` 记录每次工具调用（target/before/after/reason/user_confirmed），支持逐步回退/重现。
- **模型不可用**：`make_llm_decide` 返回 `None` → 回退确定性批量翻译（现有行为）。

## 10. 分阶段实施计划（里程碑）

> 每阶段结束跑 `python -m unittest discover -s tests` 全绿；测试离线（mock 交互模型）。

**M1 — 文档信息与分型（PREPROCESS）**
- `pdfio.get_doc_info` + `detect_language`；`agent/tools` 注册 `get_doc_info`/`classify_page`；`state` 加 `DocInfo`/`PageTriage`/`phase`。
- 验收：给样例 PDF，`get_doc_info` 返回正确页数/文本 vs 扫描页数；`classify_page` 对样例页分型正确。
- 测试：`test_pdfio`（get_doc_info / detect_language / 分型）。

**M2 — 文档级会话控制器与阶段状态机**
- 新增 `DocumentSession`（`agent/flow` 或新 `agent/session`），持 `WorkflowState`，实现 `begin→preprocess→translate_normal→special_pages→completed` 的阶段推进与进度上报（**先翻完正常页、再集中特殊页**）。
- `main_window` 点「开始翻译」→ 创建会话并 `begin()`；`worker` 改为宿主会话或由会话调用现有执行/导出。
- 验收：侧栏输入「开始翻译」能触发预处理并给出文档信息摘要；普通页自动翻译、进度上报正常；特殊页被推迟到 normal 翻译完成后。
- 测试：`test_session`（用 scripted decide 驱动阶段推进、阶段状态正确）。

**M3 — SPECIAL_PAGES：集中处理特殊页（预览 + 询问 + 按意见处理）**
- 在全部正常页翻译完后，再逐特殊页 `preview_page` + `ask_user`；`user_decisions` 落库。
- 验收：扫描/图表/表格页在 normal 完成后集中弹预览 + 问题按钮，按用户选择执行（保留/翻译/跳过）。
- 测试：`test_session`（特殊页与用户决策路径、处理顺序：先正常后特殊）。

**M4 — 复核阶段（AI 自检 / 用户手动检查）**
- COMPLETED 后询问模式；`review_mode=ai` 走 agent 自检闭环；`=user` 进入 REVIEW。
- 验收：完成初稿后弹「AI 自检 / 我手动检查」；两种模式都能进入并收尾导出。
- 测试：`test_session`（模式选择与出口）。

**M5 — 手动检查：预览导航 + 指令改页**
- `goto_page`/`next_page`/`previous_page`/`show_preview` 工具；`route_command` 用户指令解析；`make_page_executors` 补绑定写/绘制工具。
- 验收：说「显示第3页」「下一页」「把第2页公司名换成 Bank」等，AI 调对应工具改 `out_doc`，预览随之更新。
- 测试：`test_session`（指令→工具调用）；`test_agent`（新工具绑定/只读性）。

**M6 — 图片标注回传 + 坐标改页**
- `SelectionCanvas` 带坐标；`PreviewBridge.get_region` 返回 `{png, rect_pdf, page}`；`apply_annotation` 工具：标注→最近块→按指令改；标注图作为新视觉注入 `decide`。
- 验收：在预览框选并「发送标注」，AI 依据标注+指令修改对应块并更新译文。
- 测试：`test_preview`（坐标映射）；`test_session`（标注→改块）。

**M7 — 导出与收尾**
- `export_output` 工具；完成时调用 `pdfio.save_*`；主窗「完成/打开输出」。
- 验收：确认后正确导出双语/仅译文/文本；日志与侧栏内容分流正确。
- 测试：`test_worker`（导出）+ `test_session`（收尾）。

## 11. 测试与验收策略

- **离线**：复用 `tests/_helpers.py` mock chat-completions（`[n] MOCK:<原文>`），交互模型（decide/聊天）用 scripted/fake client（同 `test_agent`/`test_chat` 模式）。
- **阶段**：每里程碑配 `test_session`/`test_preview`/扩展对应模块单测，保证冷缓存（`PDFTRANSLATE_CACHE_DIR` 指向临时目录）。
- **端到端**：`verify_real_run.py` 或手工冒烟：真实模型跑通「开始→预处理→翻译→特殊页协商→复核→标注改页→导出」。
- **回归**：原有 216 个测试必须全绿；新增不破坏现有 agent 单页循环/翻译/导出契约。

## 12. 开放问题 / 风险

1. **「特殊页」的精确判定**：需明确阈值（扫描=无文本层+图片；图表=`is_chart`/竖排；表格=`in_table`/`find_tables`；uncertain=模型置信度低）。建议 M1 先做确定性初筛，M2/M3 再让 AI 复核不确定页。
2. **自检走 agent 还是独立一轮**：上一轮已删独立质检；本方案的自检回归到 agent 视觉闭环内（不新增独立质检管线），需确认其强度是否够。
3. **标注坐标精度**：用户手绘框 vs 块边界的匹配（用中心点最近匹配已在 QC 里验证过类似思路），边框误差需容差。
4. **AI 调用工具的频次/成本**：REVIEW+M5+M6 是高频交互，需 `Budget`（max_steps/max_passes/cost_cap）与每页上限控制，避免失控。
5. **会话与现有 worker 的执行边界**：是把现有 worker 改为「执行器」由会话驱动，还是会话直接住在 worker 线程？建议：会话控制器**住在** worker 线程（`QThread`），界面交互（预览/问题/标注）经 Bridge 到主线程——与现有 `PreviewBridge`/`AnswerBridge` 一致。
6. **多文档/并发**：同一时间只跑一个交互会话（沿用现有「单 worker」约束）。

---

## 结论

方案把草案落成**7 个里程碑**，核心新增是：
① 文档级 `DocumentSession` 阶段状态机；② `get_doc_info`/`classify_page` 等预处理工具；
③ 特殊页「预览+询问+按意见处理」；④ 复核（AI 自检/人工检查）二选一；
⑤ 预览导航 + 用户指令→工具调用；⑥ 图片标注→坐标→块→修改闭环。

建议从 **M1 + M2** 起步（信息与会话骨架，改动面小、可离线验证），再依次推进 M3–M7。
