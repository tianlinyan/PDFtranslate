# v0.3.0 设计方案：AI 主导的全流程编排

> 状态：已定稿（决策点已于用户确认）　|　对应版本：0.3.0　|　本文档为常驻参考

本方案把项目从「确定性流水线 + AI 决策工具」升级为「**AI 主导编排 + 确定性工具层 + 人类在环**」。目标是最大化 AI 作用，同时守住财务报表项目**必须保真**（数字 / 科目代码 / 术语 / 编号）这条不可妥协的底线。

---

## 0. 已锁定的决策

| 决策点 | 结论 |
|---|---|
| 默认行为 | **0.3.0 默认走「AI 编排」**（AI 控制器主导全流程） |
| 人工确认强度 | **译文侧自由、无需确认**；唯一红线是**原文不可变**（读工具只读，写工具只作用于译文/输出） |
| 用户交互 | **用户可随时提出问题和要求**（任意时刻插入，AI 暂停回应后继续） |
| 交互载体 | **非阻塞侧边栏对话面板**（GUI 内，不打断主流程） |
| 范围 | **全类型文档**（扫描报表、纯文本、图文混排、原文本页等） |

## 一、总体原则

1. **AI 是大脑，工具是手**：AI 永不直接改 PDF，只**调用工具**。一切「编辑/生成/绘制/擦除/覆盖」都被封装成确定性工具；AI 负责决定**做什么、按什么顺序、对谁**。
2. **原文不可变（硬性红线）**：原始文档在**任何情况下**都不被删除、篡改、覆盖原文文字。读/观察工具只读原文；所有写操作只作用于**译文/输出**。译文可被 AI 通过工具调用**随意删除、创建、编辑、删页、建页、重排**，不受限制。
3. **译文可变（不受限）**：AI 对译文侧拥有**完全自由**——增删改块、增删改页、重排、绘制、覆盖、擦除，均无需用户确认（前提：不触碰原文）。
4. **数字与代码不可侵犯**：财务数字、报表/科目/附注编号、单位，任何工具都**拒绝**被 AI 改写（在译文侧同样保真）。数字保真由 `verify_number` + 确定性守卫 + 人工签核保障。
5. **一切可回退**：由于原文始终保留，任何译文修改都能**从原文重新生成/还原**。每个操作记录 `before/after`，有 `restore`；流程有预算上限与步数上限。
6. **可审计**：全程写 provenance（谁改了哪、为什么），可回放、可诊断。

## 二、三层架构

```
┌─────────────────────────────────────────────┐
│ 交互层  Interaction（GUI 侧边栏对话面板）     │
│   · 非阻塞，随时可提问/给要求                │
│   · AI 问（歧义/术语/预算告警）→ 用户答 │
└─────────────────────────────────────────────┘
                ▲ 问题 / ▼ 用户决定
┌─────────────────────────────────────────────┐
│ 编排层  FlowAgent（AI 控制器）                │
│   · 观察（视觉读原文+当前状态+用户要求）      │
│   · 拆解目标 → 计划 → 调用工具 → 读结果       │
│   · 校验反馈 → 递归直至完成/预算/需询问       │
│   · 维护 WorkflowState（状态+来历+预算+待办） │
└─────────────────────────────────────────────┘
                ▲ 调用 / ▼ 返回值(结构化)
┌─────────────────────────────────────────────┐
│ 工具层  ToolPlane（确定性原语，全 fail-closed）│
│   · 分组：读取/内容/绘制/擦除覆盖/校验/结构    │
│   · target=source 只读原文；target=output 自由改译文 │
└─────────────────────────────────────────────┘
```

## 三、工具清单（ToolPlane）

每个工具 = `OpenAI tool schema`（`name/description/parameters`）+ 确定性实现。分组如下。

> **原文 / 译文分离**：`target="source"` 的工具只**读**原文（观测/判定），绝不改写；`target="output"` 的工具作用于**译文/输出**，可自由增删改/画/盖/擦。原文在任何情况下不可删改（硬红线），译文侧完全自由。

### A. 读取 / 观察
| 工具 | 作用 | 返回 |
|---|---|---|
| `read_page` | 读某页块列表+布局元数据 | `{blocks:[Block]}` |
| `render_region` | 渲染某区域成图（供视觉观察） | `png` |
| `get_layout` | 行/列聚类、网格、跨度 | `{rows,cols,grid}` |
| `detect_table_merge` | 表头跨列/跨行 | `[{row,col,rowspan,colspan}]` |

### B. 内容（编辑/修改/生成）
| 工具 | 作用 |
|---|---|
| `translate_block` | 单块翻译（缓存+编号协议） |
| `retranslate_block` | 强制重译（绕过缓存） |
| `rewrite_block` | 改写译文措辞（供用户预览） |
| `set_text` | 直接把某块文本置为指定值（**仅非数字块**） |
| `apply_terminology` | 术语替换（glossary 或用户指定） |

### C. 绘制 / 布局
| 工具 | 作用 |
|---|---|
| `draw_table` | 画干净 N×M 表（含合并） |
| `draw_block` | 画某块译文（位置/字号/对齐） |
| `set_font` | 设某块字号（**夹逼**可读下限/上限） |
| `set_align` | 左/中/右对齐 |
| `merge_cells` / `split_cell` | 格合并/拆分 |
| `grid_rule` / `draw_line` | 画表格线/分隔线 |

### D. 擦除 / 覆盖（作用于**译文/输出**侧，自由；原文受保护不受影响）
| 工具 | 作用 |
|---|---|
| `cover_region` | 白块盖住区域 |
| `erase_text_layer` | 红action 文本层（保留图片/线条） |
| `drop_element` | 移除元素（签字区、水印、照片） |

### E. 校验 / 反馈
| 工具 | 作用 |
|---|---|
| `verify_number` | 数字与原件一致性（TRUE/FALSE+修正值） |
| `check_residual` | 残留中文/漏译检查 |
| `check_missing` | 内容缺失（源有译文无） |
| `qa_render` | 读回成品找问题（溢出/越线/压叠/字过小） |
| `audit` | 汇总差异（数字/术语/编号）→ 报告 |

### F. 交互 / 预览（供用户查看，不修改文档）
| 工具 | 作用 |
|---|---|
| `preview_page` | 在**非阻塞预览窗口**显示指定页（原文/译文），可聚焦某区域/块。用户可随时要求"看第 X 页 / 某块"，AI 调用此工具弹出窗口（见 §5 交互） |

### G. 译文页 / 结构操作（`target="output"`，自由，不受限）
| 工具 | 作用 |
|---|---|
| `delete_page` | 删除译文某一页（输出侧；源页不受影响） |
| `create_page` | 在译文某处创建/插入一页（空白或复制上一页） |
| `move_page` | 重排译文页序 |
| `delete_block` | 删除译文某一块 |
| `create_block` | 在译文某位置创建一块 |
| `move_block` | 移动/重排译文块 |

## 四、AI 控制器（FlowAgent）决策回路

递归：**观察 → 计划 → 执行 → 校验 → 反馈 → 再决策**。

```
用户输入(原文+要求) ──▶ WorkflowState 初始化
        │
        ▼
  LOOP（受限：max_steps / max_passes / cost_cap）：
   ① 观察：read_page/render_region + state → 视觉+提示词
   ② 分析：分类(keep/translate/代码/签字/表/图)、判断结构/读序
   ③ 决策：选工具+参数（tool_call，tool_choice=auto）
   ④ 执行：确定性工具落地 → 结构化结果
   ⑤ 校验：verify/check/qa 看动作是否生效
   ⑥ 反馈：ok? ─yes─▶ 下个目标
            ├─ 可自动修 ─▶ 修正后回④（递归）
            └─ 歧义/术语/预算告警 ─▶ 问用户（暂停→等回复→继续）
        （预算/步数/页数触顶 或 无待办 → 结束）
```

### 递归要点
- **待办目标队列**：state 持 `todo`，AI 逐个推进，可重排/新增。
- **递归预算**：`max_passes`（每页轮数）、`max_steps`（总工具调用）、`cost_cap`；触顶走保守路径（保留原文/回退基线）。
- **fail-closed**：工具抛异常 → `{ok:false, error}`，控制器据此调整；连续失败 → 该处标记 `需人工`。

## 五、人机交互协议（非阻塞侧边栏）

| 触发 | 问什么 | 答 |
|---|---|---|
| 发现歧义 | 「这格是科目代码还是正文？」 | keep/translate/代码 |
| 术语 | 「'递延所得税资产' 统一译成？建议：Deferred tax assets」 | 采纳/改 |
| 校验收支 | 「发现 2 处数字疑似读错，采纳修正？」 | 采纳/保留 |
| 预算 | 「已用 80% 预算，继续或收敛？」 | 继续/收尾 |
| 用户主动 | 任意时刻插入问题/要求，AI 暂停回应后继续 | 自由文本 |
| 查看 | 「让我看看译文第 3 页」→ AI 调 `preview_page` 弹出预览窗口 | 查看/追问 |

**实现**：`FlowAgent` 见 `needs_user` → 向 GUI 发 `ask` 事件（问题+候选）；GUI 侧边栏显示并回写 `answer` 到 state；控制器从暂停点恢复。默认**非阻塞**（不弹模态框），用户可忽略 / 延迟回答。

**预览**：用户随时可要求查看（"看看第 X 页 / 某块"）。`FlowAgent` 解析意图后调用 `preview_page`（带页号/原文或译文/可选的聚焦区域），GUI 据此弹出**非阻塞预览窗口**渲染对应页面（并高亮 `region`/`block`）。此工具只"展示"，不修改文档，也不打断主流程。

**框选发送**：预览窗口支持用户**按住左键在预览图上框选区域**（拖出矩形相框），点「发送」后把**相框内的内容裁剪成图**并发送给 AI——成为 AI 的新视觉输入（用户据此"指哪看哪"）。实现见 `translate_app/preview.py`：`SelectionCanvas`（拖拽框选）+ `PreviewWindow`（显示/发送）+ `crop_region`/`scale_rect`（纯函数，可单测）。

## 六、状态与记忆（WorkflowState）

```python
@dataclass
class WorkflowState:
    src_path: str
    lang: str
    doc: object = None                 # DocumentText（提取后填充）
    requirements: list[str] = []
    user_decisions: dict = {}
    pages: list[PageState] = []        # 每页进度/keep/译文/issues
    ops: list[Op] = []                 # provenance：{tool,args,before,after,reason}
    todo: list[Goal] = []              # 待办目标队列
    budget: Budget = ...
    pending_question: dict | None = None
    log: list[str] = []
```

- `PageState`：`{index, status(pending/in_progress/done/needs_user), keep_indices, translated, issues, decisions}`。
- `Op` 记录让 AI 能「回退一步 / 重做某页 / 审计全过程」，失败时能退到确定性基线。

## 七、可靠性 / 护栏

| 护栏 | 机制 |
|---|---|
| 原文不可变 | 读工具只读（`target="source"`）；写工具只作用于译文/输出（`target="output"`）。`erase/cover/drop` 只作用于译文侧 |
| 数字保真 | 工具层守卫（`_num_atom`、数字原子性）、`verify_number`、`set_text` 拒改数字格 |
| 代码/编号 | `keep` 类块只能保真，不能改（译文侧同样） |
| 递归有界 | `max_steps/max_passes/cost_cap`，触顶收敛或回退 |
| 失败降级 | AI 决策失败 → 标记 `需人工`，不整体崩溃；可整体回退确定性流水线 |
| 可审计 | `audit` 输出差异报告；`ops` 可回放 |

> 底线：**AI 控制「流程、版面、决策」，数字/代码/术语的正确性由确定性工具 + 校验 + 人工签核兜底。**

> **清理说明（v0.3.0）**：0.2.7 及以前的"硬编码约束"（组织结构图/架构图节点自动保留 `is_chart`、手写签字自动剔除 `_drop_signature_items`、姓名列自动保留 `_mark_name_column`、以及对应的图表节点分类复核 `classify_keep_blocks`/`_release_kept_blocks_via_tool`）已从流水线移除——这些由 AI 交互（agent 的 classify/ask_user/视觉）在运行时判断。`Block.is_chart`/`keep_original` 字段与导出的红action/绘制处理保留，供 AI 设置。

## 八、测试策略

1. **工具层**：每个工具确定性单测（`_draw_ai_table`、`_normalize_number` 等已有基础）。
2. **控制器**：假模型（脚本化 tool_call 序列）驱动 `FlowAgent`，断言调用顺序、state 变化、预算收敛、交互触发。
3. **护栏**：测「AI 改数字格→被拒」「预算触顶→收敛」「原文不可变→写工具只作用于译文」。
4. **端到端**：0.2.7 确定性基线作对照，AI 编排只在基线一致/更好时采纳。
5. **Golden path**：真实模型跑真实年报，人工核对。

## 十、权衡与风险

1. **模型随机性**（第 4 页教训）：AI 决策不稳定。缓解＝校验+人工确认+递归重试+可回退。**不假设模型次次对。**
2. **成本/时延**：视觉+多工具调用比现在贵/慢。缓解＝缓存、并发、预算、按需。
3. **过度自由**：AI 可能改不该改的。缓解＝工具守卫（`target` 分离原文/译文）+ 数字不可碰 + 原文不可变红线。
4. **调试**：AI 流程黑盒。缓解＝provenance + 回放 + audit 报告。
5. **财报保真**：硬约束——**AI 控流程，保真靠工具+人工签核**。
