# 0.5.44 混合页（文本+图片）图片翻译方案：让图内文字**可选**转译、默认不破坏图

> 版本：v0.5.44（草案）　　状态：待定稿　　前置阅读：`0.3.8-formula-figure.md`（§7 未决问题「图内 OCR 文字」）、
> `0.3.0-设计.md`（AI 主导 + 确定性工具层 + 人类在环）、`0.4.0-控制台与流程.md`（入口唯一、流程受控台授权）
>
> **本文改判** `0.3.8-formula-figure.md` §7 的结论「当前倾向**不转译**图内文字」：
> 改为「**可选转译，默认保守不译**」——给出触发条件、确定性判据、四种策略与逐级回退，
> 并说明为什么它不必破坏图形（因为覆盖与绘制可复用已有的逐行字形带 + 局部背景采样机制）。

---

## 1. 一句话目标

对**有完整文本层的混合页**里的**位图图片**（截图、示意图、流程图、照片里的表格）：
先把图内文字**识别出来并让 AI/用户看见**，再按图片自身的背景性质选一种处理方式——
**平坦背景**就地覆盖原文并画译文（`overlay`）、**结构型图**交 VLM 重建成矢量（`redraw`）、
**照片/彩色底**完全不覆盖（`keep` 或 `external` 旁注）。
**任何一步失败都退回「原图不动」，绝不静默丢内容、绝不在非平坦背景上挖白洞。**

---

## 2. 现状与问题（证据）

| # | 现状 | 位置 | 后果 |
|---|---|---|---|
| 1 | OCR 只在 `not lines or sparse_text` 时触发 | `pdfio.py:980` | **有文本层的混合页从不 OCR**：图内文字对整条管线不可见（`_needs_ocr` 看得到图片，但调用点的 `and` 条件把它挡掉了） |
| 2 | 稀疏混合页（≤3 行）反而会 OCR 并**并入**文本层 | `_merge_ocr_blocks`、`_ocr_page_blocks` | 图内文字被当普通块翻译：判为「纸」则**白底**覆盖（浅底图/彩色底图上就是一块白疤），判为「照片」则**不覆盖、译文直接叠画在原像素上**（`_photo_ocr_blocks`，`pdfio.py:2302`）→ 叠字。已有雏形，但触发偶然、覆盖色恒为白、无策略、无审计 |
| 3 | 页面分型里没有「含文字的位图」这一类 | `classify_page`（`pdfio.py:208`）→ normal/scan/chart/uncertain(+formula/figure) | AI 与用户都不知道「第 3 页那张图里有 4 行英文」，也就无从决策 |
| 4 | 图注（文本层）照译，图内标注（A/B、坐标轴、单位、流程框文字）不译 | —— | 译文与自己的图注/正文自相矛盾（`0.3.8-formula-figure.md` §2 已列为问题） |
| 5 | 矢量图里的文字**本来就会被译**；但 `is_chart` 节点标签被有意保留 | 导出分支 `pdfio.py:5789`；竖排 `_draw_vertical_label`（`:4380`） | 本方案**不改**矢量图路线，只处理位图（矢量图的图内文字已是真文本） |

**结论**：这不是「从零做一个功能」，而是**把已经存在的「OCR → 覆盖 → 画译文」机制从扫描页推广到混合页的图区**，
并补上它缺的三件事：**触发条件、覆盖颜色、策略与审计**。

## 3. 三个必须分清的对象

| 对象 | 判据 | 现状 | 本方案 |
|---|---|---|---|
| **整页扫描**（scan） | 无文本层 + 整页位图 | 已实现（OCR + 逐块覆盖 + 可选矢量重绘） | 不动 |
| **部分页位图**（partial raster image） | 页内有文本层 + `get_image_info()` 的图区（面积 < 0.95×页） | **图内文字不可见**（问题 1） | **本方案的处理对象** |
| **矢量图形/图表** | 真文本块 + 矢量笔画 | 文字已译；`is_chart` 节点标签有意保留 | 不动（除策略沿用 §5 的「不属漏译」注记） |

## 4. 数据与检测（全部确定性、离线）

### 4.1 图区枚举 `_image_regions_for_ocr(page)`
- 来源：`page.get_image_info()`（与 `_partial_image_rects`，`pdfio.py:2150` 同源；后者把 >50% 页面积的图当扫描，这里放宽到 <0.95×页并**排除整页扫描**）。
- 过滤：单边 ≥ 24pt、面积 ≥ 2000pt²（滤掉图标/二维码/分隔装饰）；同 `bbox` 去重（平铺小图只取一次）；`image_max_regions_per_page` 上限（默认 4，超出则只报告不处理并记日志）。
- 帧：现有代码**已按「同帧」使用**（`_partial_image_rects` 的 rects 直接与 `Block` 框比较覆盖率，见 `_photo_ocr_blocks`），
  即 `get_image_info` 的 bbox 与 `Block` 同为未旋转 cropbox 帧；但**旋转页要落地前先对拍**——
  用 `_rot_map_rect`（`pdfio.py:2477`）映射采样/覆盖，并按 `test_rot_map_matches_the_rendered_ink` 的方法逐角度验证像素位置。

### 4.2 图区渲染与 OCR
- 新增 `_region_to_array(page, rect)`：`page.get_pixmap(clip=rect, matrix=Matrix(zoom,zoom), alpha=False, colorspace=csRGB)`
  → BGR + zoom；**复用** `_page_to_array`（`pdfio.py:1428`）的 RGB→BGR 与 `np.ascontiguousarray`（负步长视图会被 OpenCV 拒）。
- 引擎与解析**全部复用**：`_get_ocr_engine()`（惰性单例、失败降级）、`_ocr_results_from_img()`（`:2926`，含 deskew 回映）、
  `_synthesize_ocr_blocks()`（`:2798`：逐条框 `isfinite` 校验、`_normalize_number` 数字归一化、`_drop_signature_items` 签字剔除）、
  `_clean_text`、`_order_blocks`。**不新增第二套 OCR 代码**。
- **旋转页的坐标帧必须先实测、不可假定**：`get_pixmap(clip=…)` 在 `/Rotate ≠ 0` 的页上「先裁后转」还是「先转后裁」直接决定像素框怎么映回，
  而 v0.5.37 的实锤（旋转页采样帧错位导致白底把照片挖洞）正是这一类错误。落地方式：先用一个小页逐角度对拍
  （把 `clip` 渲染出的墨迹像素位置与 `get_text` 的 bbox 对齐，方法同 `test_rot_map_matches_the_rendered_ink`），
  确认后再写死映射；四条旋转角都进回归。

### 4.3 确定性特征（供策略、AI 与审计共用，单一来源）
| 特征 | 取法 | 用途 |
|---|---|---|
| `paper_share` | `_region_is_paper`（`:2264`）同款局部采样 | 是否允许覆盖（主判据） |
| `bg_color` | **新增** `_image_cover_color(page, image_rect)`：**图片自身外边距**环（内缩 1/20 边长）的 RGB 中位数 | 覆盖矩形填充色（替代恒定白）。**实测：以文字框外围取环会被相邻图表元素污染**——柱状图 x 轴刻度标签的环采到了柱子色，而标题框自身一半是字，块级 `_region_is_paper` 也因此不适用 |
| `line_count` / `char_count` | OCR 行数与去空白字符数 | 是否值得处理（门槛 `≥1` 行、`≥4` 字符） |
| `line_pitch` | 相邻行顶差的中位数 | 行带 `fit_height`、判「行规整」 |
| `overlap_rules` | `_page_rule_mask`（`:2434`）在该区的像素占比 | 判「结构型图」→ 倾向 `redraw`；覆盖时避线 |
| `duplicate_of_text_layer` | `_merge_ocr_blocks`（`:2745`）的「互相包含 + 覆盖率 ≥50%」判据 | 避免同一句话被译两遍、覆盖两次 |

**门槛（保守）**：`line_count ≥ 1 且 char_count ≥ 4 且 paper_share ≥ 0.6` → 标记为「可原位转译」；
不满足 → 只出现在 `list_image_text_regions` 与日志里，**不动导出**。

## 5. 策略（四档，默认 `keep`；判据给建议、AI/用户可覆盖）

| 策略 | 做什么 | 适用判据 | 风险控制 |
|---|---|---|---|
| `keep`（默认） | 原图一字不动 | `paper_share < 0.6`；照片/彩色底/纹理；印章、签名、二维码、logo | 图内文字不译（记录在报告里） |
| `overlay` | 逐行覆盖原文字 + 原位画译文 | `paper_share ≥ 0.6` 且行规整（`line_pitch` 稳定）且 `overlap_rules` 低 | 覆盖色采样失败 → 不覆盖；覆盖矩形不得越出图区 |
| `redraw` | VLM 重建成矢量（框/线/文字）再确定性绘制 | `paper_share ≥ 0.6` 且 `overlap_rules` 高（流程/框线图） | 三重门 + 逐级回退（§6.3） |
| `external` | 原图不动，译文以 ①②③ 编号旁注/图外对照给出 | 必须译但无法覆盖（照片里的表格、彩色底图） | 默认**不新增页**（避免被 `check_layout` 判为未配对页）；追加「图 N 文字对照」页作为显式选项 |

- 决策落点：`state.user_decisions["image_policies"]`（与 `apply_terminology` 写 `user_decisions` 同构），
  键 `(page, region_index)`，值 `{"policy": ..., "note": ...}`；**未指定时用判据建议值**。
- 协商：按 `0.4.0-控制台与流程.md`，标准流程**不逐图询问**；AI 只在判据摇摆（`paper_share ≈ 0.6`、`duplicate_of_text_layer` 为真）
  时 `ask_user`，其余自动按建议值执行并在日志/报告里写明。
- 图注始终照译（它本来就是文本块），不是本方案的职责。

## 6. 渲染（复用为主，新增两处）

### 6.1 `overlay`：覆盖
- **逐行**覆盖，绝不整框覆盖（v0.5.33 的实锤：扫描件整框白底会切断位图表格线）——
  复用 `_ink_bands`（150dpi 实测字形带）得到每行的真实范围。
- **图内块不走上面这条**（v0.5.44 实测）：柱状图的**柱子是大块深色游程**，`_ink_bands` 会把它当墨迹，
  覆盖矩形就把柱子擦掉。图内块的覆盖矩形改为**该块自己的 OCR 框**（∩ 图片 rect）。
- **覆盖色 = 图片自身的背景色**（`_image_cover_color`，见 §4.3）：从图片外边距环取 RGB 中位数
  （纯灰扫描件自然得到近白；浅底图得到对应底色）。采样失败 → 白（图区已过纸面门）；覆盖矩形为空 → 连译文也不画。
- 避让：竖向用 `fit_height = 下一行行顶 − y0 − 1.5`（v0.5.40 语义），横向用 `fit_width` 或图区宽；
  下方有印刷线时沿用 `avoid_below`（`_fit_block`）与 `_page_rule_mask`。
- 覆盖矩形必须被**图区 bbox 裁剪**（`rect & image_rect`）——绝不允许擦掉图外正文。

### 6.2 `overlay`：绘制
- 每行合成一个 `Block(text=译文, bbox=行框, ocr=True, single_line=True, in_table=False, fit_height=…, size=(y1-y0)/1.2)`
  → 直接走 `_draw_translated_block`（`:4439`）/ `_fit_block`（`:4248`）：字号从原字号起缩、下限 `min(源字号, _MIN_READABLE)`
  （**不会把 5pt 的图内标签放大到 7pt**）、装不下时按行带换行、再不行横向溢出。**数字原子性**由 `_is_amount_atom` / `_is_number_atom` 保证（刻度值不会被拆断）。
- **行带与宽度预算**（`_figure_block_bands`）：`fit_height` = 到图内**下一行行顶**的真实行距，`fit_width` = 同行下一块的 x0（否则图片右缘）；
  `_fit_block` 对 `in_image` 块用 `fit_height` 作高度预算。实测：坐标轴标题曾被刻度标签换行后的第二行压住，加行带后各行互不越界。
- **纯数字/刻度不建块**：`0.400`/`0.684`/轴刻度是语言中立的，覆盖后重画同一串数字只有风险（`_is_numeric_cell` / `_is_pure_symbol` 直接跳过）。
- **永不进表格路径**：`in_table` 恒为 False —— 图里的数字若被 `_reconstruct_ocr_grid` 看到，会被当成报表网格重排。
- **轴刻度 / 图例数字**：建议按受保护块处理（只保留原文不译），与 `_is_numeric_cell` 同口径——
  坐标轴上的 `0.5 / 1.0 / 1.5` 被翻成中文数字只会更糟。
- 双语产物：`save_interleaved_pdf` 的译文页已是「源页副本 + 红action 文本 + 画译文」（v0.5.30），
  位图天然保留 → `overlay` 在双语产物上同样成立。

### 6.3 `redraw`（可选、实验）：与「AI 表格重建」同形
- 注入缝 `make_figure_rebuild_fn(model, target_lang, log, client=None)`，签名 `(page_index, region_index, png) -> dict | None`，
  与 `make_table_rebuild_fn`（`translator.py:1318`）一致；VLM 返回
  `{"canvas":[w,h], "boxes":[{"bbox":[..],"text":".."}], "lines":[[x0,y0,x1,y1]], "arrows":[[..]]}`。
- 渲染器 `_draw_ai_figure(page, spec, rect, font)` 与 `_draw_ai_table`（`pdfio.py:5371`）同形（只画矩形/线/文字，字体与正文一致）。
- **fail-closed 三重门**：① JSON 结构校验失败 → `None`；② **源行覆盖率 < 90%**（对 OCR 行数/字符数）→ `None`（防漏节点）；
  ③ 画布越界/越页 → 回退。任一门失败 → 降级 `overlay`；再失败 → `keep` + 日志。默认关闭（需 vision 模型）。

### 6.4 `external`
- 原图不动；图内每行在图**外最近的空白带**标 ①②③（`_fit_one_line` 保证不越页），译文按编号列出。
- 落点优先级：图区正下方空白 → 同页页边空白 → （显式选项）追加「图 N 文字对照」页。
- 追加页会改变页数 → 必须同步 `check_layout` 的配对逻辑（本轮刚修的「未配对目标页」检查会把它报出来，属**预期行为**，日志要说明）。

## 7. 管线落点

| 环节 | 改动 | 说明 |
|---|---|---|
| 提取 | `extract_document_text(..., image_text=None)` 新参数（默认**跟随 `ocr`**） | 图区 OCR 产物作为**普通块**加入扁平列表，带 `in_image=True` / `image_index=k`。**不进 OCR 缓存、不递增 `_OCR_CACHE_VERSION`**：OCR 缓存只服务纯扫描页/稀疏页，而图内块只可能来自**有完整文本层**的页（两者互斥），缓存里本就不会出现图内块；旧缓存反序列化时缺 `in_image` 走默认 False，语义正确 |

| 工具 | `list_image_text_regions(page)`（只读）、`set_image_policy(page, region, policy)`、`render_region(page, bbox)`（0.3.8 §4.3 已提出）、可选 `retranslate_image_region` | 描述统一进 `agent/tool_catalog.py`（单一来源 + `audience`）；**先绑定后暴露**——`render_region` 必须真进 `make_page_executors` 且图片结果进视觉观察 |

| 可见性 | `get_doc_info` 增 `image_text_regions: [{page, bbox, lines, chars, paper_share, suggested_policy}]` | 让 AI/日志一眼看到「第 3 页有 1 张图、4 行英文、建议 overlay」 |
| 设置 | 界面选项「**翻译图内文字**」（默认勾选，`prefs.json` 键 `image_text`）+ `DocumentText.image_text` 记录提取时的设置 | 与「表格列宽重排」「OCR表格重建」同款：勾选框 + tooltip + 即时持久化；**v0.5.46 已落地**。`models.json` 级别的按模型旋钮（`image_ocr_dpi`、`image_max_regions_per_page`）仍走代码常量，未暴露 |
| 体检 | `check_translation` 增「图内行 vs 译文 span」对照；`check_layout` 增「覆盖矩形是否落在平坦背景」 | 判据函数与审计**同一来源**，不写第二套 |

## 8. 安全红线（fail-closed 清单）

1. **非平坦背景绝不覆盖**：`paper_share < 0.6` 或底色采样不稳定 → 不覆盖（照片被挖白洞是不可逆的内容损失）。
2. **覆盖矩形必须被图区 bbox 裁剪**，绝不动图外正文。
3. **逐图降级**：单图 OCR/覆盖/绘制失败只放弃那一张（日志带页码+图号），不丢整页（沿用 `OcrBoxValidationTest` 的防御风格）。
4. **签名/印章**：`_drop_signature_items` 判据先跑（页底 30% + 高框 + 纯字母 + ≤6 字）。
5. **与文本层去重**：先跑 `_merge_ocr_blocks` 的「互相包含 + 位置 ≥50%」判据，避免同一句译两遍、覆盖两次。
6. **任何策略失败都退回 `keep` 并记日志**，绝不静默——静默失败等于「用户以为翻了其实没翻」。
7. **不因本功能改变既有产物**：`ocr=False`（→ `image_text` 默认跟随为 False）时提取结果不变；**真机回归 802 用例全绿**（`ocr=True` 的既有用例也不受影响——图内块只在「有完整文本层且带足够大的位图」的页出现，测试夹具的图片均为纯色块、没有可识别的文字）。

| **2** | **`overlay`（平坦背景）**：`in_image` 块 + `_image_cover_color` + `_figure_block_bands`（行带/宽度）+ 导出接线（原位与双语两条） | 真机导出：图上英文标题/轴标签/刻度标签被替换为中文；**柱子像素保留 99.7–100%**；图内数字刻度原样保留；照片区域 0 覆盖；`FigureTextTest` 4 例（含「图片其余像素逐像素不变」） | ✅ **v0.5.44 已落地**（未跑 `check_layout` 体检与旋转页——旋转页有意跳过） |
| **3** | **策略与审计**：`set_image_policy` + `user_decisions` + GUI 选项 + `_check_image_text`（审计单一来源 + 工具绑定对齐）+ `get_doc_info` 摘要 + `check_translation`/`check_layout` 扩展 | 三档策略各自行为正确；注入「覆盖落在照片上」的用例被审计抓出；`AGENT_TOOLS` vs 绑定集一致性测试通过 | ⬜ 未启动 |
| **4** | **`redraw`（可选/实验）**：`make_figure_rebuild_fn` + `_draw_ai_figure` + 三重门 + 逐级回退 | 注入假 VLM 结果走通；三类失败分别回退到 `overlay` / `keep`；`vision=False` 的模型下整条路径不启用 | ⬜ 未启动 |

> **建议**：**1** 独立可用（不改任何产物，先把「图里有什么」变成可见信息，也是 AI 决策的前提）；
> **2** 是真正的功能（覆盖白底截图类图，收益最大、风险可控）；**3** 让 AI/用户能接管；**4** 只在有 vision 模型时才值得开。

## 10. 未决问题

- **覆盖的印刷质感**：纯色填充在浅渐变/带阴影的图上会留痕。要不要给覆盖矩形加极轻的噪点/羽化？**倾向不做**（宁可不覆盖，也不要在图上留可疑痕迹）。
- **轴刻度是否一律不译**：数值原子性 vs 可读性。倾向：刻度/图例数字**一律保留**，只译文字标签。
- **`external` 的排版落点**：图下空白 vs 页边 vs 附录页；追加页会触发「未配对页」检查（§6.4），需要明确是否接受。
- **图内语言的覆盖范围**：RapidOCR 默认中英自动；图内为德/法/日时需 `ocr_fn` 注入或换引擎——是否要在 UI 暴露「图内文字语言」？
- **术语一致性**：图内术语与正文/`glossary.json` 的联动（图内文字也走同一 `extra_glossary`？）。
- **`redraw` 的验收阈值**：源行覆盖率 90% 是否足够；是否要让 `review_page_task` 的复核循环参与（AI 看图自检产物）。
- **性能**：逐图 `get_pixmap(clip=…)` + RapidOCR，单图预估数十 ms；`image_max_regions_per_page` 上限之外只报告——是否需要「只对用户点名的图做 OCR」的懒策略。
- **与 0.3.8 文档的关系**：本文取代 `0.3.8-formula-figure.md` §7「图内文字不转译」的结论，需在该文档对应条目加一行「见 0.5.44」。
