## 1. P1 问题

### P1-1　表格内的「保留块」被整段擦掉（`page_scope` 使其成为常规路径；v0.6.4 无此问题）

**判定：必须修。静默丢内容 + 回归（v0.6.5 引入）。**

- **机制**：v0.6.5 把「保留块」的语义从「跳过绘制」改成「红action 与绘制都跳过」（`pdfio.py:7277-7282` 与 `:7324-7337`）。但**表格那一遍红action 没有被这个判据豁免**——`for bb in bboxes: page.add_redact_annot(bb)`（`:7286-7287`，pass 2 `:7301-7306`）会按整张表的 bbox 擦一遍。于是表格内的保留块：① 逐块红action 跳过（文字留着）→ ② 表格 bbox 红action 把它擦掉 → ③ 绘制也跳过（不补画）→ **文字彻底消失**，且没有任何日志。
- **为什么现在必然被踩到**：`worker._mark_page_scope`（`:550-571`）把 `page_scope` **范围外的每一个块**（含表格单元格）标成 `keep_original=True`，而引擎对保留块返回的就是原文（`translator.py:767` `translated=list(blocks)`）→ `keep_original and trans == 原文` 恒真。**即：用户说「只翻第 2 页」，第 1 页（和其它页）里的表格文字会被删掉。**
- **复现（实测，`.review_tmp/repro_scope_table.py`，单页 3×3 全框线表）**：
  ```
  # 模拟 page_scope 对范围外页的处理：所有块 keep_original=True，trans=原文
  blocks = 9
  blocks whose text vanished from the export: ['Cell00','Cell01',...,'Cell22']   # 9/9 全没了
  ```
  单块的对照（`.review_tmp/repro_kept_table.py`）：表内保留块 `Echo` → 输出里**找不到**；表外保留块 `free standing paragraph` → **原样保留**（对照成立）。
  双语导出同样中招（`.review_tmp/repro_h2c.py`：镜页 `Cell11 kept: False` / 表外 `free standing kept: True`）。
- **反事实对照（`.review_tmp/head` worktree = `dd4d77f`）**：同一脚本在同一 PDF 上，v0.6.4 输出 `keep Echo` 段**有** `Echo`（保留块被逐块红action 后又按 `trans[j]` 画了回来）→ 确认是**本轮引入的回归**，不是旧账。
- **建议修法**：把「保留 = 不红action」与「保留 = 不绘制」绑成同一个**覆盖判据**，而不是各自为政。最小可靠修法二选一：
  1. 保留块**只对「不被任何表格 bbox 覆盖」的那些**跳过红action 与绘制；被表格 bbox 覆盖的保留块照旧「红action + 用 `trans[j]`（=原文）重画」——即恢复 v0.6.4 的行为；
  2. 或让 pass 2 的表格红action **避开保留块的矩形**（`bboxes` 减去保留块，必要时拆成多个 annot），pass 1 与之同口径。
  两个导出器（`save_translated_pdf` / `save_interleaved_pdf`）必须同改——它们各有各的红action 序列。
- **回归测试（必须一起补，否则 §4 的缺口还在）**：
  - `test_a_kept_table_cell_keeps_its_text`（原位）+ 双语各一例：断言输出页文本里**找得到**该单元格原文；
  - `test_page_scope_does_not_erase_other_pages_tables`（端到端：`page_scope=[1]` + 含表格的 2 页 PDF + 原位 PDF 导出）：断言第 1 页表格文字仍在、第 2 页被翻译。

### P1-2　向上扩展表体时 `ruled_rows` 记错行：真表格线被擦、假表格线画在散文行上（v0.6.4 无此问题）

**判定：必须修。静默丢内容（表格线）+ 凭空加线；回归。**

- **机制**：`_extend_with_body` 支持向**上**（`above`）补齐无框线表体。当 `above` 非空时，返回的行序是 `[合成行…] + [find_tables 的有框线行…]`，但 `ruled_rows` 被写成 `len(rows)`（`pdfio.py:4264`，`rows` 只数 `find_tables` 的原始行），`_compute_table_layout` 又把它当成「**前** `ruled_rows` 行有框线」（`:6113-6135`：`n_rows = min(ruled_rows, len(orig_top))`，`grid`/`new_bot_last` 全用它）。于是：
  - 表格线画在**合成行**的位置（凭空加线）；
  - 真正有框线的表带：`ruled_bbox` 那一遍红action 把它擦了，但 `grid` 里没有它 → **不重画 → 表格线整条消失**。
- **复现（实测，`.review_tmp/repro_above_full.py`；构造：y=150 一条整宽横线 + 3 行限定在列内的文字（无内线）+ y=250..300 一个全框线表带，最后一行才是 `find_tables` 认到的表）**：
  ```
  declared ruled_rows= 1  ruled_bbox= Rect(72.0, 250.0, 520.0, 300.0)
    row 0: y 155.2..177.7 synth      <-- 被当成「有框线的那一行」
    row 1: y 177.7..207.7 synth
    row 2: y 207.7..230.3 synth
    row 3: y 250.0..300.0 RULED      <-- 真正有框线，却被当合成行
  v0.6.5 输出横线: [150.0, 155.2, 177.7]      # 250 / 300 两条真线没了，多出两条假线
  v0.6.4 输出横线: [150.0, 250.0, 300.0]      # 反事实对照：真线都在（当时整表 borderless、既不擦也不画）
  ```
- **建议修法**：`_DetectedTable` 记录「有框线行的**区间**」而不是「前缀条数」（例如 `ruled_span=(len(above_rows), len(above_rows) + n_ruled)`，`_extract_tables`/`_compute_table_layout` 按区间出 `grid`、按 `ruled_bbox` 红action）。`ruled_rows` 这个名字本身就是错误抽象的来源。
- **回归测试**：一条整宽横线 + ≥2 行列内文字（在上）+ 一个全框线表带（在下）→ 断言输出里**原始表带的横线 y 仍在**、且合成行上**没有**新增横线。现有 `test_a_stacked_ruled_table_keeps_its_rules_aligned` 只覆盖「相邻两张全框线表」（`below` 方向），覆盖不到这条。

### P3-2　`keep_original` 被 `_flow_skips` 收编后，扩页关闭的原因被日志说错
- `_flow_skips`（`pdfio.py:6594-6603`）现在对 `keep_original` 也返回 True，于是 `fixed_below`（`:7125-7140`）会因**文本层**保留块而整页关掉扩页，日志却说「表格下方有扫描/图内文字块（像素不可搬移）」——文本层保留块与「像素不可搬移」是两回事。建议按块类型分开措辞（至少别说成扫描块）。

### P3-3　扩页产物「原文」侧回退的页号与画面不一致
- 输出页翻页模式下（`_uses_output_paging`），若该输出页没有译文，回退渲染 `self._source_page_for_preview(page)`（另一张源页），标题却是 `预览（原文）· 第 {page+1} 页`（`main_window.py:749-774`）——号是输出页号、画面是源页。建议回退分支改用源页号（或明确标注「输出第 N 页（无译文，显示原文第 M 页）」）。

### P3-4　`_has_cjk` 的两个实现从此语义不同
- `flow.py:717-741` 新增「单个单位汉字不算残留」，`check_translation.py:354-369` 的同名函数没有这个豁免。于是同一份产物：审计门 `clean`，CLI 报「残留中文」。（P3-11 刚把「字号下限」统一到同一口径，这里又分叉了。）

## 3. 覆盖缺口（这两条 P1 为什么能过 907 条测试）

1. **「保留块 × 表格」零覆盖**：新测试只测了 OCR 保留块（`KeptOcrPixelsTest`，块不在表内）。没有任何用例断言「表内保留块的文字必须在产物里」。
2. **`page_scope` 端到端只看文本导出**：`PageScopeTest.test_every_path_honours_the_page_scope` 用 `plain_text` 产物断言「范围外没有 MOCK:」——而 P1-1 是**PDF 导出**的缺陷，文本导出路根本不经过红action，所以必然漏。**建议把该用例扩成三种输出格式（plain_text / translated_pdf / bilingual_pdf）。**
3. **`_extend_with_body` 只测了 `below` 方向**：`test_a_stacked_ruled_table_keeps_its_rules_aligned` 是上下两张全框线表（`below` 被 sibling 截断），没有「表体在**上**」的用例。
