## 1. P0 — 必修（体检工具失效）

### P0-1 `check_translation` 对双语产物按 `tgt[i]` 配对 → 译文页从不比对（整体假绿）

`check_translation.py:439-446`（`Checker.check`）：

```python
n = min(src.page_count, tgt.page_count)
for i in range(n):
    style = self._check_page(src[i], tgt[i], i, skip_scan)   # ← 双语产物里 tgt[i] 是原文页
```

双语产物是「原文页 i + 译文页 2i+1」交错的 2N 页；`tgt[i]`（i<N）取到的是**下一组配对的原文页**，
真正的译文页 `2i+1` **永远不被检查**。姊妹脚本 `check_layout` 本轮已修同类页错配（S4：`interleaved` + `2i+1`），
`check_translation` 未同步。

**主审复现**（1 页源「Total assets 123,456.78 yuan」，真 `pdfio.save_interleaved_pdf` 写译文页
「Total assets **999,999.99** yuan」）：

```
G) bilingual pages: 2 | p0: 'Total assets 123,456.78 yuan' | p1: 'Total assets 999,999.99 yuan'
H) run_checks numeric: []   cjk: []
I) all_clear: True                       # 数字被改成 999,999.99 却判「干净」
```

即：**一份数字完全错误的双语产物，`check_translation` 结论是 exit 0 / 体检通过**。

**修法**：照 `check_layout.check_document` 的做法加 `interleaved = tgt.page_count == 2*src.page_count`，
译文页取 `2i+1`；并加一条「写错数字的双语产物必须报出」的回归。

## 2. P1 — 应修

### P1-1 图区枚举阈值（0.95×页）与所有下游消费方（0.5×页）不一致 · 覆盖色退化 + 双语丢图

`translate_app/pdfio.py:2501`（`_IMAGE_MAX_PAGE_SHARE = 0.95`）、`:2524-2535`（枚举，面积 ≤ 0.95×页即收）
对照 `pdfio.py:2226`（`_partial_image_rects` 只收 **≤ 0.5×页**）、`:2698-2703`（`_containing_image_rect` 用它）、
`:2717-2718`（取不到图区 → 回退纯白）、`:5050`（`save_interleaved_pdf` 的 `keep_art` 也用它）。

面积在 **(0.5, 0.95]×页** 的位图图（大截图、整版图表——正是本功能目标场景之一）会被 OCR、建 `in_image` 块，
却在导出时找不到所属图区。

**复现 A（覆盖色退化为纯白，且不裁图区）**：400×600 页 + 340×380pt 图（**0.538×页**），浅灰底图注入 OCR 标签：

```
_image_regions_for_ocr -> [(40,230,380,610)]      # 收
_partial_image_rects   -> []                      # 不收
_containing_image_rect(block) -> None
_image_cover_color(page, None) -> (1.0, 1.0, 1.0) # 纯白
导出后逐像素：源图底色 (198,198,208) → 覆盖矩形 (255,255,255)
```

浅底/彩底图上留**白疤**；README v0.5.44 与设计文档 §6.1 承诺的「覆盖矩形 = OCR 框 **∩ 图片 rect** +
**图片自身外边距采样色**」在此失效。

**复现 B（双语译文页整张图丢失）**：同一页 `save_interleaved_pdf` → 译文页 `get_image_info() == 0`，
图内译文**悬空**（`keep_art` 为假 → 译文页是空白页）。图在双语译文页缺失自 v0.5.30 的 0.5 阈值起就存在，
但本轮让该页多出悬空译文。

**修法**：抽一个 `_figure_image_rects(page)`（0.95）供 `_containing_image_rect` 与 `keep_art` 共用；
或把枚举阈值降回 0.5 并在日志里明说「>50% 页的图本轮不处理」。关键是「同一个问题只能有一个答案」。

### P1-2 设计规定的 `char_count ≥ 4` 保守门槛未实现 → 短碎片擦图重建

`translate_app/pdfio.py:2680`（只过滤 `_is_pure_symbol` 与 `_is_numeric_cell`）
对照 `docs/0.5.44-混合页图片翻译方案.md:77`：「`line_count ≥ 1 且 char_count ≥ 4 且 paper_share ≥ 0.6` → 方可原位转译；不满足只记日志、**不动导出**」。

**主审复现**：60×60pt 白底「图标」图（3600pt²，双边 ≥ 24pt）+ 注入 2 字符 OCR `"TM"` →

```
in_image blocks from a 2-char OCR fragment: [('TM', 0)]
```

logo / 公式截图 / 水印上一个 1–3 字符碎片就会成为一个**被矩形盖掉再重画译文**的块。
`FigureTextTest` 用的是 11 字符 `"CHART LABEL"`，该分支无测试。
**修法**：按区域累计去空白 `char_count ≥ 4` 才建块。

### P1-3 `check_layout` 对大下推的块仍报「漏画」（假红）

`check_layout.py:225-247`（`_covers` 的 slack 分支）/ `find_missing:273-308`。
slack 为 `box.height/2 + 12pt`，但 docstring 宣称「表格上移把散文下推也算」。

**主审单元复现**（源块高 14pt，译文整块下移）：

```
push=10pt slack=19.0 _covers=True  missing=False
push=25pt slack=19.0 _covers=True  missing=False
push=29pt slack=19.0 _covers=False missing=True     # 译文确实画在下移后的位置，仍报漏画
```

子代理用**真实导出**复现：3 行带框线表格、第 1 行译文变长使下面各行下推约 29pt，
第 2 行「667」的译文渲染可见地落在下移后的行内，仍报
`[漏画] 源块 (202,171.2)-(338,185) 附近没有译文` → exit 1（HEAD 版本同样命中，属旧缺陷，
但本轮的 slack 判据/注释声称已覆盖此情形）。
**修法**：slack 直接取「本页累计行位移」或放宽到 `box.height + 12` 以上；或把下推量传给
`find_missing` 作为候选窗口。

## 3. P2 — 建议修

### P2-1 `ChatCancelled` 未继承控制信号基类，且被末段的 `except Exception` 吞掉

`translate_app/chat.py:61` `class ChatCancelled(Exception)`；
`chat.py:283-291`：`try: _check(); msg = self._call(...)` … `except Exception: pass`。
仓库约定是控制信号统一继承 `translate_app/control.py` 的 `ControlSignal`（CLAUDE.md；流执行器一律 `except ControlSignal: raise`）。

**主审复现**（让 `cancel` 只在循环耗尽后的最后一次 `_check()`（第 17 次轮询）返回真）：
`reply` 不抛 `ChatCancelled`，而是返回占位文案「（工具调用次数过多，已停止本轮）」——
与其 docstring「cancel 返回 True 就抛 `ChatCancelled`」矛盾。
GUI 路径被 `ChatWorker.run` 事后复查 `_cancel_ev` 兜住（仍显示「已取消」），所以用户暂时看不出；
但契约已破，任何直接 `ChatSession.reply(cancel=…)` 的调用方会拿到一份本应作废的回复。
**修法**：`class ChatCancelled(ControlSignal)`，末段 `except ControlSignal: raise`。

### P2-2 页范围提示词的动词表漏词（静默把整篇翻掉）

`translate_app/agent/user_flows.py:150-156`。v0.5.42 把裸 `只/仅` 收窄成限制短语，方向正确，但**收得过窄**。
主审实测 `uf.parse_explicit_scope`：

| 输入 | 结果 |
| --- | --- |
| 只翻/只查/只看/只第5页、只翻译/仅第3页、只处理/只导出第3页、限定/范围/仅限第3页 | ✅ 命中 |
| 只**保留**第3页 / 只**留**第3页 / 只**想要**第3页 / 只有第3页 / 唯独第3页 | ❌ `None`（＝整篇翻译） |

动词表缺 `保留/留/要/想要/需要`。后果：用户要「只保留第 3 页」→ 整篇被翻，无提示。
**修法**：补动词，或对「`只/仅`+第N页」在排除 `只要/不仅/不只` 后统一命中。

### P2-3 图内 OCR 不响应取消，且界面默认开启（成本未量化）

`pdfio.py:2606-2610`：`_image_text_blocks(page, page_index, ocr_fn, log)` **没有 `cancel` 参数**；
`extract_document_text` 全函数唯一的取消轮询在 `pdfio.py:3347`（仅扫描页的 `_ocr_page_blocks` 内）。
而 `pdfio.py:1128` 对每个「有完整文本层且非稀疏」的页都跑图区枚举 + 72dpi 整页渲染 + 每区 300dpi 渲染 + OCR（≤4 区/页）。
后果：点「取消」后当前页最多 4 次图区 OCR 仍会跑完；默认开启（`main_window` `prefs.get("image_text", True)`）
会给所有带图页加这笔开销，而设计文档 §10 自己把「性能」列为未决问题。
**修法**：把 `cancel` 传进 `_image_text_blocks` 并每区轮询；补默认开销的量化。

### P2-4 `check_translation` 的「分隔符角色」视图已成死代码，注释仍宣称在做它

`check_translation.py:258-259`（`_src_roles/_tgt_roles` 取到即弃）、`:272-274`（`_page_numbers` 全仓库无调用）、
`:490-493`（注释仍写「并保留分隔符角色比较以抓千分位/小数点错乱」）、`:174-192`（docstring 仍称两视图各有用）。
P0-5 改成纯按值比较是对的，但角色视图没清理：`_amounts` 里 `roles` 只接到死函数 `_page_numbers` 上。
**修法**：删 `_page_numbers` 与 `roles`（或让 `_numeric_diff` 真正使用它），同步注释/docstring。

### P2-5 `check_layout`「压线」拿**源页**规则掩膜比对**已重排**的译文 → 假红

`check_layout.py:391-407`（`find_rule_crossings` 的调用点）。
子代理用真实导出实测：源页横线 `y=100/130/160/190`；导出后目标页表格线经 redaction 重画在
`y=100/130/185.9/215.9`（`get_drawings` 实测），源线 `y=160` 在产物里已不存在，仍报
`[压线] 27% 压在表格线上 (65.2,154.0)-(194.6,161.8)` → exit 1（HEAD 同结果，旧缺陷）。
判据「压源页印刷线」对**未重排**的产物是对的，但对 `reflow/rebuild_table` 的表格必然错位。
**修法**：对检测到表格网格的产物改用**目标页**的规则掩膜（或对已重排页跳过源规则比对并提示）。

### P2-6 `_text_layer_blocks` 提取失败 → 整篇「漏画」静默跳过 + 「体检通过」

`check_layout.py:449-452`：`except Exception: return {}`。提取失败与「源页本无文本层」都返回 `{}`，
调用方 `check_document` 于是把每一页记成 `scanned_pages`、**不做漏画检查**。
主审复现（`mock.patch.object(pdfio, "extract_document_text", side_effect=RuntimeError("boom"))`）：
`missing=[]`、`scanned_pages=[1]`、`structural()==[]` → `main()` 打印「体检通过」并 return 0，只留一句误导性的「扫描页…跳过」。
本轮 diff 修了 `luma is None` 的同类静默跳过，这条同类路径未修。
**修法**：把提取失败与「无文本层」分开，失败时记日志并计入 `pages_issue`（fail-closed）。

### P2-7 `--lang zh` / `cn` 被当成西文目标

`check_translation.py:343-354`（`_has_cjk` 白名单只认 `chinese`/`中文` 等）。
主审实测：`_has_cjk("zh") is False`、`_has_cjk("cn") is False`、`_has_cjk("Chinese") is True`。
用户以 `--lang zh` 跑中文目标时会被当西文目标 → 触发「残留中文」告警（`--strict` 下 exit 1）。
端到端影响为**推断**（默认字体写不进 CJK 文本层，未能端到端坐实），但白名单缺口本身已实测。
**修法**：补 `zh`/`cn`/`zh-cn`/`zh-hans` 等常见写法。

### P2-8 `check_translation` 的 `%` 脱落与会计负号边界

`check_translation.py:211/214/228-238`。主审实测：

```
_numeric_diff("毛利率 92.5%", "Gross margin 92.5")   -> []          # % 被剥掉后等值，占比丢失不报（假绿）
_numeric_diff("金额 ( 1,234.56)", "Amount 1,234.56") -> []          # 括号与数字间有空格 → 丢负号（假绿）
_numeric_diff("金额 1,234.56-", "Amount 1,234.56")   -> []          # 尾随负号不在 token 内（假绿）
_numeric_diff("金额 (1,234.56 shares)", "Amount 1,234.56 shares") -> 报 -1234.56 缺失（假红）
```

`%` 与「紧贴括号一律当负号」都是 v0.5.38 修 P0-5 时引入的近似。**修法**：把 `%` 纳入角色键而非丢弃；
负号判据改为「左括号 + 中间只允许空白 + 右括号」的三元匹配。

### P2-9 CLI 缺文件时 exit code 与文档契约不一致（并抛 traceback）

`check_layout.py:524-536`：新增的 `fitz.open` 探测只在 `if pages:` 内。
主审实测 `main([缺源文件, 有译文])`（不带 `--page`）→ 未捕获 `pymupdf.FileNotFoundError`，
traceback 退出（与「有结构性问题」同码 1）；带 `--page` 才干净 exit 2；缺译文文件恒 traceback。
**修法**：把打开源/译文的探测提到 `if pages:` 之前并统一 catch → `sys.exit(2)`。

## 5. 测试与覆盖缺口

1. **真实 OCR 路径完全无覆盖**：所有图内文字测试都注入 `ocr_fn`，于是
   `_region_to_array` 的 `clip` 渲染 → `_ocr_results_from_img` → 区域相对框 **+ `rect.x0/y0` 平移**
   （`pdfio.py:2662-2669`）这条最脆的链（设计文档 §4.2 反复强调「帧必须先实测」）从未被执行。
   建议 monkeypatch `pdfio._get_ocr_engine` 返回假 engine（区域相对像素框），断言平移后的 PDF 框。
2. **双语 `save_interleaved_pdf` 的 in_image 分支**（`pdfio.py:5074-5080`）无测试。
3. **旋转页跳过图内文字**（`pdfio.py:2627-2630`）无测试。
4. **>50% 页图区**（P1-1）、**`char_count` 门槛**（P1-2）、**双语 `check_translation` 配对**（P0-1）均无测试。

| P0-2 OCR 框未校验 | 抽出 `_ocr_items_from_results`（逐条 try + `math.isfinite` + 计数上报），两路共用 | ✅ |
| P0-3 check_layout 旋转帧 | `frame_rect` / `to_render_frame`（cropbox 帧）；主审对拍 0/90/180/270 真实墨迹一致 | ✅ |
| P0-4 check_layout 漏画假红 | `_covers`（按 span 自身占比）+ `_credit_key`（每条译文只归一个源块，fail-closed） | ✅ |
| P0-5 check_translation 三处口径 | 扫描页仍查残留、按值比较、会计括号负数 / `%` 归一（后两条的边界见 P2-8） | ✅ |
| P0-6 check_layout 双语配对 / 越界页 | `interleaved` + `2i+1` 配对；`--page` 越界 exit 2 | ✅ |

## 7. 结论

- **1 条 P0**：`check_translation` 对双语产物整体假绿——这是本轮唯一「结论性错误」的工具缺陷，建议优先修。
- **3 条 P1**：两条来自新功能的「图区定义三处不一致」（0.95 / 0.5 / `char_count≥4`），直接影响
  「原图不破坏」这条产品红线；一条是 `check_layout` 对大下推的假红。
- P2 里 **P2-1（控制信号被吞）** 最值得顺手修：一行基类 + 一行 `except ControlSignal: raise`，却维护了仓库最重要的架构约定。
- 建议顺序：**P0-1 → P1-1 → P1-2 → P2-1 → P1-3 → P2-2/5/6/7/8/9 → P2-3/4 → P3 → 覆盖缺口 1/2/3/4**。
