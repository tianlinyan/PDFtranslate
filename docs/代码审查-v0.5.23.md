### P0-1 `run_translate` 把 requirement 里「提到」的页号当成整篇范围 → 只翻那一页
`translate_app/chat_tools.py:516`（配合 `agent/user_flows.py:140`、`agent/flow.py:1837`）

```python
page_scope = _agent.compile_from_user(str(requirement or ""), default_base="translate_page").scope
```

规则解析器 `_SCOPE_SINGLE_RE = r"第\s*(\d+)\s*页"` 只要句中**出现**「第 N 页」就产出 scope。
实测（本机复现）：

```
"帮我翻译整篇年报，第5页的图表保留原文"  -> scope=[4]   base=translate_page
"把第3页公司名翻成Bank"                -> scope=[2]
"开始翻译"                             -> scope=None
```

于是「开始翻译 + 对某页的附加要求」变成「只翻译第 5 页」：其余页全部原文导出，而工具仍返回
`ok=True`（`chat_tools.py:524`），AI 会回答「已开始翻译」。
对照 `run_flow`/`run_plan` 的既定纪律（**无模型时才允许规则解析**），这里闭包内其实**有** `llm` 槽填充可用。

**修法**：① 给 `run_translate` 的 schema 增加显式 `scope` 参数由 AI 填；② 或只在命中显式范围措辞
（「只翻/只翻译第 N 到 M 页」）时才设 scope；③ 至少改成 `compile_from_user(req, llm=llm)`。
`tests/test_chat_tools.py:448-454` 的 lambda 签名 `(req, _scope=None)` 丢弃了 scope 断言，补上。

### P0-2 旋转页（/Rotate 90/270）的双语 PDF：译文整段落到页外
`translate_app/pdfio.py:3465`

```python
page_rect = src[i].rect                      # 旋转后的可视矩形（400×200）
tpage = new_doc.new_page(width=page_rect.width, height=page_rect.height)
```

`Block` 坐标来自 `get_text("dict")`，位于**未旋转 mediabox** 帧（200×400）。实测（本机复现，
200×400 + `/Rotate 90`）：

```
block 'BOTTOM LABEL ROTATED' (20.0, 338.2, 160.0, 353.3)
out page 1 rect 400×200 rot 0 text 'TOP-LABEL-\nTRANSLATED'   ← y>200 的块译文整段消失
```

`save_ir(mode="bilingual_pdf")` 走同一路径。同文件的 `redraw_ocr` 分支（`pdfio.py:4083-4086`）
**已经**用「未旋转 mediabox + 沿用 `/Rotate`」修过同类问题，双语导出没落实。
`test_bilingual_pdf` / `test_bilingual_pdf_mirrors_block_positions` 只用未旋转页。

**修法**：`mb = src[i].mediabox` → `new_page(width=mb.width, height=mb.height)`；
`if src[i].rotation: tpage.set_rotation(int(src[i].rotation))`；补一条 `/Rotate 90` 回归。

### P0-3 `_check_layout` 的扁平索引恒为 0 → 用第 1 页的译文度量第 N 页的框
`translate_app/agent/flow.py:970`、`:976`、`:1005`

```python
offset = 0
for p in page_indices:          # page 为单个整数时 page_indices=[page]
    ...
    idx = offset + i            # 恒为页内局部索引
    t = _audit_read(state, idx) # 读的却是全文档扁平索引
    offset += len(blocks)       # 只有 page=None 才会在第二页前累加
```

同文件 `_audit_blocks`（`flow.py:838-848`）已经把 offset 算对了，另外四类检查都走它 —— 只有
layout 自己累加，单一来源被破坏。实测（本机复现，两页各 1 块，第 1 页译文超长）：

```
check_layout(page=0): [{'index': 0, 'kind': 'overflow', ...56.4pt > 12.0pt}]
check_layout(page=1): [{'index': 0, 'kind': 'overflow', ...56.4pt > 12.0pt}]   ← 应为 index=1
audit_page(state, 1, ['layout']): [{'check':'layout','index':0,...}]           ← 同样错
```

后果：① **假绿**——第 1 页块数少时 `t=""` 直接 `continue`，真溢出的页被判「干净页」跳过；
② **假红 + 改不动**——findings 里的 `index` 属于别页，模型 `set_text(page=N, index=0)` 会被
`_check_index_on_page` 拒绝，3 轮白跑。

**修法**：`offset = sum(len(src.pages[k]) for k in range(page_indices[0]))`（与 `_audit_blocks` 同源）；
补两页回归：`check_layout(1)["issues"][0]["index"] == 1`。

### P0-4 OCR 行带在密集行上被静默关闭 → 多行译文越过表格线（且验证脚本看不见）
`translate_app/pdfio.py:1865-1869`（配合 `_fit_block` `:3144-3147`）

```python
fit_height = 0.0
if next_top is not None:
    band = next_top - y0 - 1.5
    if band > y1 - y0:        # ← 行距 ≤ 字形框高时，行带被丢弃
        fit_height = band
```

`fit_height == 0` 的语义是「无行带/无界」（v5 版本注释、`_fit_block:3144-3147`），于是
`_fit_block` 在 6pt 处**无界换行**，绘制时顶对齐向下 → 压到下面几行的线/数字上。
这正好把 v5 要修的病（「v4 缓存 fit_height=0 → 换行无界、译文挂进下一行」）以另一种方式重新引入：
哨兵 `0` 同时表示「末行无需行带」和「行太窄给不出行带」。

**本机独立复现**（真机 `annual report - Mintai Commercial Bank 2025.pdf` p24-27，RapidOCR 实跑）：

| 页 | in_table 格 | `fit_height==0` | 其中非末行 | 推导行带 < 12pt（2 行 6pt 必越线） |
| --- | --- | --- | --- | --- |
| 24 | 123 | 73 | 72 | 72 |
| 25 | 192 | 95 | 94 | 94 |
| 26 | 275 | 213 | 212 | 211 |
| 27 | 234 | 161 | 160 | 160 |
| **合计** | **824** | **542 (66%)** | **538** | **537** |

**为什么长期没被发现**：`verify_real_run.py:111` 与 `check_band_fit.py:92` 都写成
`if b.fit_height > 0 and h > b.fit_height + 0.05` —— 被抑制的格根本不进统计，
CLAUDE.md 第 95 行「零行带越界」因此是**假绿**。

**修法**：① 用 `fit_height = -1`（或 `None`）表示「无下一行」，删掉 `band > y1 - y0` 门槛
（下一行顶可能 < y0，加 `max(0, …)` 保护）；② 注意真实行带只有 3–4pt 时 `_fit_band` 的下限
`_MIN_TABLE_FLOOR=3pt` 仍会越带，若要真正守住「不越线」，行带装不下 3pt 单行时**宁可保持单行横向溢出**；
③ 修两个验证脚本：按「推导行带」判定，而不是 `fit_height > 0`；
④ `tests/test_pdfio.py:821` 用的是 35pt 行距，永远走不到窄行分支，补 pitch≈字形高的用例。

### P0-5 `check_translation.py` 对**正确**译文报「致命」并 exit 1
`check_translation.py:39`（`_NUM_TOKEN_RE`）、`:138-168`（`_page_numbers`）

```python
_NUM_TOKEN_RE = re.compile(r"[+-]?[0-9][0-9,.，．]*[0-9%]|[+-]?[0-9]")
```

只认 ASCII 数字与 ASCII 负号，且**完全没有单位倍率**。本机实测：

```
'3.14 亿元'      -> {'3D14': 1}      '314 million yuan'          -> {}            equal=False
'1,234.56 万元'  -> {'1C234D56':1}   '12,345,600 yuan'           -> {'12C345C600'} equal=False
'总资产 １，２３４．５６ 万元' -> {}  'Total assets 1,234.56 …'    -> {'1C234D56'}   equal=False
'-1,234.56'      -> {'M1C234D56'}    '－1,234.56'（全角负号）      -> {'1C234D56'}   equal=False
```

而 `translate_app/eval.py:154-175` 复用的 `agent.flow._number_signature` 对同样两对判 **0 错误** ——
同一个「评估层」两套数字口径互相矛盾（`docs/0.3.8-eval-harness.md:117` §7 明确要求避免）。
`main()` 对这些误报返回 **1**（「数字不一致，请修正后重新导出」），`eval_harness --pdf-only`
（`eval_harness.py:39`）复用同一路径。CLAUDE.md 把「数字一致性发现即 exit 1」定为最致命一类 ——
对正确译文报致命会让人误改、并造成告警疲劳掩盖真实缺陷。

**修法**：让 `_page_numbers` 复用 `agent.flow._number_signature`；或至少补 ① 全角数字/标点/负号归一
② 亿/万 ↔ million/thousand 倍率归一，并补三条回归（全角源页、全角负号、单位换算）。

### P0-6 `_window_history` 裁剪后可能以 `tool` 消息开头 → OpenAI 400，整轮工具工作丢失
`translate_app/chat.py:257-273`

```python
msgs = msgs[-_CHAT_HISTORY_CAP:]                  # 32
while msgs and msgs[0].get("role") != "user":
    msgs = msgs[1:]
if not msgs:                                      # 窗口里没有 user → 回退裸尾部
    msgs = self.history[-_CHAT_HISTORY_CAP:]
```

一轮内模型连续调工具时，`user` 消息会被切掉，回退分支返回的窗口**以 `tool` 开头**。
本机实测（8 轮 × 3 工具调用 = 34 条 > cap 32）：

```
history len: 34 cap: 32 window len: 32
first roles: ['tool','tool','tool','assistant']
starts with tool: True
```

`tool` 消息没有紧邻其 `assistant(tool_calls)`，OpenAI 兼容端点直接 400；`ChatWorker.ask`
会把它转成侧栏「对话失败：BadRequestError…」，整轮工具工作全部丢失。
`chat.py:51-52` 的注释「always keeps one full tool loop intact」在 8 轮 × 并行调用下不成立。

**修法**：裁到「协议安全边界」——首条必须是 `user`，或必须是「assistant(tool_calls) + 其**全部** tool 响应」
的完整组；都不可行时只保留最后一轮 user。cap 至少 ≥ 8 ×(1+最大并行调用数)。

  `observe()` 不重放 result、`_result_for_message` 剥离 image、`_summarize_result` 截断 120 字符。
- **缓存**：翻译/OCR/prefs 三处都是临时文件 + `os.replace` 原子写；持久化仅环境变量激活；
  OCR 每页落盘；写失败只告警一次；加载时空译文条目被丢弃（自愈）；`_OCR_CACHE_VERSION` 进文件名。
- **数字原子性**：纯数字（`292,712,933,925.17`）在任何宽度都不被拆断；`_fit_band` 的二分不会越带
  （问题只在 `fit_height=0` 时根本不走 band）。
- **overlay**：键恒为 int；`set_overlay` 空文本/`delete` 一律 pop，条目整体替换（浅拷贝不会撕裂）；
  worker 端空白条目跳过 → 「绝不把块清空」成立。
- **OCR 坐标链**：RGB→BGR + `np.ascontiguousarray`（测试断言红色像素变 `(0,0,255)`）；
  旋转页 derotation 链与 `cropbox.height` 自洽；签名剔除早于网格重建；引擎缺失降级只告警一次。
- **`_fit_block` 的表格三分支**与 CLAUDE.md 逐条一致（单行 ≥6pt、多行 `_fit_exact_n`、
  `_fit_band` 0.01pt 网格二分），leading 与绘制侧同为 `_TABLE_CELL_READING`。
- **线程生命周期**：`stopped → deleteLater` + `worker_field`/`_live_worker` 的修复有效；
  `finished`/`error` 与 `_cleanup` 的投递顺序有保证（同一发送线程按序排队）。
- **测试**：679 全绿；无用例写真实 `~/.pdftranslate`；`split_translation` 4000 组随机输入零丢字/零空片段。
