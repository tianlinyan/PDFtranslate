## T-1（阻塞）测试是红的：测试读开发者 home 的 prefs.json

```
FAIL: test_the_figure_text_checkbox_is_wired_and_on_by_default (test_qt_wiring...)
AssertionError: False is not true : 图内文字默认开启
```

- 根因：`settings.APP_PREFS_PATH` 是模块级常量 `~/.pdftranslate/prefs.json`，
  `load_prefs()`(269) **没有任何环境变量覆盖点**；该测试构造真实 `MainWindow`，
  于是读到开发者保存的偏好。本机 `~/.pdftranslate/prefs.json` 里 `"image_text": false`
  → 断言必红。
- 影响：任何改过该偏好的机器 / CI 上 `unittest discover` 恒红，且会掩盖真实回归；
  同时违反本项目自己的铁律（CLAUDE.md：测试务必把状态重定向到临时目录）。
- 建议：`settings.py` 增加 `PDFTRANSLATE_PREFS_PATH`（或 `PDFTRANSLATE_HOME`）覆盖
  `APP_PREFS_PATH`，测试统一指到临时目录；短期可在测试里
  `unittest.mock.patch("translate_app.settings.load_prefs", lambda: {})`。
- 附带：GUI 测试的 `_persist_*` 也走真实路径，存在测试写脏开发者偏好文件的风险。

## P1-1 单块过高时，开扩页比不扩页**丢更多**内容（与特性目标相反）

场景：A4 单页、一个占满正文区（y 60..800 = 740pt）的正文块（提取器把整页并成一个块
很常见），译文按同字号自然排出的高度为块高的 R 倍。统计输出 PDF 中**可提取**字符
（画到页面可见区之外会被 PDF 裁掉 = 静默丢内容）：

| R（译文/原文高度） | 扩页关 | 扩页开 |
|---|---|---|
| 1.2（中英典型膨胀） | **100%** | 90% |
| 1.4 | **100%** | 78% |
| 2.0 | 86% | **55%** |

极端场景（整页中文→英文 6.5×）实测：关 81% / 开 52%。

- 根因：`_draw_overflow_pages`(6138) 把元素视为不可分单元——
  `if page is None or (y + need_head + h > limit and y > _MARGIN + 0.01)`，
  **新页的第一个元素无论多高都直接画**；`_flow_split`(6060) 也只在元素之间切，
  永不切分元素内部。超出 `limit = mediabox.height - _MARGIN` 的部分画到页外。
  而关闭扩页时 `_fit_block` 会缩字（正文下限 7pt）把内容留在纸上。
- 后果：用户勾选「译文扩页」以避免压缩/丢字，实际在长段落上**反而丢 10–45%**，
  且日志只报「已扩展到后续 1 页」，没有任何丢失告警。
- 建议（择一，推荐 ①+③）：
  1. 续页对 **prose 元素按行切分**：`_wrap` 出行后按续页剩余高度分段绘制，段末翻页
     （表格行仍保持不拆，符合「行不跨页」的既定语义）；
  2. 或对 `h > limit - _MARGIN` 的元素退回老路径（缩字 + 页底钳制）留在原页；
  3. 无论选哪种，`h` 超过一页可用高度时**必须记日志**告警「该块仍需压缩，已缩字」。
- 回归：`test_an_oversized_paragraph_continues_onto_the_next_page`
  断言「输出可提取字符数 == 译文非空白字符数」；再加
  `test_no_translation_is_drawn_outside_the_page`（对全部输出页断言
  `max(word.y1) <= page.rect.height + 0.5`，现有同名断言只覆盖装得下的元素）。

## P1-2 旋转页（/Rotate 90|270）+ 表格 + 扩页 → 文档爆炸，首页被搬空

实测（1 页源，400×200，`/Rotate 90`，7 行 3 列表格）：

| | 页数 | 首页词数 | 全文词数 |
|---|---|---|---|
| 扩页关 | 1 | 82 | 82 |
| 扩页开 | **8** | 5 | 82 |

日志：`第 1 页译文放不下，已扩展到后续 7 页。`

帧不一致的直接证据：

```
块坐标（未旋转帧）      项目 (62,41)-(76,49) …
_extract_tables（显示帧） bbox y 60..340，行顶 60/150/245
_map_blocks_to_table_cells 命中 2/6
_flow_split limit = page.cropbox.height - 2 = 198   → 7/7 元素「溢出」
```

- 根因：`find_tables` 在**旋转后的显示帧**返回表格几何，而块坐标与拆分上限在
  **未旋转帧**（CLAUDE.md 明确块坐标为未旋转 cropbox 帧）。非扩页路径由
  `page_height=page.cropbox.height` 的页底钳制把症状压成「行被压扁」，扩页把它
  放大成「整页搬走 + 页数 ×8」。
- 建议（择一）：
  1. 保守：`expand_here = expand_pages and not ocr_table and not rotated`
     （与 `_flow_skips`/`_ink_bands` 对旋转页一贯的保守态度一致），并记一行日志；
  2. 彻底：`_extract_tables` 的行/列几何经 `_rot_map_rect(..., inverse=True)`
     映回未旋转帧——顺带修好「表格只命中 2/6 块」这个扩页之前就存在的问题。
- 回归：`test_expand_pages_on_a_rotated_page_does_not_inflate_the_document`
  （断言 `page_count <= 2`）+ 断言 `_map_blocks_to_table_cells` 在旋转页上命中全部
  表格单元格。

## P2-1 导出后体检脚本不认识扩页产物 → 满屏假「致命」

3 页源、每页扩 1 页 → 输出 6 页，`page_map=[0, 2, 4]`：

```
$ python check_translation.py src.pdf exp1.pdf --lang English
[致命] 数字不一致 — 第 1 页: 原文 4 次「1234.56」在译文中缺失
[致命] 数字不一致 — 第 2 页: …
[致命] 数字不一致 — 第 3 页: …
$ python check_layout.py src.pdf exp1.pdf
[漏画] 第 3 页：源块 (62.0,22.0)-(148.0,30.4) 附近没有译文 —— 「项目」
…（数十条）
```

同一份译文**未扩页**导出：两个脚本都「体检通过：未发现问题」。

- 根因：`check_translation.py`(456-465) 与 `check_layout.py`(378-382) 只认交错产物
  的 `ti = 2*i+1`，其余一律 `ti = i`；扩页后从第一个溢出页起全部错位配对。
- 影响：文档把这两个脚本写成「导出后必查」，用户开扩页后会被假「致命」引导去改本来
  正确的译文；比不误报更糟的是**真问题被淹没在假阳性里**。
- 建议：导出时随文件写一份 sidecar（如 `输出.pdf.pagemap.json`：`{源页: 输出页}`），
  两个体检脚本优先读它配对；同时把「译文页数 > 原文页数」从静默改为显式提示
  「检测到译文扩页，已按映射配对 / 未能配对请检查」。
- 回归：`tests/test_check_translation.py` 增加「扩页产物 + sidecar → 0 报」与
  「无 sidecar 时至少不误报为致命」两例。

## P2-2 预览看不到续页，用户无法确认搬走的内容

`_translation_output_page`(main_window:912) 只做「源页 → **首个**输出页」；预览翻页
（`_on_preview_page_changed`/`parse_preview_command`）以**源页号**为单位。扩页后源页 i
的后继页 i+1…在「译文」侧没有任何入口——用户勾了扩页，却看不到扩出来的内容，只能去
文件管理器打开 PDF。

- 建议：预览标签显示「译文 第 i 页（本段 1/3）」，同一源页内允许继续翻；或让翻页
  以输出页为单位并用 `page_map` 反查源页（原文侧仍按源页号）。

## P3（次要，建议一并处理）

1. **文档与实现不一致**：CLAUDE.md/CHANGELOG 写「`_flow_skips` 把 `ocr`/`is_chart`/
   `in_image`/**保留块**排除」，实际 `_flow_skips`(5959) 不看 `keep_original`。
   后果：被标「保留原文」且有文本层的公式/签名会被红action，再在续页用正文字体重排
   （外观改变、脱离上下文）。要么补上排除，要么改文档。
2. **页底基准两套**：拆分用 `page.cropbox.height - _TABLE_BOTTOM_MARGIN`(6471)，
   续页尺寸/上限用 `src_page.mediabox.height - _MARGIN`(6153)。CropBox≠MediaBox
   （扫描书常见）时续页可见尺寸与源页不一致，内容可落在源页可见区之外。统一取
   cropbox，并在 `new_page` 后 `set_cropbox`。
3. **环境变量强制开时界面仍显示「关」**：`PDFTRANSLATE_EXPAND_PAGES=1` 只作用于
   worker，勾选框初值仍取 prefs(main_window:396)。建议按生效值刷新勾选框（或禁用并
   tooltip「已由环境变量强制开启」）。
4. **docstring 误导**：`save_translated_pdf` 称「没搬走任何页时返回 `None`」，实际恒
   返回列表（worker 用 `page_map or None` 兜住）。
5. **无关改动混入库**：`models.json` 本地端点 `192.168.0.101 → 192.168.0.19` 与本
   版本无关，是本机开发配置。建议 gitignore 或改 `${PDFTRANSLATE_LOCAL_*}` 占位符。

## 结论

`expand_pages` 的架构选择（`_flow_*` 只做「元素级」搬运、不动绘制内核、默认关闭）是
对的，默认关闭时与旧版逐字一致这点也成立。但**开启后**存在两个必须先修的问题：
P1-1 让它在典型长段落上比不扩页丢更多内容（特性目标反转），P1-2 让旋转页文档膨胀
8 倍。此外 T-1 使测试套件在当前机器上为红，应最先处理——它是「绿灯可信」的前提。
