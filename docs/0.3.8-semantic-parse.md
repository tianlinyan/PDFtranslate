# 0.3.8 语义化解析层细化方案：给 AI 一份「看得懂结构」的文档模型

> 版本：v0.3.8（草案）　　状态：待定稿　　上一篇：`0.3.8-方向设计.md`（档位 B-④）
>
> 对应方向档位：**B-④ 语义化解析层**。本文把「引入可选文档解析后端，把 PDF 还原成有语义的结构模型，并映射回现有扁平 block 列表」细化成可落地、可测试、可回退的方案。**原则：语义结构是给 agent/提示词的「元数据」，它增强而非替代确定性几何管线；默认关闭，纯几何路径仍是兜底，绝不改变现有导出的确定性行为。**

---

## 1. 一句话目标

在不破坏现有「几何块 + OCR + 逐块翻译回填」主路径的前提下，新增一个**可选**的结构理解后端，产出一份**带语义的文档模型**（标题层级 / 段落 / 语义表格 / 图 / 公式 / 栏与页），融合进现有 `DocumentText` / `Block`，让 `classify_page` / `get_doc_info` / `read_page` 和 agent 真正「看懂结构」，并为此后的 **C-⑥ IR 重排版** 打地基。

---

## 2. 问题与设计边界

### 2.1 现状
`extract_document_text` 用 `page.get_text("dict")` 的 span/行收集器产出 `Block`（含 bbox / 字号 / 对齐 / 粗体 / `in_table` / `fit_width` / `fit_height` 等几何与版式提示），`classify_page` 靠 `Block.ocr` / `_is_vertical_label` 分型。**它拿到的是一堆「摆在哪儿」的块，而不是「这是什么」的结构**——分栏标题、跨页语义表格、公式、图注、标题层级对管线是黑盒。

### 2.2 设计边界（铁律）
1. **语义是元数据，不改几何**：`kind`/`level`/`table_ref`/`tables` 只供 agent、提示词、`classify_page`/`get_doc_info`/`read_page` 读取，**不参与**导出的确定性绘制（导出仍按 bbox/版式提示走，与无解析时逐位一致）。
2. **默认关闭、可回退**：纯几何路径不变；后端未安装 / 该页解析失败 → 该页回落几何（log 告警一次），整体行为与现在一致。
3. **可选依赖**：解析后端为可选依赖（ONNX / VLM），不装则不加压力；经 `models.json` 或 `PDFTRANSLATE_STRUCTURE_PARSER` 环境变量门控（与现有缓存/流程的 env 门控风格一致）。
4. **先绑定后暴露**：新加的 `kind`/`structure` 字段必须先被 `make_source_tools`/`make_page_executors` 真正读取（见 §4 消费点），否则绝不暴露给模型——避免「声明了却用不了」。

---

## 3. 后端选型（接口可插拔，先落地一个）

| 后端 | 产出 | 依赖 | 适配 | 结论 |
|---|---|---|---|---|
| **DocLayout-YOLO（ONNX）** | 版面区域框 + 类别（title/text/table/figure/formula） | 单 ONNX，本地/离线，轻量 | 与现有「提取文本 + 区域框标注」最贴合 | **首选**（pdf2zh 同款，低于 docling 依赖体积） |
| Docling | 语义 token 流 + 表结构 + 阅读序 | 较重（ML 模型、可能需 HF 下载/GPU） | 结构/表格最强，但依赖重 | 备选（表格/阅读序增强时用） |
| MinerU / Marker | 结构 + 公式 + 表格 | 重（VLM 类） | 公式最强，但最重 | 远期（公式场景，见 B-⑤） |

> **建议**：接口定义为 `StructureParser`（可注入的 `structure_fn`，镜像现有 `ocr_fn` 测试缝），**第一步接 DocLayout-YOLO ONNX**（区域框 + 类别，产出最直接、依赖最轻），把「表格结构模型」「公式/图保护」放到第二/三步。后端选择是未决问题（见 §7）。

## 4. 数据模型与管线落点

### 4.1 `Block` 新增语义字段（不改现有字段语义）

```python
#: 语义类别（给 agent/提示词读，不改导出几何）。
kind: str = "text"        # text / heading / table / figure / formula / caption / note
level: int = 0            # 标题层级（1..6）；0 = 非标题
table_ref: int = 0        # 指向本页 tables 列表的索引；0 = 不在语义表格内
#: 块是否「结构保真、不改写」：figure/formula 区域内的文字是结构而非散文。
structure_protect: bool = False
```

`Block` 现有字段（`in_table`/`fit_width`/`fit_height`/`ocr`/`is_chart` 等）**原样保留**——它们才是导出器读的几何/版式提示，语义字段与之正交。

### 4.2 新增 `Table` 与 `PageStructure`

```python
@dataclass
class StructTable:
    rows: int
    cols: int
    bbox: tuple[float, float, float, float]
    cells: list[list[int]]        # 语义表格 [row][col] → 扁平块索引（0=空）
    block_ref: set[int]           # 属于该表的块索引集合

@dataclass
class PageStructure:
    page: int
    parser: str                   # 后端名；"" = 无（几何路径）
    elements: list[dict]          # [{"kind","bbox","level","block_indices"}]，阅读序
    tables: list[StructTable]     # 该页语义表格（可为空）
```

`DocumentText` 追加 `page_structure: list[PageStructure]`（与 `pages` 对齐，长度＝页数，缺省全 `PageStructure(parser="")`）与 `structure_parser: str`（后端名 / ""）。

### 4.3 管线钩子

新增 `extract_structured(...)`（或给 `extract_document_text` 加可选 `structure_fn=` 参数，镜像现有 `ocr_fn` 注入缝）：

```python
def extract_structured(path, *, structure_fn=None, ocr=False, ...) -> DocumentText:
    dt = extract_document_text(path, ocr=ocr, ...)          # 先走现有几何/OCR
    if structure_fn is None:
        return dt                                           # 默认：几何路径，行为不变
    # 逐页跑 structure_fn(page) -> PageStructure；失败/无区域 → 该页 PageStructure("")
    _fuse_structure(dt, structures)                          # 标注 kind/level/table_ref + 建 tables
    return dt
```

`_fuse_structure` 是所有后端都复用的**融合器**：把 `structure_fn` 产出的区域框（含类别/层级）与现有 `Block` 的 bbox 做**重叠/邻近匹配**，给 `Block` 打上 `kind`/`level`/`table_ref`/`structure_protect`；按区域类别组装 `PageStructure.elements` 与 `StructTable`。后端只产出「区域+类别+可选表格网格」，**不重建块**——块的 bbox/版式仍来自几何管线（保证导出逐位一致）。

> 这一步与 `_reconstruct_ocr_grid` / `_order_generic` 是**并行**的：融合器只做语义标注，不碰块排序与导出几何。

### 4.4 消费点（先绑定后暴露，缺一不可）

| 消费点 | 读取 | 变化 |
|---|---|---|
| `pdfio.classify_page` | `kind` | `formula`/`figure` 多 → 新分型 `formula`/`figure`（可进 special_pages 协商） |
| `pdfio.get_doc_info` | `kind`/`structure_parser` | 返回新增 `formula_pages`/`figure_pages`/`parser` |
| `agent.tools.read_page` | `kind`/`level`/`table_ref` | 每块 JSON 附语义字段 |
| `agent.tools.classify_page` | `kind` | 分型结果含 `formula`/`figure` |
| `prompts.agent_tool_policy` / `page_task` | `kind`/`level` | 引导模型「标题/段落/表格/公式/图」分别处理 |
| `agent.flow._check_*` / `audit_page` | `structure_protect` | 结构与审计的统一受保护门增补 `structure_protect` |

## 5. 安全 / 门槛

- **可选依赖**：`structure_fn` 未注入或后端未装 → 直接返回 `extract_document_text` 现状，`get_doc_info` 的 `parser` 记 `""`，**零行为差异**（保证所有现有测试绿）。
- **逐页容错**：单页解析失败 → 该页 `PageStructure(parser="")`，`log` 报原因（不静默），其余页照常。
- **受保护块**：`figure`/`formula` 区域内的块 `structure_protect=True`，翻译/审计/改写统一跳过（沿用 `_protected` 门，并入 `_audit_protected`），避免把「结构」当「散文」改坏。
- **不改导出**：语义字段不进入 `_draw_translated_block`/`_fit_block`/`save_*` 的判定；解析开/关时同一份译文导出必须**逐位一致**。

## 6. 分阶段实施计划

| 阶段 | 内容 | 验证 | 状态 |
|---|---|---|---|
| **1** | `Block`/`StructTable`/`PageStructure`/`DocumentText` 语义字段 + `extract_structured` 骨架 + `_fuse_structure` 融合器（后端可 mock） | `test_pdfio`：注入 `structure_fn` 后 `kind`/`level`/`table_ref` 正确、`tables` 组装；未注入/单页失败回落几何；**开/关导出逐位一致** | ⬜ 未启动 |
| **2** | 接 DocLayout-YOLO ONNX 后端（`structure_fn` 实现：区域框+类别） | `test_pdfio`（mock 后端）+ 真机样例：`classify_page` 新分型、`get_doc_info` 计数 | ⬜ 未启动 |
| **3** | 语义表格模型：表格网格 → `table_ref` + `get_layout` 升级 + `StructTable` | `test_pdfio`：语义表格与 `check_table`/`get_layout` 一致 | ⬜ 未启动 |
| **4** | `figure`/`formula` 保护 + `structure_protect` 并入受保护门 + special_pages 新分型协商 | `test_agent`：公式/图块不被改写；audit 跳过 | ⬜ 未启动 |

> **建议**：**1 + 2 为最小可用**（语义元数据落地 + 后端可用 + 消费点打通），先做；**3**（表格模型）是 C-⑥ IR 的伏笔，**4**（公式/图保护）与 B-⑤ 直接协同。每阶段都以 A-② 的评估 harness 度量「是否引入或消除了版面/数字回归」。

## 7. 未决问题

- **后端依赖体积**：DocLayout-YOLO ONNX 是否足够（本地、离线、低依赖）？还是需要 Docling 的强表格/阅读序？决定在 **1** 前拍板。
- **语义表格 vs 现有 `in_table`/`fit_height` 几何**：`StructTable` 的语义网格与现有 OCR 表格重建 / 文本层表格的几何**如何对齐**——语义表格用于「理解/读/negotiate」，几何仍用于「写/排版」，二者是同一张表的两面，需明确映射，避免 `check_table` 双口径。
- **`formula`/`figure` 分型与 M3 特殊页协商**：新增分型要进 `special_page_question` 的选项映射（translate/keep/skip），提示词与 `make_llm_interpret` 需同步；是否先保守（`figure` 保守保留，`formula` 保守占位），再逐步放开。
- **`structure_protect` 与现有 `_protected` 粒度**：并入哪种粒度（块级 vs 区域级）？区域级可能保护了公式周围的 caption，需按区域类别细粒度决定。
- **性能**：文档级解析后端在**大文档**（数百页）上的耗时/显存；是否按页懒加载（先解析已进入的页）而非整篇解析。
- **GUI 入口**：主窗口是否暴露解析后端选择？倾向**不暴露**（与 OCR/AI 开关一致，从主窗口移除、交给 `models.json`/env 门控），但需在 `models.json` 补 `structure_parser` 键说明。
