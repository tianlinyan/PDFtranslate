# 处理路径梳理与审查（v0.5.25）

> **范围**：`translate_app/pdfio.py` 的四条处理路径——**普通（文本层）表格**、**OCR 页（扫描页）**、
> **OCR 表格（扫描表格）**、**文本与图片混排**——以及它们在两条导出路径
> （`save_translated_pdf` 原位 / `save_interleaved_pdf` 双语）中的落点。
>
> **方法**：通读代码 + 合成 PDF 探针（每条结论都在本机 PyMuPDF 1.28.2 上复现过；
> 探针脚本只写系统临时目录）+ 三个并行子代理的独立审查。子代理的结论**逐条回读代码并复现**，
> 未复现的降级为「未验证」单列在 §5（例如「内联图像页不被 OCR」——我的探针没能构造出内联图像，
> 既未证实也未推翻）。
>
> **不在范围内**：翻译协议与缓存语义（见 `docs/代码审查-v0.5.23.md`）、agent 编排、聊天工具层。

## 0. 结论摘要

**可靠的部分**：有框线的文本层表格（`find_tables` → 单元格成块 → 行高扩展 → 网格重画）、
扫描表格的「至少一整列数字」守卫、稀疏文本层「并入」、原位导出的图片保真（红action 保留图片与线稿）、
OCR 网格的 `fit_width`/`fit_height` 行带机制、v0.5.25 的纯页判定 + 页面家具。

**三个必须优先处理的缺陷**（都会**静默**破坏输出）：

1. **矢量图表被误判成表格 → 图表内容被删除**（P0-1）。`find_tables` 只看框线，一个「有网格线 +
   单元格里有文字」的图表会被当成表格，第二遍红action 随后删掉图表本体（实测柱状图整根消失）。
2. **多行单元格的译文互相覆盖**（P0-2）。一个单元格的两行源文本被拆成两个块，导出时**都锚定到行顶**，
   译文重叠绘制（实测同一位置画出两份相同文本）。
3. **表格行高扩展没有页底约束**（P0-3）。靠近页底的表格（或表格下方的正文）被推到页面之外，
   文字与表格线落在 mediabox 之外，任何阅读器都看不到，且源文本已被擦除。

另有 10 条 P1（含无框线表格识别不到、扫描页「表格+正文」被整体网格化、OCR 白底盖住照片、
会计负数金额不修复、纯符号单元格被删、页底合法文本被当成手写签字、双语译文页无图等）与 16 条 P2。

## 1. 四条处理路径

### 1.1 判定与分派总表

| 页面形态 | `classify_page` | 是否 OCR | 表格判定 | 导出形态 |
| --- | --- | --- | --- | --- |
| 文本层正文页 | `normal` | 否（`lines > 3`） | 否 | 原位覆盖 |
| 文本层表格页（有框线） | `normal` | 否 | `find_tables()` → 行高扩展 + 列重排 | 原位覆盖 + 重画表格线 |
| 文本层表格页（**无框线**） | `normal` | 否 | **✗ 识别不到** | 列向合并块（P1-1） |
| 文本层**图表**页（网格+文字） | `normal` | 否 | **✗ 误判为表格** | 图表被删、重画黑网格（P0-1） |
| 扫描页（无文本层） | `scan` | 是 | OCR 框 → 数字列判据 → 网格 | 原位覆盖（白底矩形）/ `redraw_ocr` 重绘 |
| 扫描页 + 稀疏文本层（≤3 行） | `uncertain` | 是（**并入**） | 同上 | 同上（家具块由 `_draw_page_furniture` 补画） |
| 图表页（竖排节点 ≥3） | `chart` | 可能 | 否（`is_chart` 恒为 False，见 P2-1） | 原位：竖排重绘译文 |
| 图文混排（正文 + 图） | `normal` | 否 | 视框线 | 原位覆盖，图片/矢量保留 |
| 纯图片页（照片、无文字层） | `scan`/`uncertain` | 是 | 一般否 | 原位覆盖（照片上文字被盖白底，P1-3） |

### 1.2 普通（文本层）表格

- **入口**：`extract_document_text`（`pdfio.py:1050`）先 `_detect_table_cell_rects(page)` 取
  `find_tables()` 的单元格矩形，把行分成 `table_lines` / `text_lines`；表格行不进散文合并
  （否则行间会被并成一段），由 `_build_table_blocks` **逐视觉行**成块（`in_table=True`，
  bbox 放宽到整格并内缩 `_TABLE_CELL_PAD`，数字格 `align="right"`，其余 `center`）。
- **导出**：`save_translated_pdf`（`pdfio.py:4347`）在输出页上再跑一次 `_extract_tables`
  → `_map_blocks_to_table_cells` 建立 `block → (table, row, col)` 映射 → `_compute_table_layout`
  按译文实测高度把每行**向下推挤**并重画表格线 → `reflow=True` 时 `_rebalance_table_columns`
  在列之间借还宽度（数字列不缩，总宽不变）。
- **竖向空间**：文本层表格**不用行带**（`fit_height=0`），靠行高扩展吸收换行——这是与
  OCR 表格最关键的分工（扫描件的表格线钉死在位图上，不能推）。
- **边界**：无框线表格、多行单元格、图表误判、页底越界——见 §2。

### 1.3 OCR 页（扫描页）

- **触发**（`pdfio.py:970-972`）：`ocr=True` 且 `(not lines or len(lines) <= 3)` 且
  `_needs_ocr(page)`（有图片或矢量图形）。**已有完整文本层的页面永不走 OCR**。
- **执行**：`_page_to_array` 按 `_OCR_DPI=300` 渲染（RGB→BGR），必要时估斜/纠斜，RapidOCR 识别
  → `_synthesize_ocr_blocks`：清控制字符 → **数字归一化**（`_normalize_number`，逐条记日志）
  → **手写签字剔除**（`_drop_signature_items`）→ 尝试网格重建 → 失败则按阅读序生成普通 OCR 块。
- **稀疏文本层**：≤3 行时 OCR 结果**并入**而非替换（`_merge_ocr_blocks`），并记日志。
- **失败**：单页异常 → 该页降级为空 + `log` 报出原因；取消信号原样上抛。
- **导出**：`ocr=True` 的块不红action，而是**先画不透明白色矩形盖住扫描字再画译文**（`pdfio.py:4456`）。

### 1.4 OCR 表格（扫描表格）

- **网格重建**（`_reconstruct_ocr_grid`，`pdfio.py:1750`）：行按 y 聚类（`ytol=4.5`）、列按 x 重叠聚类，
  **守卫是「至少一整列数字」**。通过后每格成为 `Block(in_table=True, ocr=True)`，写入
  `fit_width`（可用到行内空白）与 `fit_height`（行带）。
- **导出（不勾选）**：`_reconstruct_ocr_tables`（`:3599`）用同一判据在导出期再推一次网格 →
  `ocr_table=True` → **跳过行高扩展**，靠行带换行 + 缩字。
- **导出（勾选「OCR表格重建为矢量表格」）**：`_is_pure_ocr_table_page` 判定可整页重绘
  （全部块可重绘，或位于表格 bbox 之外的**页面家具**），先尝试 AI 整表重建
  （`_draw_ai_table`），失败回退 `_draw_ocr_grid_page` 几何重绘，家具由
  `_draw_page_furniture` 补画。扫描底图/印章/手写签字按设计丢弃（但无提示，见 P2-4）。
- **边界**：表格与正文混排、密集行合并、会计负数、符号单元格——见 §2。

### 1.5 文本与图片混排

- **原位**：红action 时 `PDF_REDACT_IMAGE_NONE` / `PDF_REDACT_LINE_ART_NONE`（`:4399`）——
  图片与线稿全部保留，只擦文本（实测：含图片页 `images=1`、含矢量矩形页 `drawings=1`）；
  表格区域再单独做一次 `REMOVE_IF_TOUCHED` 擦掉旧表格线（`:4403-4412`）——**这一遍的副作用是 P0-1/P2-5**。
- **双语**：原文页整页插入，译文页是 `new_page` + 仅文字（`:3580-3591`）→ P1-10。
- **图表**：竖排标签走 `_draw_vertical_label`（旋转 90° 绘制）→ 帧与方向问题见 P2-2/P2-3。
- **竖排标签**：过长时按列宽缩字号并钳制在页内。

#### P0-1 矢量图表被误判为表格 → 图表内容被删除

> **v0.5.26 已修**：新增 `_table_has_chart_art(page, bbox)` + `_fill_looks_like_a_bar`，

> 回归 `ChartNotATableTest`（含端到端「柱体像素仍为 (51,102,204)」）。

**触发条件**：`find_tables()` 默认 `strategy="lines"`，只看框线；**网格线 + 单元格内有文字**的
图表会被判成表格。实测（4 个探针变体）：

| 变体 | 构造 | `find_tables` |
| --- | --- | --- |
| A | 外框 + 满网格，无文字 | `[]` |
| B | 外框 + 满网格 + **每格一个文字** | **4 行 × 5 列** |
| C | 柱状图 + 满网格 + 网格下方轴标签 | `[]` |
| E | B + 网格内 3 根彩色柱 | **4 行 × 6 列** |

变体 E 端到端导出后：柱体中心像素 `(51,102,204)` → **`(255,255,255)`**，`get_drawings()`
11 → 16（只剩新画的黑网格线），20 个文字块全部 `in_table=True` 被重新排成表格。
注释 `pdfio.py:4337-4338`「a vector chart (org chart etc.) is never mistaken for a table」
是**错的**。

**修法**：检测到的「表格」在跑第二遍红action 前做一次可信度校验——例如要求
① bbox 内没有「填充型」绘图（`get_drawings()` 里 `fill` 非空的项，柱体/色块都属此类），
② 或要求每行至少一个文本块（`_map_blocks_to_table_cells` 覆盖多数行）；
不满足则**放弃表格处理**（走原位覆盖）并记一条日志。

**后果**：一个单元格的两行源文本变成两个块，`_map_blocks_to_table_cells` 把两块映射到**同一个**
`(table, row, col)`；只要译文换成多行，两块都会被替换成**同一行框**，从同一 `y0` 开始绘制。
实测（1 行 × 2 列框线表，左格两行「非经常性/损益项目」，译文用长英文）：

```
blocks: [('1,234', 108.3, True), ('非经常性', 109.0, True), ('损益项目', 123.0, True)]
drawn y0=100.0 x0=73.8 'Non-recurring profit and loss items of the'
drawn y0=106.0 x0=107.8 'reporting period'
drawn y0=100.0 x0=73.8 'Non-recurring profit and loss items of the'   ← 与上一组完全重合
drawn y0=106.0 x0=107.8 'reporting period'
```

**修法**：提取期把同一视觉单元格的多个行块**合并为一个块**（文本用 `\n` 连接、
`single_line=False`），让 `_fit_block` 走 `n_lines >= 2` 的 `_fit_exact_n` 路径、只产生一个绘制框；
或绘制期按 `b.y0 - row_top` 给每块偏移锚点。

## 3. 已验证为正确的设计（勿误改）

- **OCR 不碰有文本层的页面**（`:970-972`）：`lines > 3` 直接跳过，内嵌图片不会误触发。
- **「至少一整列数字」判据**（`_reconstruct_ocr_grid:1787`、`_reconstruct_ocr_tables:3623` 同源）：
  挡住扫描散文页被误判为表格（红action/重绘丢底图的最后一道闸）。
- **稀疏文本层「并入」而非「替换」**：标题/封面文字不再丢失（去重判据的副作用见 P1-4）。
- **文本层表格用行高扩展、扫描表格用行带**（`:4370-4377`）：分工正确。
- **红action 两遍法**（`:4399` 保线稿 / `:4409` 只删表格区线稿）：第一遍若用 `REMOVE_IF_TOUCHED`
  会连框线/下划线一起删（历史回归），当前写法正确（范围过大的副作用见 P0-1/P2-5）。
- **纯页判定 + 页面家具**（v0.5.25）：放行与补画成对出现，不静默丢块。
- **图片保真**：原位导出图片与矢量线稿均保留（探针 `images=1` / `drawings=1`）。
- **数字永不送模型**：`translator._needs_translation` 要求含字母，文本层与 OCR 单元格一致
  （例外：带单位/币种的金额如 `1,234.56万元` 含 CJK，会被送去翻译——见 P2 备忘）。
- **OCR 数字归一化不改数字序列**（`:1196-1204`）：无法验证的字符串原样保留；
  `1,234` 与 `1.234` 的二义性属已知限制。
