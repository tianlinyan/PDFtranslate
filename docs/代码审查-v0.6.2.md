## 1. P1 — 应修

### P1-1 `page_scope` 只在 agent 路径生效 → IR / 确定性路径整篇翻译（默认 `run.bat` 走 IR），日志却谎报「只翻第 N 页」

`translate_app/worker.py:135` 把 `page_scope` 存进 `self._page_scope`：

```python
self._page_scope: list[int] | None = list(page_scope) if page_scope else None
```

全仓只有**一处**消费它——`worker.py:738`，传给 agent 的 `DocumentSession`：

```python
result = agent_mod.DocumentSession(
    ...,
    scope=self._page_scope,
)
```

而生产路径由 `worker.py:263` 分发：

```python
if self._ir_mode:                       # ← run.bat 设了 PDFTRANSLATE_IR_MODE=1，恒真
    result = self._run_ir(doc, engine)  #    :484 只消费 released，不认 page_scope
elif self._agent_mode and vision:
    result = self._run_agent(doc, keep_original)   # ← 唯一认 scope 的分支（:738）
else:
    ...                                 # :283-295 确定性批次，全文翻译
    result = engine.translate_blocks(doc.blocks, ...)
```

`grep -n "page_scope" translate_app/worker.py translate_app/ir.py` 只有 `:135` 与 `:738` 两行；`_extract_doc` 也不按页过滤。也就是说：

* **IR 路径**（`run.bat` 默认、GUI 勾选「IR 文档级管线」）：`page_scope` 被丢弃，整篇翻译；
* **确定性回退路径**（无视觉模型、未开 IR）：同样整篇翻译；
* 只有 **agent 视觉路径**在 `agent/flow.py:1915` 过滤 `i in self.scope`。

而 `chat_tools.py:547-552` 在启动前刚用模型解析出页范围并**如实打日志**：

```python
page_scope, ai_reason = _agent.ai_scope(str(requirement or ""), llm)
...
log(f"  [编排] AI 理解为只翻第 {pages} 页" + (f"（{ai_reason}）" if ai_reason else "") + "。")
```

于是用户说「只翻第 2、3 页」、日志也确认「只翻第 2、3 页」，实际却翻完整本——时间/费用与预期不符，且**用户没有任何信号**。

**主审复现**（2 页样本 + 本地 mock，`page_scope=[1]`＝只翻第 2 页）：

```python
# IR 路径（run.bat 默认）
os.environ["PDFTRANSLATE_IR_MODE"] = "1"
w = TranslateWorker(src, model, "Chinese", "plain_text", out,
                    agent_mode=True, ir_mode=True, page_scope=[1],
                    policy_fn=lambda c, **k: ({}, ""))
w.run()
```

输出（**第 1 页也被翻译**）：

```
===== Page 1 =====
MOCK:Page 1 heading text.
 This is a sample body paragraph to translate.
...
===== Page 2 =====
MOCK:Page 2 heading text.
...
```

去掉 `PDFTRANSLATE_IR_MODE`、`ir_mode=False` 复跑确定性路径，结果相同。

**回归缺口**：`grep -rn "page_scope" tests/` 只命中 `test_user_flows.py`（`FlowSpec` 层面），**没有任何测试把 `page_scope` 传进 `TranslateWorker` 或 `DocumentSession`**。这是该缺陷能穿过 856 个测试的直接原因。

**修法建议**：
1. 在 `run()` 分发前把不在范围内的页从待译块列表里剔除（IR/确定性路径按 `doc.block_pages` 过滤），或让 `_run_ir` 接收 `page_scope` 并只对范围内页送译、其余页原样保留；
2. 若一时不做，至少在 `_ir_mode` / 确定性分支**记一条日志**「页范围仅在 AI 视觉编排下生效」，不要与上面那条「只翻第 N 页」并排出现；
3. 补 worker 级回归：`page_scope=[1]` 时第 1 页输出必须等于原文（两条路径各一例）。

### P1-2 `in_image` 图内文字被当作歧义「ocr」块交给内容策略 → 模型 `keep` 即静默不译

`translate_app/policy.py:104-106`：

```python
if role == "figure" and not in_image:
    kind, default_keep = "figure", True
elif bool(getattr(b, "ocr", False)) and not getattr(b, "keep_original", False):
    kind, default_keep = "ocr", False      # ← 没有排除 in_image
else:
    continue
```

生产里，「有文本层页面上的图内文字」由 `pdfio._ocr_plain_blocks`（`pdfio.py:3251` `ocr=True`）生成、再经 `_image_text_blocks` `replace(in_image=True, ...)`，因此块上**同时**带 `ocr=True` 与 `in_image=True`：图分支用 `not in_image` 把它挡掉，紧接着的 `elif ocr` 又把它收进来，作为 `kind="ocr", default_keep=False` 的「歧义块」交给模型。

这与 `policy.py` 自己的设计说明直接冲突（模块 docstring：`in_image` 的块「must be translated, so it is not ambiguous at all」），也与 v0.6.1 的产品决定冲突：图内文字是**明确要求翻译**的。模型一旦在本轮返回 `keep`，`apply_policy` 就写 `keep_original=True`（`policy.py:233-236`），导出端 `pdfio.py:6233`：

```python
if getattr(b, "keep_original", False) and getattr(b, "ocr", False):
    # 不覆盖、不重画 —— 原扫描像素原样保留
    continue
```

于是图内文字**永远停留在原文语言**，而且 `_audit_protected` 会把 `keep_original` 当受保护块，`check_residual` 也不会报——**完全静默**。

**主审复现**：

```python
b = pdfio.Block("Revenue by year", 0, 0, 0, 100, 20, ocr=True, in_image=True)
doc = pdfio.DocumentText(pages=[[b]], blocks=[b.text], block_pages=[0])
print([(c.index, c.kind, c.default_keep) for c in policy.candidates(doc)])
# -> [(0, 'ocr', False)]
policy.apply_policy(doc, {0: policy.KEEP})
d_ir = ir.build_ir(doc, lang="English")
print(b.keep_original, ir._keeps_source(d_ir.pages[0].blocks[0]))
# -> True True   ← 图内文字被永久判为「保留原文」
```

**现有测试正好掩盖它**——`tests/test_policy.py:53`：

```python
def test_figure_text_on_a_text_layer_page_is_not_ambiguous(self):
    b = Block("Revenue by year", 0, 0, 0, 100, 20, in_image=True)   # ← 没有 ocr=True
    dt = _doc([[b]], structure=[_figure_structure(0, [0])])
    self.assertEqual([], policy.candidates(dt))
```

只设 `in_image=True`、不设 `ocr=True`，所以 `elif ocr` 分支根本没触发，断言「空候选」通过；生产形态（双标志）却返回一个候选。

**修法建议**：`elif` 加 `and not in_image`；把上述测试改成 `in_image=True, ocr=True`，并加一条「模型报 keep 也不得改 `keep_original`」的负回归。

## 2. P2 — 建议修

### P2-1 `ai_scope` 失败时丢弃 `parse_explicit_scope` 离线兜底 → 整篇翻译且无日志

`chat_tools.py:547-560`：

```python
if llm is not None:
    page_scope, ai_reason = _agent.ai_scope(str(requirement or ""), llm)
    ...                       # 只在 ai_reason 非空时打日志
else:
    page_scope = _agent.parse_explicit_scope(str(requirement or ""))
```

只要客户端存在（`llm is not None`），离线规则解析就**永不执行**。而 `make_llm_flow_compiler` 的网络/解析失败路径（`agent/user_flows.py:407-410`）返回 `{}`，`ai_scope` 于是得到 `(None, "")` —— 用户说「只翻第 3 页」，模型这次请求超时/回了个坏 JSON，结果就是**整篇翻译**，`ai_reason` 还是空串，日志一行都没有。

这是刻意的 fail-open（「少翻比多翻糟」），但 `parse_explicit_scope` 的规则正好覆盖这类显式措辞（`user_flows.py:185`，认「只/仅/仅限/范围」与「第 N 到第 M 页」）。既然离线解析器存在，AI 失败后应作为二级兜底。

**修法建议**：`if not page_scope: page_scope = parse_explicit_scope(req)`（离线也不认才退整篇），并让失败路径至少在 `ai_reason` 空时记「页范围解析失败，按整篇处理」。

### P2-2 内容策略请求不可取消（无看门狗，取消要等 HTTP 超时）

`worker._content_policy` 复用 `engine.client`（`translator.py:10`，默认 `timeout=300`）：

```python
fn = policy_mod.make_llm_policy_fn(self._model,
        client=getattr(engine, "client", None), log=...)
```

而能打断在途 HTTP 的看门狗只存在于 `translate_blocks` 内部（`translator.py:868-880`，`client.close()`）。内容策略在 `_run_ir` / 确定性路径里都跑在 `translate_blocks` **之前**，此时没有看门狗：

* `worker.cancel()`（`worker.py:393`）只置 `self._cancelled`；
* 策略请求不检查该标志、也没有 `cancel` 参数，于是「取消」后要等这次 HTTP 返回或 300s 超时才继续——而这正是用户最可能点取消的时刻（小本地模型首包慢）。

**修法建议**：给 `decide` 传 `cancel=`，在请求前检查并在看门狗里 `client.close()`；或让 `_content_policy` 也挂上 `translate_blocks` 同款看门狗。

### P2-3 直连（非 IR）路径上 figure 候选的「默认=保留原文」名不副实

`policy.candidates` 按 `page_structure` 的角色给 figure 块 `default_keep=True`，提示词 `prompts.content_policy_task` 对模型显示「默认=保留原文」，并说「不确定就别动它（留空即可）」。这在 **IR 路径**成立（`ir.translate_ir` 的结构门槛 `_STRUCTURAL_ROLES=("formula","figure")` 确实保留）。

但**确定性回退路径**没有结构门槛：`_content_policy` 只写 `keep_original`（`worker.py:283-295`），随后 `engine.translate_blocks(doc.blocks, ...)` 对角色一无所知。若模型照提示词「不动它」，该块**被翻译**，与它看到的默认相反。

触发条件：`PDFTRANSLATE_STRUCTURE_PARSER=doclayout`（`run.bat` 会设）但 IR 关闭（GUI 取消勾选且环境变量未设）。因为 `run.bat` 同时强制 `IR_MODE=1`，日常不触发，故列 P2/P3 之间。

**修法建议**：`default_keep` 依实际路径计算（IR 才把 figure 默认为 keep），或让直连路径也把 `keep_original` 之外的 figure 候选按默认保留。

## 3. P3 — 轻微

### P3-1 页范围不按文档页数夹取

`_coerce_scope`（`user_flows.py:203`）与 `parse_explicit_scope` 只校验「非负整数集」，不对比文档页数。agent 路径按 `i in self.scope`（`flow.py:1915`）过滤后若交集为空，`_translate_normal` 直接 `return`（「未发现正常文本页，跳过批量翻译」），随后照常导出全部原文并报成功。用户说「翻第 10 页」而文档只有 3 页时，得到一份逐字原文的「译文」而无明确告警。

**修法建议**：`DocumentSession` 拿到 `doc_info` 后把 scope 与页数求交，交集为空即报 `STATUS_NEEDS_USER` 或明确告警。

### P3-2 工作区 `models.json` 把共享 endpoint 改成私有 IP；`.pi/` 未 ignore

`git diff models.json`：`192.168.0.48` → `192.168.0.19`（`qwen3.8-local` 的 endpoint）。这是**环境相关**的本地服务器地址，提交后其他人拉到的是无法解析的模型端点；建议保留本地改动不入库，或把 endpoint 改为可被环境变量/占位符覆盖。`git status` 里 `.pi/`（含 `sol-pi.json`）为 untracked 且未被 `.gitignore` 覆盖，建议加入 ignore。

`README.md` 重排 + 新增 `CHANGELOG.md`：目录锚点与标题一一对应，无失效链接；README 仅保留「更新日志 → `CHANGELOG.md`」引用，无残留重复正文；CHANGELOG 收录 v0.5.21–v0.6.2 共 33 个版本段（行级 diff 因重新折行不可逐行比对，但内容顺序完整）。

## 5. 已核对为非缺陷（避免误报）

* **内容策略的扁平索引对齐**：`policy.apply_policy` 用 `doc.pages` 展开的扁平索引，`ir.build_ir` / `translate_ir` / 导出 / overlay 也用同一顺序。实测 `flatten(doc.pages)` 与 `doc.blocks` 在 3 份真实 PDF（含 27 页年报）上**逐字相等**，索引不会错位。
* **v0.6.0 `check_translation` 双语配对**：`tgt.page_count == 2*src.page_count` 时用 `2i+1`，与 `check_layout` 同一判据；非交错产物仍用 `tgt[i]`。
* **`check_layout` 提取失败 fail-closed**：`_text_layer_blocks` 返回 `None`（失败）与 `{}`（确实无文本层）分开，失败会作为 page issue 报出 exit 1，不再假绿。
* **v0.6.1 逐块覆盖的组织架构图保留**：`set_text` / `translate_block` / `translate_blocks` 清除 `keep_original`（= AI 覆盖），`delete_block` / `apply_annotation(delete)` 置位（= 显式保留）；导出端 `chart_page and b.ocr and 译文==原文` 只是无 agent 标记路径的兜底，与 v0.6.1 语义一致。
* **内容策略红线的不可达性**：`candidates` 在候选筛选阶段就排除 `_verbatim`（数字/金额/公式）、`in_table` 与 `is_chart`，`ir._keeps_source` 里红线判断又优先于 `release`，模型无法放行公式或金额。
