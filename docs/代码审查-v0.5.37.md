## 1. P0 — 必修（错误输出 / 崩溃 / 体检工具失效）

### P0-1 表格换行把带币种/单位的金额从中间拆断（数字红线）· ✅ v0.5.38 已修
`translate_app/pdfio.py:4054-4063`（对照 `_break_word` `:4426`）

> **修复**：`_split_line_half` 的守卫加上 `or _is_amount_atom(t)`；回归
> `test_amounts_are_never_split_by_the_line_rebalancer`、`test_two_line_cell_keeps_a_currency_amount_whole`。

`_split_line_half`（`_fit_exact_n` 用它把宽行拆成两行，凑「译文行数 == 源行数」）只判
`_is_number_atom`，**漏了 `_is_amount_atom`**；v0.5.24 的 P1-8 修复只覆盖了 `_break_word` 这条路径。

主审复现（`_split_line_half` 直接调用 / 经 `_fit_block` 两行源格）：

```
'US$1,234,567.89'  -> ('US$1,23', '4,567.89')        # _fit_block: ['US$1,23','4,567.89']
'1,234.56万元'      -> ('1,234', '.56万元')
'RMB12,345,678.90' -> ('RMB12,34', '5,678.90')
```

后果：报表里一个金额被拆成两行、读起来像两个数。**修法**：加 `or _is_amount_atom(t)`，
与 `_break_word` 同一判据；补回归（两行源格 + 带币种金额）。

### P0-2 OCR 框坐标未校验 → 导出抛异常（整轮失败）/ 整页 OCR 结果被丢弃 · ✅ v0.5.38 已修
`translate_app/pdfio.py:2770-2772`（`_synthesize_ocr_blocks`）、`:2887-2897`、`:2940-2942`

> **修复**：逐条 `try` + `math.isfinite` 校验，非法框跳过并记「N 个 OCR 框坐标非法，已跳过」；
> 回归 `OcrBoxValidationTest`（NaN/inf/扁平框 + 端到端导出不崩）。

`xs/ys` 直接 `float()` 后 min/max 进 `Block`，无 `isfinite` 校验；`box` 被当成 `[(x,y),…]`
下标访问（VLM OCR 后端返回扁平 `[x0,y0,x1,y1]` 即 `TypeError`）。主审复现（构造 OCR 块 → `save_translated_pdf`）：

```
nan  -> EXPORT RAISED: ValueError cannot convert float NaN to integer
inf  -> EXPORT RAISED: OverflowError cannot convert float infinity to integer
```

即：一次坏 OCR 结果会让**整轮导出失败**；扁平框让**整页 OCR 结果被丢弃**（仅一条日志，
该页等于没翻译）。`select_ocr_fn`（`:506`）允许选 `vlm` 后端，模型输出畸形坐标完全可能。
**修法**：逐 item try/continue，四点 `math.isfinite` 校验并计数上报。

### P0-3 `check_layout.py` 旋转页帧不一致 → 正确产物 exit 1（假红），且「压线」恒假绿 · ✅ v0.5.38 已修
`check_layout.py:257`、`:267-279`

> **修复**：新增 `frame_rect()`（未旋转 cropbox 帧，判界用）与 `to_render_frame()`（映射到渲染帧，
> 采样用；cropbox 尺寸感知，四种旋转 + CropBox 偏移逐例对拍渲染像素验证）；回归
> `RealExportTest.test_rotated_pages_are_not_reported_off_page`。

`spans` 来自 `get_text("dict")`（未旋转帧），却拿 `page.rect`（旋转视图）判越界、采样旋转帧掩膜。
主审复现（300×500 + `/Rotate 90`，文本在 y≈450，经 `pdfio.save_translated_pdf` **正确**导出）：

```
out text: 'TRANSLATED BOTTOM LABEL ROTATED'   （导出正确，输出页 500×300 /Rotate 90）
check_layout exit: 1
[第 1 页] 块 …(40.0,440.2)-(178.1,450.5) 越出页面 (0.0,0.0)-(500.0,300.0)
```

同一帧错位使「压线」检测在旋转页上恒为 0 条（同一段文本+表格线：rot=0 → 1 条；rot=90/180/270 → 0 条）。
**修法**：用未旋转帧（`cropbox`/`mediabox`）判界与采样，或先把 spans 映射到渲染帧。

### P0-4 `check_layout.py` 漏画判据按「单个 span 覆盖 ≥10% 源块面积」→ 长段落必然假红 · ✅ v0.5.38 已修
`check_layout.py:226`

> **修复**：`_covers()` 改为「span 自身 ≥30% 落在块内」或「同列且在块 ±（半块高+12pt）内」（后者
> 容忍被表格下推的散文）；越界 `--page` 改为 exit 2；`luma is None` 不再跳过漏画检查。
> 回归 `test_long_paragraph_translation_is_not_missing`、`test_dropped_translation_is_still_missing`、
> `test_out_of_range_page_is_a_usage_error`。

仍报「附近没有译文」→ exit 1；约 >10 行的源块（`1.31×字号/0.10`）**必然**误报。
另：`--page 9`（越界）返回「文字块 0 段 / 体检通过」**exit 0**（主审复现，假绿）；
`luma is None → continue` 会连带跳过「漏画」检查且无提示（实测 missing 1→0）。

## 4. P2 — 轻微（择要）

**性能**：每块 `_fit_block` 调 3 次（`pdfio.py:5018/5714/4397`，33 块 1 页导出 1429ms、`_fit_block` 99 次）；
每页像素分析 ≈390ms（`_page_rule_mask` 235ms + `_pixmap_luma` 109ms + `_page_levels` 44ms），
而注释 `:5588` 仍写「≈3 ms」；`make_page_executors` 每页重建整篇扁平块表；`_block_meta` 每块全页重扫 spans。

**翻译 / 设置**：`_parse_response` 末块吞收尾语（`'[[1]]a\n[[2]]b\nHope this helps!'` → `['a','b Hope this helps!']`，且会被缓存）；
单块批次接受越界标记；未知 `models.json` 字段直进 `OpenAI()` → `TypeError` 而 `validate()` 不报（`page_concurency` 拼错即触发）；

`_is_cjk_language` 子串误判——`Javanese/Zhuang/Kongo` 因含 `ja/zh/ko` 判为 CJK（主审实测 True），
导致例输出回落中文、`measure_complete` 把正常拉丁译文判 `residual_latin`；
4 段提示词（单块重译/批量重译/表格重建/合并检测）仍内联在 `translator.py`（`prompts.py` 单一来源漂移）。

**GUI / 对话**：预览「－」回退到适应后 `_pan` 不重置 → 画布全白且拖不回来（`preview.py:129-136`）；
