# 0.3.8 中间表示（IR）+ 自适应重排版方案：解耦「语义内容」与「视觉布局」，做文档级翻译

> 版本：v0.3.8（草案）　　状态：待定稿　　上一篇：`0.3.8-方向设计.md`（档位 C-⑥）、`0.3.8-formula-figure.md`（B-⑤）、`0.3.8-semantic-parse.md`（B-④）
>
> 对应方向档位：**C-⑥**，整条路线 **payoff 最高、改动最大**的一份。本文把「把『逐块翻译→回填 bbox』升级为『IR 翻译→重锚定』」细化成**可选、可回退、可复用现有拟合原语**的方案。**核心洞察**：现有 `save_*` 已经是「把译文重锚定回原版式」，其物理上限在于**翻译发生在块粒度、受限于源 bbox**——IR 的关键收益不是「换一个渲染器」，而是**把翻译粒度提升到语义组、带跨页/跨栏上下文、并允许版面在必要时『重排』而非『缩字』**。

---

## 1. 一句话目标

在**默认关闭**的前提下，新增一条可选路径：把文档解析成 **IR（语义内容 + 版面锚点分离）**，在 IR 上做**文档级翻译**（语义组粒度、跨页上下文、术语一致性、公式占位），再由**自适应重排版引擎**把译文重锚定回原版式、并在源几何装不下时**重排**（扩行、列间重平衡、跨栏回绕）而非一味**缩字**。**默认路径 `save_*` 不变**，两者可 A/B 对比（A-② 基准）。

---

## 2. 现状的天花板（为什么需要 IR）

| 现状 | 物理上限 | IR 的解法 |
|---|---|---|
| 逐块翻译、无上下文 | 跨页/跨术语/跨栏语义不一致 | 文档级翻译 + 跨页上下文 |
| 译文重锚定回源 bbox | 译文比原文长 → 缩字/换行，物理极限（扫描件已到 3–4pt） | 允许版面**重排**：扩行/列重平衡/跨栏回绕 |
| 数字/表格已尽力 | 表格行扩展是局部的，跨页表/长表仍错位 | 语义表格 + 表级术语一致性 |
| 公式/图被当散文 | 公式被改坏（见 B-⑤） | 公式占位、图本体保护 |
| 块是"摆在哪儿"，无结构 | agent 看不到标题/段落/表结构 | IR + B-④ 的结构模型（`PageStructure`/`StructTable`） |

## 3. 核心概念：IR 模型（`translate_app/ir.py`）

IR 三层：**文档 → 页 → 语义元素（锚点 + 角色 + 分组 + 样式）**。

```
IRDoc
 ├─ meta: {title, lang, parser}
 ├─ pages: list[IRPage]
 └─ terms: dict[str,str]          # 文档级抽取的术语表（源→目标），注入翻译

IRPage
 ├─ page: int
 ├─ role_blocks: list[IRBlock]    # 语义元素，阅读序
 ├─ tables: list[StructTable]     # 复用 B-④；语义网格
 └─ reading_order: list[int]      # 阅读序（块索引），跨栏先读左列

IRBlock
 ├─ anchor: Block                 # 「视觉锚点」——复用现有 Block（bbox/版式/fit_width/fit_height）
 ├─ text: str                     # 源文本
 ├─ role: str                     # paragraph / heading / table_cell / formula / figure / caption
 ├─ level: int                    # heading 层级（B-④）
 ├─ group_id: int                 # 同一逻辑单元（跨块段落、一张表、一公式）
 ├─ table_ref: int                # 指向 tables；0=不在表内（B-④）
 ├─ style: dict                   # {size, align, bold, color}
 └─ src_id: int                   # 对应扁平 blocks 索引（可回落到几何路径）
```

> **关键**：`IRBlock.anchor` 复用现有 `Block`，所以：
> - 导出时仍可用现有 `_draw_translated_block`/`_fit_block`/`_fit_band`/`_wrap` 作「拟合原语」；
> - IR 是**元数据 + 分组 + 阅读序**，不是另一套几何系统——① 不需要重写 `save_*` 的绘制；② 保底回退（某页/某元素 IR 不适用 → 该元素直接按现有块路径处理）天然成立；
> - 与 B-④ 的 `Block.kind`/`StructTable`、B-⑤ 的 `structure_protect` 复用，不重复建模。

## 4. 与现有管线的边界（复用 vs 新增）

| 层 | 复用 | 新增 |
|---|---|---|
| 提取 | `extract_document_text` / `_order_generic` / OCR | `build_ir(doc) -> IRDoc`（分组/角色/阅读序，底层由 B-④ `structure_fn` + 现有块几何驱动） |
| 拟合 | `_fit_block` / `_fit_band` / `_wrap` / `_compute_table_layout` / `_draw_translated_block` | `save_ir(ir, trans_ir, ...)`（重排决策：扩行/列重平衡/跨栏回绕） |
| 翻译 | `translate_blocks` / `make_retranslate_batch_fn`（批并发、缓存、数字原子性） | `translate_ir(ir, model, ...)`（按语义组 + 跨页上下文 + 术语 + 公式占位） |
| 会话 | `DocumentSession` / `out_doc` / `audit_page` | IR 模式下 P2 走 `translate_ir`，export 走 `save_ir` |

## 5. 文档级翻译（`translate_ir`）

### 5.1 语义组翻译
- **段落组（跨块）**：`group_id` 相同的多个 `anchor` 组成一个逻辑段落 → 一次请求翻译整段（带上下文），再**回绕**进原锚点区域（`fit_width` × 可用高度）。修复当前「拆行坏语义、逐块丢上下文」。
- **表格**：语义表 `StructTable` 逐格译，但**表级注入**（表头/合计/单位/术语）保证列语义一致；`check_table`/`_compute_table_layout` 沿用。
- **公式**：占位（B-⑤ `structure_protect`），周围说明/编号照译。
- **标题**：按 `level` 注入层级提示，`style`（对齐/粗体/颜色）保留。
- **图注**：`kind="caption"` 译，图本体保护。

### 5.2 跨页 / 跨栏上下文
- 翻译单元带**滚动上下文**：前页关键术语 / 译名（`IRDoc.terms`）+ 紧邻块；跨页名词（人名、楼盘、表头、章节名）用 `apply_terminology`/`glossary.json` 合并。
- 跨栏：段落组跨两栏时，按阅读序合并为一段，一次译；回绕时可**列间重平衡**。

### 5.3 术语一致性
- `build_ir` 时从全篇抽取**高频/专有**候选 → 术语表；翻译**首遍**先确定术语 → 后续所有译文用同一术语表（`extra_glossary` 注入，且计入缓存键，见 `translator`）。这比当前「每批注入 glossary.json + 模型自觉」更一致。
- 人机可改：用户 `apply_terminology` 覆盖 / 增补，写入 `IRDoc.terms`。

## 6. 自适应重排版（`save_ir`）

给定 `IRDoc` + 译文 IR，逐页重排版回 PDF（沿用「源页原样 + 覆盖文字」或双语镜像）：

- **保持锚点**：译文放得下源 bbox / `fit_width` → 直接 `_draw_translated_block`（现状）。
- **装不下 → 重排**（按角色决定）：
  - 表格格：扩行（`_compute_table_layout`，已有）、**表内重平衡**（列宽按译文重分配）、跨页断行。
  - 段落：**跨栏回绕**（占用相邻空区 / 本栏剩余高度 / 页宽上限），而非缩字到 3pt。
  - 公式/图：占位/保护，不动。
  - 头部/节标题：保留样式与层级，必要时下移。
- **可读性下限**：沿用 `_MIN_TABLE_FLOOR`(3) / `_MIN_READABLE`；**重排优先于缩字**——这就是「把版面重排出来」与「把字缩到不可读」的分水岭。
- **保底**：任何元素重排失败/不适用 → 回退到现有块路径（该元素按 `_draw_translated_block` 现状画），绝不丢内容。

> **为何不重写 `save_*`**：`save_translated_pdf` 已做「表格行扩展 + 网格重绘 + OCR 全覆盖 + 竖排标签保护」，其拟合规则经真机验证、细节极多。IR 的 `save_ir` **只在其上层加一层「重排决策」**（哪些元素允许离开源 bbox、往哪排），底层的字宽/行带/数字原子性全复用，避免把成熟逻辑重造造成回归。

## 7. 数据模型与接口

```python
# translate_app/ir.py
@dataclass
class IRBlock: ...        # 见 §3；anchor 复用 Block
@dataclass
class IRPage: ...
@dataclass
class IRDoc: ...

def build_ir(doc: DocumentText, *, structure=None) -> IRDoc:
    """由现有 DocumentText + B-④ structure 组装 IR；structure 为 None 时按几何分角色。"""

def translate_ir(ir: IRDoc, model, *, client=None, context_pages=1, log=None) -> IRDoc:
    """文档级翻译：按语义组批并发 + 跨页上下文 + 术语 + 公式占位；返回译文 IR。"""

def save_ir(ir: IRDoc, trans_ir: IRDoc, out_path, *, mode: str = "translated_pdf", log=None) -> None:
    """自适应重排版导出；mots 支持 translated_pdf / bilingual_pdf。"""
```

`worker._export` / `_run_re_export` 在 IR 模式分支到 `save_ir`；`OUTPUT_TYPES` 不变。`DocumentSession` 在 `ir_enabled` 时 `build_ir` → `translate_ir` → `save_ir`，否则原样走 `run_page_visual` + `save_*`。

## 8. 集成 / 开关 / 回退

- **开关**：`models.json` 条目或 env `PDFTRANSLATE_IR_MODE`（默认关闭）。关闭 → 行为与现在**逐位一致**，所有现有测试绿。
- **A/B**：开启后与默认路径各跑一遍 A-②，对比版式保真指标 + judge 分 + 术语一致性；IR 应显著**降低 overflow/spill、提升术语一致**，且**不引入数字回归**。
- **逐级回退**：IR 对某页构建失败/某元素不适用 → 该页/该元素按现有几何路径处理（`run_page_visual` / `_draw_translated_block`）。**绝不丢内容**。
- **先绑定后暴露**：IR 若暴露新工具（如 `get_structure` / `reflow_element`），必须真实绑定进 `make_source_tools`/`make_page_executors` 且结果进入导出/视觉观察——否则不做。

---

## 9. 安全 / 门槛

- **默认关闭**，改动是**增量、可选**，不破坏现有主路径。
- **复用拟合原语**（`_fit_block`/`_fit_band`/`_compute_table_layout`/`_draw_translated_block`），不重写成熟逻辑。
- **受保护块不改**：公式/图/数字/代码（`structure_protect` ∪ `_protected`）在 IR 翻译与审计中一律跳过。
- **数字原子性 / 缓存**沿用：`translate_ir` 走同一 `translate_blocks`/缓存/退避/致命错误路径；数字块不与模型、不写缓存。
- **fail-closed**：IR 任一步失败回退几何，绝不崩溃；审计不把「保留原文」误报为残留。

## 10. 分阶段实施计划

| 阶段 | 内容 | 验证 | 状态 |
|---|---|---|---|
| **1** | `IRBlock`/`IRPage`/`IRDoc` + `build_ir`（角色/分组/阅读序；structure=None 时按几何分角色） | `test_ir`：`build_ir` 分组/角色/`table_ref` 正确；往返无损 | ⬜ 未启动 |
| **2** | `translate_ir`：语义组翻译 + 跨页上下文 + `IRDoc.terms` 术语抽取与注入 | `test_ir`/`test_translator`：段落组一次译、术语跨页一致、公式块跳过 | ⬜ 未启动 |
| **3** | `save_ir`：重排决策（扩行/列重平衡/跨栏回绕）复用 `_compute_table_layout`/`_draw_translated_block` | `test_ir`：重排优先于缩字；可读性下限守住；回退不丢内容 | ⬜ 未启动 |
| **4** | 集成：`worker`/`DocumentSession` IR 分支 + 开关 + A/B（A-② 基准） | `test_worker`/`test_session`：IR 开/关两路径、A/B 指标对比、现有测试绿 | ⬜ 未启动 |

> **建议**：**1** 先落地 IR 数据结构与构建（含 B-④ 复用）；**2** 是核心价值（文档级翻译 + 上下文 + 术语一致）；**3** 是重排版引擎；**4** 集成与 A/B。**每阶段都以 A-② baseline 度量**，IR 只有在「版式保真不劣化 + 术语一致提升」时才算成功，否则回退。

## 11. 未决问题

- **IR 表示语言**：自定义 dataclass vs 借鉴 BabelDOC 的 HTML/结构化中间表示。倾向**自定义 dataclass**（与本项目 `Block` 强耦合、可控），但需评估与外部/下游（如 MCP）交换的序列化成本。
- **重排的「越界容忍度」**：允许重排（跨栏/扩行）在多大程度上偏离源版式？重排是 IR 的核心收益，但对「版面尽量像原文」是取舍——需要用户可见的档位（严格锚定 / 允许重排）。
- **术语抽取的精度**：`build_ir` 全篇抽术语可能误抽（专有名词/表头/人名），需保守 + 用户可覆盖；是否走 **AI 抽取 + 人机确认**（`make_llm_decide`）还是纯规则？
- **跨页表**：语义表格跨多页（`StructTable` 跨页）如何切分与重排？当前 `find_tables`/OCR 网格都是页内，跨页表是难点。
- **性能**：文档级语义组翻译 + 跨页上下文在**大文档**上的请求数/上下文预算；语义组批量是否沿用 `batch_size` 预算与并发。
- **缓存键**：`translate_ir` 的缓存键需含「分组/上下文/术语」结构，否则 IR 开关会复用旧缓存造成不一致——需设计 `_CACHE_VERSION` 或独立命名空间。
- **与 B-④/B-⑤ 的交付顺序**：`build_ir` 依赖 B-④ 结构模型、公式保护依赖 B-⑤。是否**先做 B-④/B-⑤ 的最小可用**再启 C-⑥-1？（倾向是。）
