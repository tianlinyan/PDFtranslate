# 0.3.8 评估 harness 草案：给「版面保真 + 译文保真」建立可复用、可对比的度量基准

> 版本：v0.3.8（草案）　　状态：待定稿　　上一篇：`0.3.8-方向设计.md`
>
> 对应方向档位：**A-②**。本文把「评估」从现有的一次性脚本（`check_translation.py`／`verify_real_run.py`／`verify_selfcheck.py`）升级为**一个可复用、可对比、离线可复现的度量基准**。目的不是「再写一个检查脚本」，而是**在动任何结构性大改（B/C 档的语义化解析、IR 重排版、VLM OCR）之前，先有一把尺**，让每一步改进都有客观可度量的增量，避免「改了就回归、回了又改」的无底洞。

---

## 1. 目的与设计原则

- **可复现**：给定「原文 PDF + 译文（out_doc 或已导出 PDF）」，指标必须算出来且两次运行一致。
- **离线优先**：确定性指标（版面/数字/完整性）**不依赖任何模型在线**，可在 CI / 无网环境跑；只有「译文保真」的 LLM-as-judge 是可选、需模型、且付费的，独立开关。
- **分层**：**硬指标（确定性，作为门槛）** 决定「这一改有没有把版面/数字改坏」；**软指标（LLM-as-judge，作为趋势）** 决定「译文质量有没有提升」。两者不互相代偿。
- **可对比**：支持 **A/B** —— 基线 vs 候选，输出**聚合分 + 分页/分块明细 + delta**，让人一眼看出改动是变好还是变坏、坏在哪一页哪一块。
- **复用而非重造**：所有度量尽量基于现有 `pdfio._fit_block` / `_wrapped_height` / `_line_leading` / `_render_page_png` 与 `agent.flow._check_layout`/`check_numbers` 等，**绝不重复实现**（与 CLAUDE.md「细粒度审计引擎单一来源」一致）。

## 3. 指标设计（两层）

### 3.1 硬指标（确定性，离线）—— 版式保真 + 数字/完整性

对每个**已翻译块**（跳过 protected / 竖排标签 / 保留跳过页，沿用 `_audit_protected` / `_is_vertical_label`），用 `_fit_block` 量测并归入下类：

| 指标 | 定义 | 来源 |
|---|---|---|
| `overflow` | 译文高度 > 自身框高 + 2pt | `_check_layout` kind `overflow` |
| `crowding` | 译文高 > 框高 + 相邻块间隙 + 2pt | `_check_layout` kind `crowding` |
| `too_small` | 译文字号 < 可读下限（表格 3pt / 正文 min(块字号, 有底线)） | `_check_layout` kind `too_small` |
| `band_violation` | 表格格 `fit_height>0` 且多行、`_wrapped_height > fit_height + 0.05` | `verify_real_run` 的行带越界逻辑 |
| `single_over` | 单行格 met曲尺度 > 行带（良性：无降部，仅记录不计差） | `verify_real_run` |
| `severe_tiny` | 表内格字号 < 5pt（<4pt 另计为严重） | `verify_real_run` 的字号桶 |
| `too_many_lines` | 译文字号触到下限仍多行（物理极限） | 汇总用 |
| `missing` | 该译而未译的块数 | `_check_missing` |

> **阈值一律沿用现有 `pdfio` 常量**（`_MIN_TABLE_FLOOR=3`、`_MIN_TABLE_READABLE=6`、`_MIN_READABLE`、`_MAX_FONT`），不做新的魔法数——度量与产线判定用同一套规则，避免「检测时合法、产出时违规」的割裂。

每页聚合为 `{page, total, counts, buckets}`；全篇再聚合为汇总 dict。

### 3.2 软指标（需模型，可选开关）—— 译文保真

- **LLM-as-judge**：对每页给多模态模型「源页渲染图（`_render_page_png` 原文 vs 译文）」，按 **保真（语义一致）/ 术语一致 / 可读性** 三轴 0–100 打分（参考 BabelDOC 的多模态 LLM-as-judge 思路）。
- **可选参考译文**：若有 reference（人工/高置信），可退化为 BLEU/COMET 类参考打分；无参考则纯 judge。
- **付费 / 慢**：必须用 `models.json` 的某个模型、独立 `--judge` 开关，默认关闭；结果单独落盘，不参与硬门槛。

### 3.3 聚合评分（可配置权重）

`score = 100 × (1 − weighted_issue_ratio)`，其中：

```
weighted_issues = overflow×2.0 + band_violation×2.0 + too_small×1.5
                + crowding×1.5 + severe_tiny×2.0 + too_many_lines×1.0 + missing×2.0
issue_ratio     = min(1.0, weighted_issues / total_translated_blocks)
```

最终报告 = **硬评分（门槛）+ 软评分（趋势）+ 逐页/逐块明细 + delta（vs 基线）**。权重进 `models.json` 或 `eval_harness.py` 顶部常量，注释说明「调整权重即改变容忍度」，不硬编码进判断逻辑。

### 4.2 `eval_harness.py`（CLI 入口，放项目根、与 `check_translation.py` 平级）

```
python eval_harness.py 原文.pdf 译出.pdf [--lang English] [--json report.json]
                        [--baseline base.json] [--compare] [--judge MODEL_ID]
                        [--outdir out/] [--skip 24-27] [--pdf-only]
```

- `译出.pdf`：已导出的 PDF。缺省走 `pdfio.extract_document_text` + `group_by_page` 重建块与 out_doc（**便宜**，复用缓存），从而能 `measure_layout`。
- `--pdf-only`：只跑**文本层后验**（复用 `check_translation.run_checks`，即数字一致性/残留/章节编号/页数），不开版式度量（因为已是导出物，无 out_doc bbox 几何）。
- `--json`：机器可读报告（聚合 + 逐页 + delta），供 CI / 基线落盘。
- `--baseline base.json --compare`：读先前基线，输出 delta 与 top-N 变化。
- `--judge MODEL_ID`：可选软指标。默认不启用。
- 退出码：0 = 硬门槛通过；1 = 硬门槛有差（版式/数字/完整性）；复用 `check_translation` 的 0/1/2 约定。

### 4.3 与现有脚本的关系（不重复，而是收编）

- `check_translation.py`：保留为「导出后文本层后验」，本 harness 通过 `--pdf-only` 复用它，**不重写**。
- `verify_real_run.py` / `verify_selfcheck.py`：保留为「真机/真模型走查」；本 harness 的 `measure_layout` 直接**移植**它们的字号桶/行带越界逻辑（这些逻辑已是成熟且经真机验证的度量）。

## 5. 语料与基线沉淀

- **评估语料**：小但有代表性。起步用现有 `test_mintai_sample.pdf`（含封面/文本页/扫描页）+「Mintai 年报 p24–27」（扫描报表，`verify_real_run` 已用）+ 一个**含公式/科学版式**的样例（为 B-⑤/C-⑥ 预留）。放进 `eval_data/`（或继续用根目录样例），各自标注**页码语义**（normal / scan / chart / formula）。
- **基线落盘**：`eval_baseline/` 下存每个语料的 `base.json`（聚合 + 逐页指标）。**改任何版面/OCR/解析代码前后**各跑一次，`--compare` 看 delta。
- **门槛约定**：`--compare` 默认**不允许硬指标回归**（如 overflow/band_violation/missing 不得增加），软指标（judge 分）可上升可下降、仅作趋势。这条约定写进 README / CI，避免「评分涨了但检测变松了」。

## 6. 分阶段实施计划

| 阶段 | 内容 | 验证 | 状态 |
|---|---|---|---|
| **1** | `translate_app/eval.py`：`measure_layout`（移植 `verify_real_run` 的字号桶/行带越界 + `_check_layout` 三类）+ `measure_numbers`（复用 `check_translation._page_numbers`）+ `aggregate` | `test_eval`：对样例页指标与 `verify_real_run` 手算一致；两次调用稳定 | ⬜ 未启动 |
| **2** | `eval_harness.py` CLI：`--pdf-only`（复用 `check_translation`）/ `--json` / `--baseline --compare` | `test_eval`（CLI 子进程）：JSON 可解析、退出码符合约定 | ⬜ 未启动 |
| **3** | 软指标 `--judge`（LLM-as-judge，可选、需模型） | 单独 `test_eval` 或真机走查；默认关闭 | ⬜ 未启动 |
| **4** | 语料补「公式/科学版式」样例；落基线 `eval_baseline/*.json`；`--compare` 门槛约定写进 README | `--compare` 在已改版面前后跑通 | ⬜ 未启动 |

> **建议**：先做 **1 + 2**（离线硬指标 + CLI + A/B）——这是「动结构前的尺」的最小可用集；**3**（judge）与 **4**（语料/基线）再跟进。1/2 完成后即可作为 B-④/C-⑥ 每步改动的回归基准。

## 7. 未决问题

- **度量口径统一**：`measure_numbers` 是复用 `check_translation._page_numbers`（文本层，含中文序数归一化）还是 `agent.flow._check_numbers`（in-progress，含单位倍率）？建议**两者都要**、分别落盘（一个是导出后验、一个是过程审计），但评分只取其一，避免混口径。
- **「译文保真」缺参考译文**：多数场景无人工 reference。是否投入一个**小而贵的人工校对子集**作为 judge 的锚，还是纯粹靠 LLM-as-judge 的相对趋势？
- **软/硬权重**：默认 0.6 硬 / 0.4 软，是否要按文档类型（年报 vs 论文）给不同默认权重？先定常量，后续再按语料调。
- **CI 可行域**：judge 依赖模型在线，无法进无网 CI；`--pdf-only` 硬门槛可进 CI。是否把 CI 限定为硬门槛，judge 留给本地 `eval_harness.py`？
- **`too_many_lines`（物理极限）** 是否计为「差」：v0.3.x 真机已确认这类是扫描件不可回避的物理极限，并非实现缺陷。建议**计入但降权、并在报告里单独标 orange**，避免把「不可改进」误判成「改坏了」。
